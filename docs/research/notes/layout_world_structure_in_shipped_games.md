# World structure in shipped games: interiors, exteriors, floors, and how NPCs cross them

Researched 2026-10-23. Scope: the data model (places, warps, Z levels, rooms, portals) and how NPC pathfinding, schedules and off-screen simulation interact with it. Editors/tooling and visual presentation are covered by other researchers and only touched where they constrain the data model.

Where a claim comes from reading game source (Stardew 1.6 decompile, Exult, FreeSO, pret disassemblies), the link points at the file and the symbol is named so the report writer can quote it.

## Stardew Valley: GameLocation graph, Warp/door data, interiors vs footprints, cross-location NPC routing, known failures

### Takeaway
Stardew is the canonical "graph of places joined by warps" design: every interior is its own `GameLocation` with its own map, warps are per-tile records `(fromX, fromY, toArea, toX, toY)`, and NPC travel between locations is a precomputed depth-first enumeration of location-name sequences (`WarpPathfindingCache`) plus a per-location A* with an iteration cap of 30,000. Interiors are routinely several times larger than their exterior footprint, which the data model permits trivially because there is no shared coordinate space. The failure modes are all graph failures: a schedule target with no warp chain, an NPC-impassable door, a route through a banned location, or an unexpected warp tile on the path.

### Cited Findings

**Warp and door data**
- Map property `Warp [int fromX] [int fromY] [string toArea] [int toX] [int toY]+`, valid in any location, repeatable (`+`). `fromX/fromY` is the tile that triggers the warp, `toArea` the destination location name, `toX/toY` the arrival tile. (0,0) is top-left. `NPCWarp` has the same format but only NPCs use it. — [Stardew Valley Wiki, Modding:Maps](https://stardewvalleywiki.com/Modding:Maps)
- Tile-level warps: `Action Warp <x> <y> <area>` (note x, y, then area), `TouchAction Warp <area> <x> <y> [prerequisite]` (area first; player-only, fires on step), `TouchAction MagicWarp`, `Action ObeliskWarp`. — [Modding:Maps](https://stardewvalleywiki.com/Modding:Maps)
- `Action LockedDoorWarp <toX> <toY> <toArea> <openTime> <closeTime> [NPC] [friendship]` creates a time-limited warp; 24-hour times, `600 2600` means always unlocked; example `7 9 LeahHouse 1000 1800 Leah 500`. — [Modding:Maps](https://stardewvalleywiki.com/Modding:Maps)
- Interior doors need both the `Doors [x] [y] [sheetID] [tileID]+` map property (indoor locations only) and an `Action Door [npcName]+` or `Action ConditionalDoor <query>` tile property on the lower door tile; with NPC names the door needs two or more hearts with one of them. — [Modding:Maps](https://stardewvalleywiki.com/Modding:Maps)
- NPC-movement tile properties: `NPCBarrier T` (Back; blocks NPCs on Farm, mines, island), `NPCPassable T` (Buildings; lets NPCs cross a Buildings tile), `Shadow T` (player passes, NPCs do not), `NoPath T` (Back; excluded from NPC pathing), `TemporaryBarrier T` (used briefly when doors open; NPCs pause before rushing through). Map width above 200 breaks layering; height is unlimited. — [Modding:Maps](https://stardewvalleywiki.com/Modding:Maps)
- Runtime `Warp` object: net-synced fields `x, y, targetX, targetY, targetName, flipFarmer, npcOnly`. — [Warp.cs, 1.6 decompile](https://github.com/AcidicNic/StardewValleyDecompiled1.6/blob/2878fb248092f9f5b8704ad2cc7e19d0abe1cf45/StardewValley/Warp.cs)
- `GameLocation` stores warps in `warps` (a `NetCollection<Warp>`) and interior-door warps separately in `doors`, a `NetPointDictionary<string, NetString>` keyed by door tile with the target location name as value. `getWarpPointTo(location)` checks, in order: a building whose indoors name matches (returns `building.getPointForHumanDoor()`), then `warps` by `TargetName`, then `doors` by value; returns `Point.Zero` if none. `getWarpPointTarget(point)` resolves a door's destination by re-parsing the `Action` tile property (`Warp`, `LockedDoorWarp`, `WarpMensLocker`, `WarpWomensLocker`, plus hardcoded `WarpCommunityCenter` -> (32,23), `Warp_Sunroom_Door` -> (5,13), `WarpBoatTunnel` -> (17,43)). — [GameLocation.cs lines 2833-2905](https://github.com/AcidicNic/StardewValleyDecompiled1.6/blob/2878fb248092f9f5b8704ad2cc7e19d0abe1cf45/StardewValley/GameLocation.cs)

**Location definitions and interiors vs exteriors**
- `Data/Locations` entries carry `CreateOnLoad.MapPath` (the map asset), `DefaultArrivalTile` (where a warp without a tile lands you; default none, which usually means (0,0)), `FormerLocationNames` (globally unique legacy names for save migration), and `ExcludeFromNpcPathfinding` (default false; when true NPCs ignore the location when routing between locations). — [Modding:Location data](https://stardewvalleywiki.com/Modding:Location_data)
- `Data/Buildings` defines the exterior and interior separately: `Size` (exterior width/height in tiles, default 1x1), `IndoorMap` (map asset for the interior, e.g. "Shed" loads Maps/Shed), `IndoorMapType` (C# class; must be a vanilla type or saving crashes), `HumanDoor` (door tile relative to the building's top-left), `AnimalDoor` (rect relative to top-left), `CollisionMap` (walkable exterior tiles; default all blocked), `NonInstancedIndoorLocation` (use an existing global location such as FarmHouse or Greenhouse as the interior; single-use per location, later copies fall back to instanced `IndoorMap`). The player enters one tile north of the first warp in the interior's warp list. — [Modding:Buildings](https://stardewvalleywiki.com/Modding:Buildings)
- Interior sizes are decoupled from footprints: the basic Shed's exterior is 7x3 while its interior is 11x9, and the Big Shed interior is 17x12. — [Stardew Valley Wiki, Shed](https://stardewvalleywiki.com/Shed)
- A fan-made comparison lists each farm building's map footprint vs usable interior tiles, with ratios from about 2.7 (coop) to about 7.4 (deluxe barn); shed: 21 footprint squares vs 99 interior squares. — [Nexus Mods article](https://www.nexusmods.com/stardewvalley/mods/4202)
- A location knows its container: `GameLocation.GetParentLocation()` resolves `parentLocationName`, `GetContainingBuilding()` finds the `Building` whose `HasIndoorsName(NameOrUniqueName)` matches, and `GetRootLocation()` returns the parent or self ("the interior for a farm building will have the farm as its root location"). — [GameLocation.cs lines 4155-4191](https://github.com/AcidicNic/StardewValleyDecompiled1.6/blob/2878fb248092f9f5b8704ad2cc7e19d0abe1cf45/StardewValley/GameLocation.cs)
- Farmhouse upgrades: Upgrade 1 adds a kitchen and bedroom, Upgrade 2 enlarges rooms and adds two more; the third upgrade adds a cellar reached by stairs from the kitchen. — [Stardew Valley Wiki, Farmhouse](https://stardewvalleywiki.com/Farmhouse)
- In the 1.6 code the farmhouse is one `FarmHouse` location whose layout is changed by `ApplyMapOverride("FarmHouse_Cellar", ...)`, `"FarmHouse_Bedroom_Open"`, `"FarmHouse_SouthernRoom_Add"`, `"FarmHouse_CornerRoom_Add"` etc. keyed on `upgradeLevel`; the cellar itself is a distinct location, since `WarpPathfindingCache.IgnoreLocationNames` seeds `"Cellar"` and adds `"Cellar" + i` per farmhand. — [FarmHouse.cs](https://github.com/AcidicNic/StardewValleyDecompiled1.6/blob/2878fb248092f9f5b8704ad2cc7e19d0abe1cf45/StardewValley.Locations/FarmHouse.cs); [WarpPathfindingCache.cs](https://github.com/AcidicNic/StardewValleyDecompiled1.6/blob/2878fb248092f9f5b8704ad2cc7e19d0abe1cf45/StardewValley.Pathfinding/WarpPathfindingCache.cs)
- Upper floors on the farmhouse exist only via mods: a content-pack framework where "each floor type points to a map file that must be included in the content pack and indicates the tile position to draw the staircases." — [Nexus Mods 23068](https://www.nexusmods.com/stardewvalley/mods/23068)

**Cross-location NPC routing (the "route table")**
- `StardewValley.Pathfinding.WarpPathfindingCache` ("Handles pathfinding between locations") holds `Routes: Dictionary<string, List<LocationWarpRoute>>` keyed by start location; each `LocationWarpRoute` has a `LocationNames` array and optional `OnlyGender`. `GetLocationRoute(start, end, gender)` returns "a list of location names to transit through including the start and destination locations. For example, `[ "BusStop", "Town", "Mountain" ]`", or null. — [WarpPathfindingCache.cs](https://github.com/AcidicNic/StardewValleyDecompiled1.6/blob/2878fb248092f9f5b8704ad2cc7e19d0abe1cf45/StardewValley.Pathfinding/WarpPathfindingCache.cs)
- `PopulateCache` clears `Routes`, then for every location not in `IgnoreLocationNames` (seeded `{ "Backwoods", "Cellar", "Farm" }` plus farmhand cellars) runs `ExploreWarpPoints`, a depth-first search that follows both `location.warps` (by `TargetName`) and `location.doors.Values`, refuses to revisit a location already on the current route, skips locations where `ShouldExcludeFromNpcPathfinding()` is true, skips generated mine and volcano levels, applies `OverrideTargetNames` (`"BoatTunnel"` -> `"IslandSouth"`) and `GenderRestrictions` (`BathHouse_MensLocker` male-only, `BathHouse_WomensLocker` female-only), and records every path of two or more locations via `AddRoute`. There is no explicit maximum route length, routes are not sorted, and `GetLocationRoute` returns the first match, so it is not guaranteed shortest. — [WarpPathfindingCache.cs](https://github.com/AcidicNic/StardewValleyDecompiled1.6/blob/2878fb248092f9f5b8704ad2cc7e19d0abe1cf45/StardewValley.Pathfinding/WarpPathfindingCache.cs)
- Pre-1.6 the same logic lived in `NPC.exploreWarpPoints(GameLocation l, List<string> route)` / `routesFromLocationToLocation`. — [veywrn/StardewValley NPC.cs (older decompile)](https://github.com/veywrn/StardewValley/blob/3ff171b6e9e6839555d7881a391b624ccd820a83/StardewValley/NPC.cs)
- `NPC.pathfindToNextScheduleLocation(scheduleKey, startLoc, startX, startY, endLoc, endX, endY, facing, endBehavior, endMessage)` throws if the start tile is (0,0) ("start position in {startingLocation} is at tile (0, 0), which isn't valid"); gets `locationsRoute` from the cache when start != end; for each hop calls `currentLocation.getWarpPointTo(next)` and throws `"it requires a warp from X to Y, but none was found"` if `Point.Zero`; runs `PathFindController.findPathForNPCSchedules(start, warpTile, location, 30000)` for each leg, then sets the next leg's start to `getWarpPointTarget(warpTile)`; the legs are concatenated into one `Stack<Point>` and returned as a `SchedulePathDescription`. Passive-festival `MapReplacements` and the `Trailer` -> `Trailer_Big` upgrade are substituted per hop. — [NPC.cs lines 5156-5223](https://github.com/AcidicNic/StardewValleyDecompiled1.6/blob/2878fb248092f9f5b8704ad2cc7e19d0abe1cf45/StardewValley/NPC.cs)
- `findPathForNPCSchedules` is 4-connected A* with Manhattan heuristic, a -2 bonus for continuing straight, terrain preference weights (`stone` -7, `wood` -4, `dirt` -2, `grass` -1, terrain feature +5), and returns null after `limit` iterations (30,000 as called). `isPositionImpassableForNPCSchedule` treats as blocked: any Buildings-layer tile whose `Action` starts with `LockedDoorWarp`, or whose Action contains neither `Door` nor `Passable`, or a Buildings tile with neither `Passable` nor `NPCPassable`; any `NoPath` Back tile; any tile that is a `Warp` source in `loc.warps`; any terrain feature. — [PathFindController.cs](https://github.com/AcidicNic/StardewValleyDecompiled1.6/blob/2878fb248092f9f5b8704ad2cc7e19d0abe1cf45/StardewValley.Pathfinding/PathFindController.cs)
- Actual crossing happens at movement time: each update the NPC calls `controller.handleWarps(rect of next path tile)`, which asks `location.isCollidingWithWarpOrDoor(position, character)`; if a warp is hit the NPC is moved with `Game1.warpCharacter(npc, w.TargetName, (w.TargetX, w.TargetY))` and `controller.location` is swapped to the new location. Married NPCs get their BusStop/FarmHouse warps rewritten to the spouse's home entry. A `doorClose` sound plays only if the player is present. — [PathFindController.cs `handleWarps`](https://github.com/AcidicNic/StardewValleyDecompiled1.6/blob/2878fb248092f9f5b8704ad2cc7e19d0abe1cf45/StardewValley.Pathfinding/PathFindController.cs); [NPC.cs line 5056](https://github.com/AcidicNic/StardewValleyDecompiled1.6/blob/2878fb248092f9f5b8704ad2cc7e19d0abe1cf45/StardewValley/NPC.cs)
- Content Patcher advertises that for custom locations it "automatically handles NPC pathfinding, object persistence, etc." — [Content Patcher custom-locations guide](https://github.com/Pathoschild/StardewMods/blob/stable/ContentPatcher/docs/author-guide/custom-locations.md)
- A mod-author article notes map-to-map connections are handled by warps and "each map only considers their own warp points, and not their neighbors." — [Nexus Mods article 118](https://www.nexusmods.com/stardewvalley/articles/118)

**Off-screen simulation**
- The host updates every location every tick: `Game1.UpdateLocations` runs `Utility.ForEachLocation(_UpdateLocation)`; `_UpdateLocation` calls `UpdateWhenCurrentLocation` only if a farmer is in (or remotely viewing) the location, and always calls `updateEvenIfFarmerIsntHere(time)`. That method calls `updateCharacters(time)`, which runs `character.update(time, this)` for every NPC when `Game1.shouldTimePass()`, and also updates buildings and (for non-current locations) animals. So NPCs in other maps walk their real tile paths, not a travel-time estimate. Clients update only the current location plus `multiplayer.activeLocations()`. — [Game1.cs lines 5363-5420](https://github.com/AcidicNic/StardewValleyDecompiled1.6/blob/2878fb248092f9f5b8704ad2cc7e19d0abe1cf45/StardewValley/Game1.cs); [GameLocation.cs `updateEvenIfFarmerIsntHere`, `updateCharacters`](https://github.com/AcidicNic/StardewValleyDecompiled1.6/blob/2878fb248092f9f5b8704ad2cc7e19d0abe1cf45/StardewValley/GameLocation.cs)

**Schedule format and fallbacks**
- Schedule entry: `<time> [location] <tileX> <tileY> [facingDirection] [animation] [dialogue]`, slash-delimited; a leading `a` on the time means "arrive by" and the game back-computes departure (used in vanilla only for Emily's and Sandy's Fall 15 schedules). Omitted location means the previous one; the first entry defaults to the bus stop (married) or the NPC's default location. `GOTO <key>`, `NOT friendship <npc> <hearts>`, `MAIL`, `GOTO NO_SCHEDULE`; `<location>_Replacement` fallback when JojaMart/Railroad are locked; `bed` sends the NPC home. The `spring` key must always exist. — [Modding:Schedule data](https://stardewvalleywiki.com/Modding:Schedule_data)
- Known issues from the same page: NPCs added to an existing save do not follow schedules until the player sleeps once; a time of 600 may not trigger movement (use 610); a missing `GOTO` target crashes or errors under SMAPI. — [Modding:Schedule data](https://stardewvalleywiki.com/Modding:Schedule_data)

**Documented failure modes**
- Modding-community troubleshooting lists: schedule points too dense (NPC must leave for the next point before reaching the first, and `a1700` arrival entries can collide with earlier points); pathing onto Buildings-layer tiles (impassable to NPCs); pathing into banned maps ("Backwoods and Farm, are excluded for NPCs to avoid circular pathing"); "voidwalking" when an NPC cannot reach a warp or path to its next point; unintended warps before 1.6.16, where "NPCs can walk into warp points and end up in another location" (test with `patch summary` to find warps added by other mods); schedules disrupted by patch reload; no schedule applied when the `Characters/schedules/<name>` asset is missing. — [Stardew Modding Wiki, Troubleshooting: NPCs](https://stardewmodding.wiki.gg/wiki/Troubleshooting:_NPCs)
- A representative crash log: `System.Exception: schedule pathing tried to find a warp point that doesn't exist` thrown from `NPC.pathfindToNextScheduleLocation` during `NPC.parseMasterSchedule` -> `getSchedule` -> `resetForNewDay` -> `dayUpdate` in `Game1._newDayAfterFade`, i.e. the whole day fails to start because one NPC's route has a missing warp. — [Stardew forums thread 27022](https://forums.stardewvalley.net/threads/schedule-pathing-error-in-update-loop-dont-know-the-source.27022/latest)
- Modded-NPC pathing bugs reported in the wild: NPCs "walk through the sign, and crash into the fence, and are stuck there for the remainder of the day." — [Stardew forums thread 27121](https://forums.stardewvalley.net/threads/getting-started-with-npc-pathing-changes.27121/latest)
- Players cannot infer travel time from schedules ("NPC schedules only show when they leave a location"). — [Stardew forums thread 13110](https://forums.stardewvalley.net/threads/determining-how-long-it-takes-for-character-to-travel-between-two-locations.13110/latest)
- 1.6 bus rework: warps placed along the Desert bus road can trigger while the bus passes, soft-locking the player (a warp-handling edge case of per-tile warps). — [Stardew forums thread 28960](https://forums.stardewvalley.net/threads/sdv-1-6-players-inside-the-bus-can-collide-with-map-warps-and-soft-lock-the-game.28960/latest)

### Inferences
- The route cache is a reachability enumeration of the location graph, not a weighted shortest path; "first route found" means authoring order of warps in a map can change which way an NPC walks. The per-leg A* is capped, so very large maps or long detours silently return null paths.
- Locked doors are unreachable to NPC schedule pathing by construction (`LockedDoorWarp` tiles are impassable in `isPositionImpassableForNPCSchedule`), while `doors` entries are reachable; the only timing enforcement is on the player side. This is why "NPC stuck at a locked door" tends to present as a missing-warp exception or a null path rather than an NPC waiting at a door.
- Because every warp source tile is impassable to schedule pathing except as a destination, maps with warps sprinkled across walkable tiles create accidental barriers and accidental teleports (the "unintended warps" issue). The data model has no notion of a warp's extent or direction.
- The decoupled interior size is a feature of this model: the engine never needs the interior to fit the footprint, and vanilla content exploits it (3x to 7x ratios).

### Gaps
- I could not find a first-party statement about the design intent of interiors larger than exteriors; the ratios are community measurements.
- The wiki pages fetched do not document the cache's rebuild timing (when `PopulateCache` is invoked) or what happens to in-progress NPC paths when a location is added mid-session; the 1.6 code was only read for the files named above.
- Vanilla Stardew has no upstairs farmhouse map in 1.6; the "upstairs" premise in the brief appears to be mod-only. I did not find a vanilla map that places two floors in one `GameLocation`.

## Ultima VI and VII (Exult / Nuvie): chunks, superchunks, lift, roofs, stairs, schedules without Z

### Takeaway
Ultima VII is a single continuous 3072x3072-tile world (12x12 superchunks of 16x16 chunks of 16x16 tiles) with a per-object 4-bit "lift" (0-15) as the Z axis; buildings' upper storeys and roofs are ordinary objects at higher lifts stored in the per-superchunk IFIX files. The original SCHEDULE.DAT records only X and Y (plus a 3-hour time slot and a 5-bit activity), so NPC schedules could not target upper floors; this is the documented reason upper floors in U7 are almost empty, and Exult added an 8-byte schedule entry with a Z field to fix it.

### Cited Findings

**Map structure**
- U7's map is a 12x12 grid of superchunks (144), each a 16x16 grid of chunks (192x192 chunks total, 36,864), each chunk a 16x16 grid of 8x8-pixel "chunk bits" (tiles); full map 24576x24576 pixels. `U7MAP` stores one 2-byte chunk number per chunk; `U7CHUNKS` holds a 512-byte palette per chunk (offset = chunk number * 512), 2 bytes per tile where byte 1 plus the low 2 bits of byte 2 give the shape and the high 6 bits give the frame. — [Ultima Codex, Ultima VII game structure](https://wiki.ultimacodex.com/wiki/Ultima_VII_game_structure)
- Exult's constants: `c_tilesize = 8`, `c_tiles_per_chunk = 16`, `c_num_schunks = 12`, `c_num_chunks = 12 * 16`, `c_chunks_per_schunk = 16`, `c_num_tiles = c_tiles_per_chunk * c_num_chunks` (3072); coordinate helpers wrap modulo `c_num_tiles`. — [exult_constants.h](https://github.com/exult/exult/blob/master/exult_constants.h)
- Objects: 144 IFIX (static) and 144 IREG (moveable) files, one per superchunk. IFIX entries are 4 bytes: byte 1 nibbles = X and Y tile anchor within the chunk, upper half of byte 2 = lift factor (4 bits), remaining bytes = shape and frame. IREG records are 6 or 12 bytes with chunk/tile position, shape, frame, lift, and a Quality byte; 12-byte records are for eggs and containers. Each lift unit shifts the drawn position by 4 pixels. — [Ultima Codex, Ultima VII game structure](https://wiki.ultimacodex.com/wiki/Ultima_VII_game_structure)
- "First-story walls are in U7MAP and U7CHUNKS. Second-story walls, roofs, and outdoor semi-immovable objects are in IFIX." The author notes there is no "layers" concept in the files; drawing order is a z-buffer problem. — [Ultima Codex, Ultima VII game structure](https://wiki.ultimacodex.com/wiki/Ultima_VII_game_structure)
- Exult Studio documents "12x12 superchunks," a skip-lift control (`Alt-l : Decrement skiplift`), a "Hide lift" option, and notes the teleport egg "can't be used to move your character onto roofs because there is no z option provided." Roofs are built from many small objects whose height must be set individually; Exult Studio's "combo" tool exists to make that tolerable. — [exult_studio.txt](https://github.com/exult/exult/blob/master/docs/exult_studio.txt)

**Schedules and Z**
- `SCHEDULE.DAT`: header = 4-byte NPC count (256 in both BG and SI) plus 2 bytes per NPC; body = 4-byte entries with masks `0xFF000000` schedule number (bits 7-3, values 0-31) and match time (bits 2-0, in 3-hour steps 0AM..9PM), `0x00FF0000` X within superchunk, `0x0000FF00` Y within superchunk, `0x000000FF` superchunk number = `(Y/256)*12 + (X/256)`. No Z/lift field. Each NPC has at least one and at most eight schedules. Activity numbers 0-31 include Combat, Pace, Talk, Dance, Eat, Farm, Tend Shop, Miner, Hound, Stand, Loiter, Wander, Blacksmith, Sleep, Wait, Major Sit, Graze, Bake, Sew, Shy, Lab, Thief, Waiter, Special, Kid Games, Eat at Inn, Duel, Preach, Patrol, Desk Work, Follow Avatar. — [Ultima Codex, SCHEDULE.DAT](https://wiki.ultimacodex.com/wiki/Ultima_VII_internal_formats_%E2%80%93_SCHEDULE.DAT)
- Exult's `Schedule_change` holds `time` ("Time*3hours"), `type`, `days` (a bit per day, "We don't yet use this"), and `Tile_coord pos`; it has `set4()` ("Create from 4-byte entry"), `set8()` ("Create from Exult entry (v. -1)"), `write8()` ("Write out 8-byte Exult entry") and `set(ax, ay, az, stype, stime)`, i.e. Exult extended the format to carry Z. — [schedule.h](https://github.com/exult/exult/blob/master/schedule.h)
- Exult Studio's NPC Schedules tab: "Enter the x, y and z coordinates of the place you want the NPC to follow his schedule at. The z coordinate sets on which floor of a house the schedule begins." Also: if the needed item (bed, smithy) is not at the location "the NPC will use the next near item in the vicinity." — [exult_studio.txt section 7.6](https://github.com/exult/exult/blob/master/docs/exult_studio.txt)
- Forum history: a modder "cannot find a way to get the NPCs to know that it's on the third floor that they go to sleep at night"; a poster suspected "BG didn't allow a Z-coordinate for NPC schedules, which was why you almost never see characters on the second floors of buildings"; a developer: "U7 doesn't provide a z-coord for schedules. In other words, they have to start on ground level"; the Z field in Studio "auto reverts after pressing apply" (before the fix); a developer later said "it's something we'd like to do (maybe soon)" and a subsequent snapshot "did mess it up. Should be fixed in tomorrow's snapshot." Upper-floor castle guards "have no schedules - just patrol routes, which are handled differently." Suggested workaround: a set path to the nearest of several coordinates reached via stairs or a teleporter. — [Exult forum: NPCs on the second floor?](https://exult.sourceforge.io/forum/viewtopic.php?p=26491); [Exult forum: Schedule Locations](https://exult.sourceforge.io/forum/viewtopic.php?p=19179); [Exult forum p=15254](https://exult.sourceforge.io/forum/viewtopic.php?p=15254); [Exult forum p=26671](https://exult.sourceforge.io/forum/viewtopic.php?p=26671)
- Exult's Patrol schedule follows "path" markers (shape #607) in numeric order with rules depending on each marker's quality. — [exult_studio.txt section 6.6](https://github.com/exult/exult/blob/master/docs/exult_studio.txt)

**Ultima VI**
- U6: 1024x1024 tiles per world, 128x128 tiles per superchunk, 64 (8x8) surface chunks named `[a-h][a-h]`, plus five dungeon chunks `[a-e]i`; map chunks are 8x8 tiles and only 1024 distinct chunks exist. — [u6notes.txt](https://3e8.org/pub/ultima6/u6notes.txt); [u6edit help: Map Chunks](https://u6edit.sourceforge.net/help/mapchunks.html)

### Inferences
- U7 is the strongest historical example of "continuous world with Z" in a 2D game, and its lesson is that schedule data, not rendering, was the bottleneck: once the schedule record lacked Z, authors simply stopped using upper floors for NPC life.
- The 4-bit lift range (0-15) with ~5 lift units per storey (Exult's skip-lift controls step per lift) effectively caps buildings at about three storeys, which matches the game's content.
- Stairs in U7 are just objects with lift; there is no stair record in the map format, so pathing up them is a matter of the walkability solver accepting a lift change between adjacent tiles. I did not find an authoritative description of U7's stair-walk rule; see Gaps.

### Gaps
- Exult forum pages and Exult Studio HTML docs are behind Cloudflare and returned 403/challenge pages; the forum content above is from search-result excerpts, and the thread dates are not recoverable from them.
- No source found for how the original U7 decides roof hiding (presumably by Avatar lift vs object lift) or for the exact stair-walk rule; those belong to the presentation researcher anyway.
- Nuvie documentation for U6 NPC schedules and dungeon-level data was not reachable; the U6 facts above come from third-party notes.

## Pokémon Gen 1-3 (pokered / pokeemerald): stitched overworld connections plus warp events to interiors

### Takeaway
Pokémon uses both patterns at once: towns and routes are separate maps stitched edge-to-edge by up to four directional `connection` records (direction, offset, target map), so the overworld scrolls seamlessly, while every building interior is a separate map reached by a `warp_event` that names a destination map and a destination warp index. Connections are one-way records that must be authored on both maps.

### Cited Findings
- Gen 3 structs (`global.fieldmap.h`): `MapConnection { u8 direction; s32 offset; u8 mapGroup; u8 mapNum; }`; `MapConnections { s32 count; const MapConnection *connections; }`; `WarpEvent { s16 x, y; u8 elevation; u8 warpId; u8 mapNum; u8 mapGroup; }`; `MapEvents` holds counts and pointers for object events, warps, coord events and bg events; `MapHeader` at 0x00 `mapLayout`, 0x04 `events`, 0x08 `mapScripts`, 0x0C `connections`, 0x10 `music`, 0x12 `mapLayoutId`, 0x14 `regionMapSectionId`, 0x15 `cave`, 0x16 `weather`, 0x17 `mapType`, flags `allowCycling/allowEscaping/allowRunning/showMapName`, 0x1B `battleType`; `MapLayout { s32 width; s32 height; const u16 *border; const u16 *map; primaryTileset; secondaryTileset; }`. — [pokeemerald include/global.fieldmap.h](https://github.com/pret/pokeemerald/blob/master/include/global.fieldmap.h)
- Example data (Littleroot Town `map.json`): one connection `{ map: MAP_ROUTE101, offset: 0, direction: up }`; three warp events, e.g. `(14, 8, elevation 0) -> MAP_LITTLEROOT_TOWN_MAYS_HOUSE_1F warp 1`, `(7, 16, 0) -> MAP_LITTLEROOT_TOWN_PROFESSOR_BIRCHS_LAB warp 0`. — [pokeemerald data/maps/LittlerootTown/map.json](https://github.com/pret/pokeemerald/blob/master/data/maps/LittlerootTown/map.json)
- Gen 1 header (Pallet Town): `map_header PalletTown, PALLET_TOWN, OVERWORLD` / `connection north, Route1, ROUTE_1, 0` / `connection south, Route21, ROUTE_21, 0` / `end_map_header`. — [pokered data/maps/headers/PalletTown.asm](https://github.com/pret/pokered/blob/master/data/maps/headers/PalletTown.asm)
- Gen 1 macros: "Connections go in order: north, south, west, east"; the connection's 4th argument is the "offset of the target map relative to the current map (x offset for east/west, y offset for north/south)"; the macro computes `_src`/`_tgt` strip offsets and per-direction `_blk`, `_map`, `_win`, `_y`, `_x`, `_len` (the block strip copied from the neighbour so it renders at the edge). `warp_event` emits `db y, x, destWarpId-1, destMap` with "destination map (-1 = wLastMap)" and "destination warp id; starts at 1 (internally at 0)". — [pokered macros/scripts/maps.asm](https://github.com/pret/pokered/blob/master/macros/scripts/maps.asm)
- Porymap: each connection has a direction, an offset, and a destination map; "Connections are one-way. Each map's side of a connection must be set separately," with a "Mirror to Connecting Maps" option; Dive/Emerge connections have no direction or offset, only a destination map. — [Porymap manual, Editing Map Connections](https://huderlem.github.io/porymap/manual/editing-map-connections.html)
- Warp semantics as used by a randomizer: many doorways are two or three warp events acting as one logical warp; some warps are destination-only (fall-through holes); some warp destinations are `MAP_DYNAMIC` with a special warp id (Moving Truck, Trade Center); one-way warps are those "whose destination doesn't warp back." — [Archipelago pokemon_emerald warps.md](https://git.hollymcfarland.com/monorail/Archipelago/src/branch/main/worlds/pokemon_emerald/docs/warps.md)
- Multi-floor buildings are separate maps per floor (e.g. `MAP_LITTLEROOT_TOWN_MAYS_HOUSE_1F`), connected by warps on stair tiles; the pret wiki has a "Stair Warps" tutorial for making those transitions walk-animated. — [pokeemerald wiki](https://github.com/pret/pokeemerald/wiki/Stair-Warps); [LittlerootTown map.json](https://github.com/pret/pokeemerald/blob/master/data/maps/LittlerootTown/map.json)

### Inferences
- The `elevation` byte on a Gen 3 warp (and on object events) is a within-map height layer used for bridges and collision, not a floor index; floors are separate maps. So Gen 3 is "graph of places" for interiors with a small Z-like layer inside each map.
- Edge connections solve exteriors only; they are a stitching convention for rendering and player movement and have no role in NPC routing, since Gen 1-3 NPCs never leave their map.

### Gaps
- The pokeemerald wiki index fetch showed only part of its 235 pages; I did not find a dedicated "map connections" explainer there, so the connection semantics above come from headers, macros and Porymap rather than a narrative source.
- No source on how NPC (object event) movement handles map boundaries in Gen 3 beyond their being confined to their map.

## The Sims 1-4: lots, levels, walls on tile edges, flood-filled rooms, portals, stairs as objects

### Takeaway
The Sims model (as reconstructed in the open-source FreeSO reimplementation of the Sims 1-era engine) is a single lot with a fixed small number of levels (5 stories), per-level `WallTile[]` arrays where walls live on tile edges (TopLeft/TopRight segments plus diagonals) and doors are flags on those segments, a per-level room map produced by flood fill (`VMRoomMap.GenerateMap`), and routing done hierarchically as A* over room portals (doors, stairs) followed by within-room geometric pathfinding. Stairs are objects that act as portals between rooms on different levels. Routing failures across floors are a persistent player-facing issue in every Sims generation.

### Cited Findings
- FreeSO `VMArchitecture`: `public int Stories = 5;` with `Walls = new WallTile[Stories][]`, `Floors = new FloorTile[Stories][]`, `ObjectSupport[Stories][]`, `Supported[Stories-1][]` ("no supported array for bottom floor. true if this tile is supported"), and `Rooms = new VMRoomMap[Stories]`; `RegenRoomMap()` regenerates each level's room map from its walls and floors. — [FreeSO VMArchitecture.cs](https://github.com/riperiperi/FreeSO/blob/master/TSOClient/tso.simantics/VMArchitecture.cs)
- `WallTile` struct: `WallSegments Segments` (edge flags), `TopLeftPattern/TopRightPattern/BottomLeftPattern/BottomRightPattern`, `TopLeftStyle/TopRightStyle`, `bool TopLeftDoor, TopRightDoor`, `OccupiedWalls`; `TopLeftSolid` = segment present and not a door. Walls therefore belong to a tile's two "top" edges, and diagonals are flagged (`HorizontalDiag`, `AnyDiag`). — [FreeSO WallTile.cs](https://github.com/riperiperi/FreeSO/blob/master/TSOClient/tso.world/Model/WallTile.cs)
- `VMRoomMap.GenerateMap(WallTile[] Walls, FloorTile[] Floors, width, height, rooms, floor, context)`: "flood fill recursively. Each time choose find and choose the first '0' as the base. The first recursion (outside) cannot fill into diagonals"; room 0 (array value 1) is outside; diagonal walls split a tile into two half-rooms encoded in the high and low 16 bits of the `uint` map; the fill records `AdjRooms` for each room and `SupportRooms` for rooms resting on lower floors; `MakeOutside` propagates "outside" through adjacent rooms. — [FreeSO VMRoomMap.cs](https://github.com/riperiperi/FreeSO/blob/master/TSOClient/tso.simantics/Model/VMRoomMap.cs)
- `VMRoom { RoomID, LightBaseRoom, sbyte Floor, IsOutside, Area, IsPool, Unroutable, HashSet<ushort> AdjRooms ("all adjacent rooms, for DFS traversal of light"), WallObs, RoomObs, RoutingObstacles, WallLines, FenceLines, Bounds, SupportRooms }`; `VMRoomInfo { List<VMRoomPortal> Portals; List<VMRoomPortal> WindowPortals; Entities; DynamicObstacles; StaticObstacles; RoomLighting Light; VMRoom Room }`; `VMRoomPortal { short ObjectID; ushort TargetRoom; }`. — [FreeSO VMRoomInfo.cs](https://github.com/riperiperi/FreeSO/blob/master/TSOClient/tso.simantics/Model/VMRoomInfo.cs)
- `VMRoutingFrame`: finds a "set of room portals to get to the target's room (calls their portal functions in order), then pathfinds to the relevant position once in the same room"; "find shortest room traversal to destination. Simple A* pathfind. Portals are considered nodes to allow multiple portals between rooms to be considered"; the sim is modelled as a portal into its own room as the start node; "portals are used to traverse floors, so we do not care about the floor each point is on"; if a portal function fails the route is re-evaluated with that portal in `IgnoredRooms` (`VMRouteFailCode.NoRoomRoute`). — [FreeSO VMRoutingFrame.cs](https://github.com/riperiperi/FreeSO/blob/master/TSOClient/tso.simantics/Engine/VMRoutingFrame.cs)
- Sims 2 lot portals are "invisible objects created automatically when a lot is made," six types, cloneable, and at least one non-beach portal must remain on a lot "for both portals on-lot and on the street"; a Portal Revealer mod shows them as placeholder boxes. — [SimsCommunity, Sims 2 portals guide](https://simscommunity.info/2026/07/06/the-sims-2-portals/)
- Sims 2 staircases: "normal stairs join two stories, and connecting stairs extend until they hit a floor or terrain tile." The default build cap is five floors; `setHighestAllowedLevel` raises it. — [StrategyWiki, The Sims 2 Tutorial 5](https://strategywiki.org/wiki/The_Sims_2/Tutorial_5); [SnootySims, Sims 2 cheats](https://snootysims.com/wiki/sims-2/cheats-for-pc/)
- Design origin: Will Wright described objects broadcasting "an advertisement of pheromones in a particular flavor, and the flavors are the eight basic needs of the Sims"; the objects "were originally there to score the architecture." — [GamesRadar, The making of The Sims](https://www.gamesradar.com/the-making-of-the-sims); [Don Hopkins, Designing User Interfaces to Simulation Games](https://donhopkins.medium.com/designing-user-interfaces-to-simulation-games-bd7a9d81e62d)
- A developer thread describing the Sims wall model: "walls are skinny and sit on the edges of the grid, so a tile with a wall on its edge stays walkable but can't be crossed through to the tile on the other side." — [GameDev.net, A* considering edges](https://gamedev.net/forums/topic/622781-a-considering-edges/)
- Sims 4 cross-floor routing failures reported by players: a platform under a turned staircase generated terrain on the floor above and caused "a routing failure"; too little headroom at the top of stairs; open staircases without railings treated as platforms "inaccessible to adult sims" so only children and pets could use them; a 1x1 room with no floor or ceiling blocking stairs; roofs over stairs blocking routes. — [EA forums 8541511](https://forums.ea.com/discussions/the-sims-4-gameplay-en/floor-issue-on-top-of-customised-stairs/8541511); [EA Answers, open staircase routing failures](https://answers.ea.com/t5/Bug-Reports/WORKAROUND-Open-staircase-cause-routing-failures/m-p/9734960); [EA forums 9248255](https://forums.ea.com/discussions/the-sims-4-mods-and-custom-content-en/my-stairs-wont-work/9248255)
- Sims 3 inter-lot routing: sims "often won't route from one lot to another" at different heights; Isla Paradiso lag attributed to spiral staircases placed incorrectly and public markers not placed in elevator shafts. — [ModTheSims thread 546924](https://modthesims.info/t/546924); [EA forums 187679](https://forums.ea.com/discussions/the-sims-3-technical-issues-en/fixing-town-lag-constant-error-trap-stuck-sims/187679/replies/187687)
- Room lighting and the "room score" are tied together in player documentation ("the amount of light also effects the overall room score"). — [StrategyWiki, Sims 2 lighting](https://strategywiki.org/wiki/The_Sims_2/Lighting/Outdoor_Lamps)

### Inferences
- The Sims is the clearest precedent for "rooms as derived data": rooms are never authored; they are recomputed by flood fill from edge walls whenever architecture changes, and everything (lighting, room score, routing) keys off the room id grid. That is exactly what RimWorld later did with regions.
- Multi-level routing collapses to a portal graph because stairs are objects with portal functions; the within-room pathfinder is 2D and ignores level. This is "graph of places" at room granularity inside a "continuous lot" presentation.
- The recurring stairs/headroom/platform failures across Sims 3 and 4 are the cost of inferring portal validity from geometry (headroom, railings, terrain) rather than from explicit authored links.

### Gaps
- Official Maxis documentation of Sims 1 room detection or the room score formula was not found; FreeSO is a reimplementation (of The Sims Online, which shares the Sims 1 engine lineage) and is the best available code-level source.
- I found no first-party description of Sims 4's level/routing data structures (tdesc, portals); only player-facing forum reports.

## Dwarf Fortress: first-class Z levels and what they cost

### Takeaway
Dwarf Fortress treats Z as a full third axis (typical embark ~50 land levels plus 15 sky, worldgen supports 400), with movement rules that let creatures change level only via stairs, ramps, flying, climbing or swimming. The cost is pathfinding: Tarn Adams uses plain A* plus walking-connectivity components maintained by flood fill, and reports that hierarchical overlays were too hard to keep current under constant terrain change; adding Z to an XY codebase took weeks.

### Cited Findings
- "Each layer of view is a discrete z-level with a value relative to the bottom of the map space"; default settings give "around 50 z-levels of land (for an embark with average elevation changes) with an additional 15 z-levels of empty sky space above the highest point of land"; 0 is sea level; worldgen can set a minimum of 6 and well over 600 ("Worldgen has 400 z-levels; maybe one can force 200 levels of sky"); reducing z-levels, especially caverns, "can reduce processor demand and boost framerate." An older page gave ~150 land levels, so the number has changed by version. — [DF Wiki, Z-level](https://dwarffortresswiki.org/index.php/Z-level); [DF Wiki, v0.31 Z-level](https://dwarffortresswiki.org/index.php/v0.31:Z-level)
- Map scale: a 1x1 embark cross-section is 48x48 tiles; 16x16 embark tiles is the maximum and covers one region tile; a tile is about 2 m x 2 m x 3 m. — [DF Wiki, Tile](https://dwarffortresswiki.org/index.php/Tile)
- Movement between levels: "Creatures can move directly up or down, as long as the target space is not blocked and the movement is possible (via flying, climbing, swimming, stairs, etc.)"; "Creatures can move diagonally across Z-levels only when both lateral and vertical movement are simultaneously possible," e.g. ramps. Traffic designations (High/Normal/Restricted) change path cost; restricted tiles on mandatory routes raise cost and can lower FPS "because pathing searches for alternate routes." A* "can search every tile, which is the main performance cost"; advice includes keeping routes 2 tiles wide and avoiding single doors and single stairs since dwarves path around an occupied 1-tile corridor. — [DF Wiki, Path](https://dwarffortresswiki.org/index.php/Path)
- In the 40d era, a dwarf could take a long route to a nearby level rather than a closer same-level stockpile because vertical distance counted for less than lateral. — [DF Wiki, 40d:Path](https://dwarffortresswiki.org/index.php/40d:Path)
- Tarn Adams: A* is "not good enough by itself"; jump point search does not fit because the map changes so often; "precomputed structures layered over the map were too hard to maintain as terrain changed"; the core trick is tracking connected components reachable by walking, updated by flood fill (if water splits the fortress one side gets a new index), and agents compare component numbers before pathing so most failed A* calls are avoided; component tracking covers only walkers (a separate flier index would cost memory and speed); adding a Z coordinate "required reworking logic written around X and Y. It took weeks and was the most tedious task he recalls"; the game is single-threaded apart from graphics and "at the edge of what we can currently support." — [Stack Overflow Blog, How Dwarf Fortress is built](https://stackoverflow.blog/2021/07/28/700000-lines-of-code-20-years-and-one-developer-how-dwarf-fortress-is-built/)

### Inferences
- DF shows that a true Z axis forces you to solve connectivity maintenance, not just path search: the component index is the price of admission, and it still does not help fliers.
- The number of levels scales simulation cost roughly linearly (the wiki's advice to cut cavern levels for FPS), which is why most "continuous Z" games cap at a handful of levels (Sims 5, PZ 8 then 32, U7 16 lifts).

### Gaps
- No primary source on DF's internal map block layout (16x16 blocks) or the exact component-index data structure was reachable; the DFHack API docs were not fetched.

## Project Zomboid, Shadows of Doubt, Kingdom Come: Deliverance, RimWorld, Prison Architect, Dungeon Keeper / Theme Hospital

### Takeaway
Among modern continuous-world games: Project Zomboid is one isometric world streamed in cells and chunks with per-tile Z (8 floors historically, up to 32 per chunk in Build 42, basements injected from prebuilt binaries) and explicit `BuildingDef`/`RoomDef` metadata (rooms as rect lists with a `level`); Shadows of Doubt builds a City > District > Block > Building > Floor > Address > Room hierarchy and uses doors as both room connectors and culling portals; KCD runs ~600-2,400 NPCs on daily cycles in a seamless CryEngine world using behaviour trees plus "smart areas" and AI LOD; RimWorld is a single-level map where rooms and reachability are derived from a 12x12-bounded region grid with doors as their own regions. Prison Architect, Dungeon Keeper and Theme Hospital define rooms by zoning/claiming tiles, with enclosure checks.

### Cited Findings

**Project Zomboid**
- Build 42 removed the old 8-storey cap "so that each chunk can have its own height, up to 32 levels"; basements are picked at random when an area first streams in "from a list of prebuilt basement buildings" exported as a binary and "injected into the map as it loads" to minimise disruption to the existing map, modded maps and tooling. — [NME report on The Indie Stone's Build 42 blog](https://www.nme.com/news/project-zomboids-very-big-build-42-update-will-introduce-basements-3320807)
- Each map cell is stored as a `lotheader`, a `chunkdata .bin`, and a `lotpack` file named by grid coordinates; legacy cells are 300x300 tiles and Build 42 source cells are 256x256; a community tool reprojects B42 cells into editable 300x300 WorldEd TMX cells and reports "variable Z levels preserved where present in the compiled data." — [Steam Workshop discussion](https://steamcommunity.com/workshop/filedetails/discussion/3017064123/3803905146216964674); [PZ_Vanilla_map_b42](https://github.com/Unjammer/PZ_Vanilla_map_b42)
- Runtime metadata: `IsoMetaChunk` holds rooms and zones per chunk with `addRoom(RoomDef)`, `getRoomAt(int x, int y, int z)`, `getEmptyOutsideAt(x, y, z)`, `getAssociatedBuildingAt(x, y)`, `getBuildingsIntersecting(...)`, `getRoomsIntersecting(...)`. — [PZ JavaDocs 42.21.0, IsoMetaChunk](https://albion.codeberg.page/PZ-JavaDocs/zombie/iso/IsoMetaChunk.html)
- `BuildingDef` fields: `rooms` and `emptyoutside` (`ArrayList<RoomDef>`), bounds `x, y, x2, y2`, `overlappedChunks`, collapse rect, `id`/`metaId`, `alarmed`, `seen`, `hasBeenVisited`, `lootRespawnHour`; methods `getMinLevel()`, `getMaxLevel()`, `containsXYZ(x, y, z)`, `getRoofRoomID(int)`, `isBasement()`, `isResidential()`, `isShop()`, `isFullyStreamedIn()`. — [PZ JavaDocs, BuildingDef](https://albion.codeberg.page/PZ-JavaDocs/zombie/iso/BuildingDef.html)
- `RoomDef` fields: `level` (int), `building` (`BuildingDef`), `rects` (`ArrayList<RoomDef.RoomRect>`), `name`, bounds `x, y, x2, y2`, `area`, `id`, `metaId`; methods `getZ()`, `isInside(x, y, z)`, `getRoomRect(x, y, z)`, `contains(x, y)`, `forEachChunk(...)`, `getFreeSquare()`, `getRandomSquare(...)`. So a room is a named union of rectangles on one level, owned by a building. — [PZ JavaDocs, RoomDef](https://albion.codeberg.page/PZ-JavaDocs/zombie/iso/RoomDef.html)
- 2013 tooling note: TileZed/BuildingEd building files (.tbx) are dragged onto the WorldEd map to place them; BuildingEd lets creators place multi-tile objects as single entities. — [The Indie Stone, 2013 modding tools post](https://projectzomboid.com/blog/news/2013/02/hello-hello-we-are-the-modding-tools/)

**Shadows of Doubt**
- "Buildings in Shadows of Doubt are split into floors, then divided into 'addresses', and within them 'rooms'," within a larger City > District > Block hierarchy; the aim is "generating huge numbers of apartments, offices, cafes" with little hand design. — [ColePowered DevBlog #13](https://colepowered.com/2019/02/)
- "The game breaks everything down into rooms connected with doors," streets are handled as rooms behind the scenes, and "doors act as the portal between them" for a custom culling system: trees/groups of rooms visible to the player are built from the door graph, and closed doors cut rendering behind them. — [DevBlog #22: Doors Galore](https://colepowered.itch.io/shadows/devlog/164492/shadows-of-doubt-devblog-22-doors-galore)
- Citizens: earlier routines were "almost entirely precomputed"; now paths are calculated dynamically so spontaneous actions do not break the routine; a "sims-like stat system" drives needs; AI update rate is high only near or on screen, making "about 95% of citizens at any time relatively insignificant" in cost. — [DevBlog #15: Moving in the Citizens](https://colepowered.itch.io/shadows/devlog/78044/shadows-of-doubt-devblog-15-moving-in-the-citizens)
- Player reports (late 2023) of crashes while riding elevators in large generated cities, with developers advising against large/extra-large cities. — [Steam discussion](https://steamcommunity.com/app/986130/discussions/0/4034727620349650714/)

**Kingdom Come: Deliverance**
- GDC 2026 session "Supporting Thousands of NPCs in Kingdom Come: Deliverance" (Petr Smrcek, Warhorse): KCD2 has "nearly 2,400" NPCs, about half in one city, "doing their daily routines and reacting to player actions even when the player is long gone"; "new techniques for the level of detail of the AI simulation had to be introduced, while making the scripting interface as oblivious to the LODs as possible"; takeaways include thread usage, "moving standardized logic to code," and "knowing what can be stripped away in various use cases." — [GDC schedule](https://schedule.gdconf.com/session/supporting-thousands-of-npcs-in-kingdom-come-deliverance-kingdom-come-deliverance-ii/915120); [GameDev.net summary](https://gamedev.net/news/5526-supporting-thousands-of-npcs-in-kingdom-come-deliverance-kingdom-come/)
- A 2018 Czech presentation by Smrcek lists ~600 simultaneously active NPCs with jobs, homes and a daily cycle, and AI challenges of navigation, perception, behaviour trees, smart objects, scheduling and object relations. — [Smrcek presentation (PDF, Czech)](https://www.karlin.mff.cuni.cz/mffseminar/prezentace_smrcek.pdf)
- The "Smart Areas" paper (Cerny, Plch, Marko, Ondracek, Brom; ICAART 2014; two authors at Prague Game Studios) describes the system "for an upcoming AAA RPG game": behaviour trees extended with variables and types plus an NPC messaging system; a Smart Area is "a specific place within the game world (e.g., a pub) that contains all the information the NPCs need to behave appropriately in this place"; NPCs pull behaviours via a BT "request node"; areas form a parent-child hierarchy ("make the whole city a SA and make the pubs its children"), so an NPC requests "have fun" from the city and receives a BT that moves it to a pub and requests "drinking" there; SAs can be created on the fly for dynamic situations; design objectives include adding "new places where NPCs could perform some of the activities (e.g., a new pub) ... without changing any of the NPC code." The paper does not name KCD. — [Smart Areas paper (PDF)](https://www.scitepress.org/Papers/2014/49211/49211.pdf)
- A GDC-reported detail: Warhorse built a "Long Distance Move" component so that two of ~550 characters with horses could navigate correctly in the first game. — [Shazoo (Russian report)](https://shazoo.ru/2025/03/20/165400/razrabotcikam-kingdom-come-deliverance-prislos-sozdat-sloznuiu-sistemu-navigacii-vsego-dlia-dvux-npc-s-losadmi)

**RimWorld**
- 2013 dev blog: A* "has a known weakness when no path exists," scanning the whole map; fix: "Every walkable square in the map is marked with a zone index number" by an optimized flood fill; colonists compare indexes first; full regeneration took ~5.5 ms on a 200x200 map, too slow per frame, so only affected regions are regenerated on change. — [Ludeon blog, Reachability at last](https://ludeon.com/blog/2013/07/reachability-at-last)
- Wiki: "The map is divided into 12x12 regions. Regions must be contiguous, are subdivided otherwise, and never extend past their 12x12 grid cell"; impassable buildings and terrain split regions and regions merge when possible; "A single-tile door creates a 3-tile map region centered on the door," a double door creates one region per tile, and "Door-created regions don't interact with any other regions, including each other." A room is an area fully enclosed by walls, doors (open or closed), vents, natural rock or coolers; "A room can be at most 36 map regions"; largest possible room 72x72 (5,184 tiles) but an empty 50x50 is the largest that avoids region issues; above the limit the area is "indoor space that isn't a room"; "The more complex a room's shape, the more likely it is to run into map region problems." Room roles are scored from contents (e.g. Dining room 12 points per table, Kitchen 28 per cooking station). — [RimWorld Wiki, Rooms](https://www.rimworldwiki.com/wiki/Rooms)
- Doors: opening time depends on material (wood quick, steel moderate, stone very slow); forbidden doors block colony pawns even when open; raiders "treat a closed door like a wall and break one only if no other path to their target exists"; doors count as room boundaries and support roofs. — [RimWorld Wiki, Door](https://www.rimworldwiki.com/wiki/Door)
- A mod changelog notes pawns "still try jobs they cannot reach, because reachability checks look at rooms rather than individual cells." — [Steam Workshop changelog](https://steamcommunity.com/sharedfiles/filedetails/changelog/1084452457?p=38)
- Secondary (unsourced) claim: long paths are planned region-to-region, then refined to tiles; region pathfinding arrived in Alpha 4 (2014); Dev Mode shows a wooden door as "+45" extra ticks. — [RimWorldHub](https://rimworldhub.com/post/ai_paths_unpacked_rimworld_routing_quirks__tactics)

**Prison Architect, Dungeon Keeper, Theme Hospital**
- Prison Architect (community reports): "Only foundations are considered indoors"; a walled area without a foundation "is simply a walled off outdoor area"; a broken rectangle makes things "seen as outside"; a room zone must cover every tile ("if you miss even one square, it won't count"). — [Steam discussion 3105763714512324525](https://steamcommunity.com/app/233450/discussions/0/3105763714512324525); [Steam discussion 487870763297010915](https://steamcommunity.com/app/233450/discussions/0/487870763297010915)
- Dungeon Keeper: a room's flag appears on the first tile laid; efficiency depends on surrounding same-type room tiles and walls; rooms are captured tile-by-tile by enemy imps draining room health. — [Dungeon Keeper Wiki, Room Flags](https://dungeonkeeper.fandom.com/wiki/Room_Flags)
- Theme Hospital (CorsixTH reimplementation): a room type is declared as data, e.g. `room.id = "gp"`, `room.minimum_size = 4`, `room.objects_needed = { desk = 1, cabinet = 1, chair = 1 }`, `room.objects_additional = {...}`, `room.wall_type`, `room.floor_tile`, `room.required_staff = { Doctor = 1 }`; the player draws the rectangle and places the door. — [CorsixTH rooms/gp.lua](https://github.com/CorsixTH/CorsixTH/blob/master/CorsixTH/Lua/rooms/gp.lua)

### Inferences
- PZ and SoD both end up with an explicit building/room metadata layer on top of the tile world (`BuildingDef`/`RoomDef`, Floor/Address/Room). A continuous world does not remove the need for a place graph; it moves it from the map format into derived or authored metadata.
- RimWorld's region design is the mature version of The Sims' room flood fill: bounded region size (12x12) keeps incremental updates cheap, doors are isolated regions so door state can be toggled without re-flooding neighbours, and the room limit (36 regions) is a direct consequence of making rooms unions of regions.
- SoD's choice to make streets "rooms" and doors "portals" unifies culling and pathing on one graph; this is the same door-graph idea as Stardew's warp cache applied at room granularity in a continuous 3D world.

### Gaps
- The Indie Stone's original Build 42 blog post and any lotpack/lotheader byte-level spec were not reachable; cell/chunk numbers come from community tools.

## Zelda (ALttP, OoT/MM), Animal Crossing, Harvest Moon and Stardew-adjacent games: scene-swap conventions

### Takeaway
Zelda games use a scene/room hierarchy with explicit connectors: ALttP has an overworld of large screens plus a separate underworld of fixed-size rooms, and OoT/MM scenes list their rooms, their entrances (start position + room) and "transition actors" (doors) that name a front room and a back room. GameCube Animal Crossing is a 5x6 grid of 16x16-tile acres loaded separately. For Harvest Moon, Graveyard Keeper and Moonlighter I found no technical sources.

### Cited Findings
- ALttP overworld uses 32x32 metatiles each made of four 16x16 metatiles, with separate arrays per quadrant. — [TCRF, ALttP Development: Maps](https://new.tcrf.net/Development:The_Legend_of_Zelda:_A_Link_to_the_Past/Maps)
- ALttP dungeon room layout "is specified in 32 vertical rasters of 22 tiles," with a 12x7 interior defined by indices into 12-byte groups; column specifiers use bit 7 as a column-start flag and bits 6-4 as a repeat count. — [sicherman.net, Zelda moon map notes](https://sicherman.net/videogames/zelda/moonmap.html)
- OoT/MM: a scene header contains the room list (0x04; each room a start/end address pair), entrance list (0x06; 2-byte entries pairing a start position with a room), start positions (0x00), exit list (0x13; entrance-table indices), collision (0x03) and transition actors (0x0E). Transition actors are "scene-level actors that switch which room is loaded," up to 64 per scene, each defining "a room to load from the front and a room to load from the back," camera modes, actor number, position, Y rotation and init variable. A scene can have up to 32 rooms "without encountering potential issues." Room object lists (max 15) are compared on transition and mismatched trailing objects are unloaded. — [CloudModding, OoT Scenes and Rooms](https://wiki.cloudmodding.com/oot/Scenes_and_Rooms)
- Animal Crossing acres are 16x16 tiles; the GameCube games have a 5-across by 6-down town (30 acres, A-1..F-5 style labels); Wild World 4x4, City Folk 5x5, New Leaf 5x4 (acres largely removed), New Horizons 7x6 (42, labelled). Entering an acre spawns one fish and one bug at set locations; bugs cannot leave their acre. — [Nookipedia, Acre](https://nookipedia.com/wiki/Acre)
- The GameCube game used "completely separately loaded acre squares, which have since been replaced by the 'rolling log' system used today." — [Animal Crossing World analysis](https://animalcrossingworld.com/2020/02/16-smaller-fun-features-details-in-animal-crossing-new-horizons-you-might-have-missed-analysis/)

### Inferences
- OoT's transition actor (front room / back room on one door) is the cleanest shipped example of a door as a bidirectional edge object owned by the container scene rather than by either room; Stardew's model by contrast stores two independent one-way warps.
- The acre system shows the "stitched screens" approach surviving into a 3D game: separate loads per 16x16 block with gameplay rules (spawns, bug confinement) that leak the block boundary to players.

### Gaps
- No ALttP source on the overworld area count, the entrance/exit tables, or how areas connect; the Data Crystal and ZScream pages were unreachable (HTTP 526).
- Harvest Moon: Friends of Mineral Town has a Data Crystal entry with ROM/RAM map sub-pages but I did not reach any warp/map format detail. — [Data Crystal, HM:FoMT](https://datacrystal.tcrf.net/wiki/Harvest_Moon:_Friends_Of_Mineral_Town)
- Graveyard Keeper and Moonlighter: no technical sources about scene structure, warps or NPC schedules were found in two searches.
- Majora's Mask specifically: covered only by the OoT page (shared engine); no MM-specific scene documentation was fetched.

## Pathfinding across maps and floors: HPA*, portal/door graphs, region systems, and simulating NPCs that are elsewhere

### Takeaway
Every shipped approach examined reduces to a two-level search: a coarse graph of places (Stardew locations, Sims rooms, RimWorld regions, HPA* clusters, SoD rooms) connected by portals (warps, doors, stairs, cluster entrances), then a local grid/geometry search inside the place. Off-screen NPC simulation splits into "really walk the tiles everywhere" (Stardew updates every location every tick) and "lower the update rate or LOD for far NPCs" (Shadows of Doubt, KCD).

### Cited Findings
- HPA* (Botea, Muller, Schaeffer, 2004): abstracts a grid into linked local clusters, pre-computes and caches optimal crossing distances, and plans at the cluster level; "up to 10 times faster" than optimized A* "while finding paths that are within 1% of optimal"; a later paper reproduces a figure with 10x10 sectors where "entrances along the borders between the sectors become nodes in the abstract graph." Publication details differ between records (Journal of Game Development 1(1), pp 1-22 vs pp 7-28). — [UAlberta papersdb record](https://papersdb.cs.ualberta.ca/~papersdb/view_publication.php?pub_id=585); [Jansen & Buro (AAAI)](https://cdn.aaai.org/ojs/18791/18791-52-22495-1-10-20210929.pdf); [Botea et al. PDF](https://webdocs.cs.ualberta.ca/~mmueller/ps/hpastar.pdf)
- A reference implementation notes paths route "through predetermined boundary nodes" and are therefore "a bit less optimal" than plain A*. — [hugoscurti/hierarchical-pathfinding](https://github.com/hugoscurti/hierarchical-pathfinding/blob/master/readme.md)
- Graph representation basics: edges can be directed ("one-way doors, ledge jumps, and portals"), weighted, or multigraph (two ways across the same river); "rooms as nodes and hallways as edges" is a standard dungeon representation. — [Red Blob Games, Grids and Graphs](https://www.redblobgames.com/pathfinding/grids/graphs.html)
- Stardew's two levels: `WarpPathfindingCache.GetLocationRoute` (location sequence) then `PathFindController.findPathForNPCSchedules` per leg with a 30,000-iteration cap; NPCs in all locations are updated every tick on the host (`Utility.ForEachLocation` -> `updateEvenIfFarmerIsntHere` -> `updateCharacters`). — [WarpPathfindingCache.cs](https://github.com/AcidicNic/StardewValleyDecompiled1.6/blob/2878fb248092f9f5b8704ad2cc7e19d0abe1cf45/StardewValley.Pathfinding/WarpPathfindingCache.cs); [NPC.cs](https://github.com/AcidicNic/StardewValleyDecompiled1.6/blob/2878fb248092f9f5b8704ad2cc7e19d0abe1cf45/StardewValley/NPC.cs); [Game1.cs](https://github.com/AcidicNic/StardewValleyDecompiled1.6/blob/2878fb248092f9f5b8704ad2cc7e19d0abe1cf45/StardewValley/Game1.cs)
- Sims (FreeSO): room-portal A* with portals as nodes, then in-room pathfinding; portal failure triggers re-planning with that portal excluded. — [FreeSO VMRoutingFrame.cs](https://github.com/riperiperi/FreeSO/blob/master/TSOClient/tso.simantics/Engine/VMRoutingFrame.cs)
- RimWorld: region index comparison before A*; 12x12-bounded regions; door regions isolated. — [Ludeon blog](https://ludeon.com/blog/2013/07/reachability-at-last); [RimWorld Wiki, Rooms](https://www.rimworldwiki.com/wiki/Rooms)
- Dwarf Fortress: connected-component index for walkers maintained by flood fill; hierarchical overlays rejected because of map churn. — [Stack Overflow Blog](https://stackoverflow.blog/2021/07/28/700000-lines-of-code-20-years-and-one-developer-how-dwarf-fortress-is-built/)
- Shadows of Doubt: dynamic path computation for citizens with update rate scaled by proximity to the player (~95% of citizens cheap). — [DevBlog #15](https://colepowered.itch.io/shadows/devlog/78044/shadows-of-doubt-devblog-15-moving-in-the-citizens)
- KCD: AI simulation LOD so thousands of NPCs keep routines "even when the player is long gone." — [GDC schedule](https://schedule.gdconf.com/session/supporting-thousands-of-npcs-in-kingdom-come-deliverance-kingdom-come-deliverance-ii/915120)

### Inferences
- A "graph of places joined by doors" is not an alternative to a continuous world's pathfinder; it is the top level of the pathfinder every continuous-world game ends up writing (regions, rooms, clusters). The real choice is whether that graph is authored (Stardew warps, Pokémon warps, OoT transition actors) or derived (Sims rooms, RimWorld regions, HPA* clusters).
- Authored graphs fail by omission (missing warp, unreachable schedule target) and the failure is detectable at load time (Stardew throws during `dayUpdate`). Derived graphs fail by geometry (headroom, platform vs stairs, region shape limits) and the failure is discovered at runtime by a stuck agent.
- Stardew's "walk everywhere every tick" works because the whole world is ~30-40 small maps and one NPC per location update is cheap; it is the simplest correct model for a Stardew-scale town and avoids any travel-time estimation.

### Gaps
- The Botea et al. PDF itself returned 503 both at the old and new host, so cluster-size defaults and memory figures are from secondary citations.
- I did not find a shipped 2D town game that estimates travel time and teleports NPCs along the warp graph instead of simulating them; the brief's premise of "teleport at a travel-time estimate" is not confirmed for Stardew, where NPCs really walk. If any Stardew-like does this I did not find it documented.

## Authoring consequences and the decision: graph of places vs continuous Z

### Takeaway
Across these games the reported authoring pain divides cleanly. Graph-of-places games suffer from connector bookkeeping (one-way connections authored twice, warp tiles that double as barriers, missing warps crashing the day) but give authors free interior sizing and trivially isolated edits. Continuous-Z games suffer from vertical authoring (U7 roofs built from many objects with individual heights, Sims stair/headroom/platform rules, PZ needing a whole new height model for basements) and from schedule data that must carry Z, but give seamless movement and a single coordinate space for simulation.

### Cited Findings
- Stardew: interior and exterior defined independently (`Size` vs `IndoorMap`), warps are per-tile strings in map properties, interior doors require two coordinated properties, tile property order depends on tilesheet order (prefix custom sheets with `z_`), map width over 200 breaks layering. — [Modding:Buildings](https://stardewvalleywiki.com/Modding:Buildings); [Modding:Maps](https://stardewvalleywiki.com/Modding:Maps)
- Stardew: a single bad schedule route throws during new-day setup; NPC pathing bugs arise from other mods adding warps to shared maps ("run `patch summary` on the map to find warps added by other mods"). — [Troubleshooting: NPCs](https://stardewmodding.wiki.gg/wiki/Troubleshooting:_NPCs); [Stardew forums 27022](https://forums.stardewvalley.net/threads/schedule-pathing-error-in-update-loop-dont-know-the-source.27022/latest)
- Pokémon: "Connections are one-way. Each map's side of a connection must be set separately," and both maps must be saved. — [Porymap manual](https://huderlem.github.io/porymap/manual/editing-map-connections.html)
- Ultima VII / Exult: "Constructing a roof can be a long and difficult process because it involves properly positioning multiple small objects and then manually setting each object's height"; schedules had no Z so upper floors went unused until Exult extended the record to 8 bytes. — [exult_studio.txt](https://github.com/exult/exult/blob/master/docs/exult_studio.txt); [schedule.h](https://github.com/exult/exult/blob/master/schedule.h); [Exult forum p=26491](https://exult.sourceforge.io/forum/viewtopic.php?p=26491)
- Sims: cross-floor route failures from headroom, railings, platforms, stray 1x1 rooms, roofs; Sims 3 inter-lot routing at different heights. — [EA Answers](https://answers.ea.com/t5/Bug-Reports/WORKAROUND-Open-staircase-cause-routing-failures/m-p/9734960); [EA forums 8541511](https://forums.ea.com/discussions/the-sims-4-gameplay-en/floor-issue-on-top-of-customised-stairs/8541511); [ModTheSims 546924](https://modthesims.info/t/546924)
- RimWorld: room shape complexity and the 36-region cap are authoring constraints players hit when building large or irregular rooms. — [RimWorld Wiki, Rooms](https://www.rimworldwiki.com/wiki/Rooms)
- Dwarf Fortress: adding Z "took weeks and was the most tedious task" and precomputed path hierarchies were abandoned because terrain changes constantly. — [Stack Overflow Blog](https://stackoverflow.blog/2021/07/28/700000-lines-of-code-20-years-and-one-developer-how-dwarf-fortress-is-built/)
- Project Zomboid: basements were added by injecting prebuilt binary buildings at stream time precisely to avoid disrupting "the existing map development, modded maps and everything else." — [NME on Build 42 blog](https://www.nme.com/news/project-zomboids-very-big-build-42-update-will-introduce-basements-3320807)
- Zelda OoT: room object-list ordering causes actors to unload on room transitions, a data-ordering hazard of per-room loading. — [CloudModding](https://wiki.cloudmodding.com/oot/Scenes_and_Rooms)

### Inferences
- For a Stardew-like with scheduled NPCs, the evidence favours the graph of places: it matches how schedules are authored (time, place, tile), it makes unreachable schedule entries a load-time error rather than a runtime stall, it allows interiors larger than footprints, and Stardew's own off-screen model (simulate every place every tick) needs no travel-time estimation at that scale. Its known problems are all addressable with validation: check every schedule hop against the warp graph at load, forbid warp sources on arbitrary walkable tiles, store doors as single bidirectional records (as OoT does) rather than two one-way warps, and keep a shortest-route (not first-found) route table.
- A continuous world with a Z axis buys seamless exteriors and genuine upper floors but, per U7, Sims and DF, obliges you to (a) put Z in every schedule record, (b) define stair/ramp walkability rules and keep a connectivity index over them, and (c) cap the level count. Hybrid designs (Pokémon's stitched exteriors plus warped interiors; SoD's room-door graph inside a continuous city) show the two are composable: stitch exteriors if seamless outdoor travel matters, keep interiors and floors as graph nodes.

### Gaps
- No developer postmortem was found that directly compares the two models on authoring cost; the above is assembled from per-game evidence.
