# Google image generation and editing models for 2D game assets (as of 2026-10-22)

Scope: Google-only (Gemini "Nano Banana" family, Imagen, Vertex AI / "Gemini Enterprise Agent Platform"), evaluated for producing sprites, characters, tiles, buildings and props for a Stardew-style top-down game from a headless Node/TypeScript pipeline with no GPU. Non-Google models and third-party pixel-art tools are out of scope.

Naming note that affects every source below: during 2026 Google renamed "Vertex AI" to "Gemini Enterprise Agent Platform" in its docs and terms. The Vertex AI deprecations page now says "Vertex AI documentation is no longer being updated and ... its services are now part of Gemini Enterprise Agent Platform" — [Vertex AI deprecations](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/deprecations). Older sources say "Vertex AI"; newer ones say "Agent Platform". They are the same product line.

## Which models exist now (IDs, dates, status)

### Takeaway
As of October 2026 Google's image lineup is entirely Gemini-native ("Nano Banana"): `gemini-nano-banana-2.1` (GA, Oct 6 2026, the recommended default), `gemini-3.1-flash-lite-image` (GA, cheapest), `gemini-3.1-flash-image` (GA May 2026, deprecated Oct 6 2026 with no shutdown date), `gemini-3-pro-image` (GA May 2026, premium), and legacy `gemini-2.5-flash-image`. Every Imagen model (3 and 4, all variants, plus the Imagen editing/customization "capability" models and product-recontext) is shut down or deprecated, and Google has no model with explicit sprite, pixel-art or "game asset" features.

### Inferences
- For a new pipeline the realistic choices are `gemini-nano-banana-2.1` (default), `gemini-3.1-flash-lite-image` (bulk/cheap, but weak on references and multi-turn), and `gemini-3-pro-image` (hardest compositions, text, sprite-sheet layouts). ## Reference images, consistency, and the API parameters

### Takeaway
Reference images are passed as ordinary image input parts (no named "reference" parameter); the docs cap it at 14 mixed references, with per-model sub-limits for "objects", "characters" and (Pro only) "style". Consistency across a set is reported by developers as good for style and identity but unreliable for exact proportions, scale and grid placement across separate calls; no Google eval of cross-set consistency exists.

### Cited Findings
- "Nano Banana models allow you to mix up to 14 reference images." Sub-limits: Gemini 3.1 Flash Lite Image: up to 14 object images, characters N/A, style N/A; Nano Banana 2.1 and 3.1 Flash Image: up to 10 object images "with high-fidelity to include in the final image", "Up to 5 images of characters to maintain character consistency", style N/A; Gemini 3 Pro Image: up to 6 object images, characters N/A (as printed), "Up to 3 images to be used as style references" — [Gemini API: Image generation](https://ai.google.dev/gemini-api/docs/image-generation). The 2.1 model page says "character consistency for up to 4 characters and object fidelity for up to 10 objects" — [Gemini API: gemini-nano-banana-2.1](https://ai.google.dev/gemini-api/docs/models/gemini-nano-banana-2.1) (5 vs 4: the two Google pages disagree).
- Mechanism: in the Interactions API the request is `input: [{type:"text", text}, {type:"image", data:<base64>, mime_type:"image/png"}, ...]`; the prompt itself says what each image is for (e.g. "An office group photo of these people"). There is no `reference_type`, `subject_id` or similar field in the examples — [Gemini API: Image generation](https://ai.google.dev/gemini-api/docs/image-generation)
- Agent Platform limits for 2.1: "Maximum images per prompt: 14", 7 MB per inline image, 30 MB from Cloud Storage, input MIME types `image/png, image/jpeg, image/webp, image/heic, image/heif`, "Nano Banana 2.1 consumes 1,120 tokens per input image" — [Agent Platform: Nano Banana 2.1](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/nano-banana-2-1)
- Multi-turn editing uses `previous_interaction_id` to continue a conversation; the doc recommends "iterate conversationally and state which elements must stay unchanged" — [Gemini API: Image generation](https://ai.google.dev/gemini-api/docs/image-generation)
- Developer report (Ben Hoyle, March 7 2026, Nano Banana Pro via the Gemini web app, ~48 clothing sprites and 26 character sprites for a casual mobile game): the model "was good at keeping a cartoon style across a sheet and mostly kept character identity across poses" but "did not reliably keep exact proportions across separate generation calls, so a character could vary slightly between sheets"; recommends one character per sheet, two at most; "Keep each sheet small: 3-6 items per row, 2-3 rows maximum. Style consistency drops with complexity" — [roboticape.com](https://roboticape.com/2026/03/07/generating-game-sprites-with-gemini-image-generation-nano-banana-pro-lessons-learned/)
- Same report: the model "did not space sprites in a uniform grid, even when asked. Sprites varied in width with their content"; uniform slicing merged two poses when one row had 6 sprites and the next 5; content-aware slicing (connected non-transparent regions and transparent-column boundaries) found the correct 11 boundaries and is recommended as the default — [roboticape.com](https://roboticape.com/2026/03/07/generating-game-sprites-with-gemini-image-generation-nano-banana-pro-lessons-learned/)
- A walk-cycle guide (geekvibesnation, ~Oct 2026) recommends defining each frame's view/action/direction up front, keeping an approved reference image alongside, using distinctive landmarks (scarf, helmet, boots) to check drift, and generating poses on identical canvases with ground-level and center guides because otherwise "the animation can bounce because of inconsistent cropping rather than the character's motion" — [geekvibesnation.com](https://geekvibesnation.com/nano-banana-pro-sprite-sheets-make-the-walk-cycle-work) (practitioner guide, no measurements)
- A SpriteCook review of Nano Banana 2 Lite found a nine-slot inventory set "uniform" but recommended full Nano Banana 2 or Pro "for batches where everything has to match" (vendor blog) — [spritecook.ai](https://www.spritecook.ai/blog/nano-banana-2-lite-fast-pixel-art)
- fal.ai claims Nano Banana Pro "keeps a character's identity across poses and lighting setups" (vendor claim) — [blog.fal.ai](https://blog.fal.ai/nanobana-pro-is-now-available-on-fal/)
- Gemini 2.5 Flash Image GA on Vertex (Oct 2025) added "image generation from multiple reference images, and improved multi-turn image editing" — [Vertex AI release notes](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/release-notes)

### Inferences
- For 8-direction walk cycles or four-season buildings, the viable pattern is: generate one canonical reference per character/building, then pass it as a character/object reference in every subsequent call with an explicit pose/direction/season instruction, on a fixed canvas and aspect ratio. Expect drift in proportions between calls; plan an automated trim/normalize step and a human QA pass. Nothing Google publishes quantifies drift.
- The Pro model's "characters N/A / style up to 3" vs 2.1's "characters up to 5 / style N/A" split suggests Pro is better for style-locking a whole asset set, and 2.1 for locking specific character identities. This is an inference from the limit table, not a benchmark.

### Gaps
- No Google-published eval of character consistency across many generations (walk cycles, seasons). Only anecdotal developer reports.
- No Reddit/X threads specific to 8-direction sprite consistency with Nano Banana surfaced in searches.

## Transparency (alpha output) and matting

### Takeaway
No Google model outputs an alpha channel; requesting transparency produces fake checkerboards or flat backgrounds. The working recipe in developer reports is a solid `#00FF00` background plus a 2-3 px white outline around each sprite, then HSV chroma-key removal in post. Google's own segmentation/background products (Imagen product recontext, Imagen 3 capability masks) are deprecated.

### Cited Findings
- Google's image-generation doc never mentions transparent backgrounds, alpha, or RGBA; output `mime_type` options are `image/jpeg` or `image/png` — [Gemini API: Image generation](https://ai.google.dev/gemini-api/docs/image-generation)
- Ben Hoyle: "Attempt 1 asked for a transparent background directly. This failed because the model returns flat RGB images. It rendered checkerboards, white, or black backgrounds instead." Conclusion: "Gemini image models cannot generate true transparency." Magenta/black backgrounds with brightness thresholds failed because black outlines matched the background and "anti-aliasing blended background color into edge pixels". Working solution: `#00FF00` background, "a clean white outline/border 2-3 pixels wide around every sprite in every frame", HSV green detection (hue ±22° around 120°, saturation > 0.3, value > 0.3), occasional GIMP cleanup when green was non-uniform; "Expect green to sneak into sprites occasionally, despite instructions" — [roboticape.com](https://roboticape.com/2026/03/07/generating-game-sprites-with-gemini-image-generation-nano-banana-pro-lessons-learned/)
- That workflow is credited to Phil Schmid's "transparent stickers with Nano Banana" post; the URL I tried (philschmid.de/transparent-stickers-nano-banana) returned 404, so the primary could not be verified — [roboticape.com](https://roboticape.com/2026/03/07/generating-game-sprites-with-gemini-image-generation-nano-banana-pro-lessons-learned/)
- Third-party alternatives: Replicate's `jide/nano-banana-2-transparent` generates the image on white and black backgrounds and computes per-pixel alpha from the pair; `jide/nano-banana-2-bg-remove` returns an alpha PNG at input dimensions; an MCP server (`nano-banana-claude`) runs rembg (U2-Net) after generation — [replicate.com/jide/nano-banana-2-transparent](https://replicate.com/jide/nano-banana-2-transparent); [glama.ai MCP listing](https://glama.ai/mcp/servers/hfs9yobln6)
- Google's segmentation-style products: Imagen product recontext (`imagen-product-recontext-preview-06-30`) was 1:1 1024x1024 only, access by request form, 50 RPM per project — [Vertex AI product recontext docs (ja)](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/models/imagen/product-recontext-preview-06-30?hl=ja); it is listed as a discontinued endpoint (migrate to `gemini-2.5-flash-image` before March 19, 2026) — [Vertex AI release notes](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/release-notes)
- Imagen's mask-based editing ("inserting and removing objects, expanding image content beyond original borders, and replacing backgrounds through mask-based editing") used `imagen-3.0-capability-001`, available only via the Agent Platform/Vertex provider — [Firebase AI Logic: Edit images with Imagen](https://firebase.google.com/docs/ai-logic/edit-images-imagen-overview); `imagen-3.0-capability-001/002` are in the June 30, 2026 deprecation table — [Vertex AI release notes](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/release-notes)
- Google's own sticker prompt template ends with "The background must be white." — [Gemini API: Image generation](https://ai.google.dev/gemini-api/docs/image-generation)

### Inferences
- In a no-GPU Node pipeline, chroma-key with `sharp` (or raw pixel loops) is the only Google-adjacent option; a CPU rembg/U2-Net run is possible but slower. The white-outline trick matters because it moves the anti-aliased fringe to white instead of green, which is also what Stardew-style sprites usually have anyway (dark outline is more typical; test both).

### Gaps
- No Google background-removal or matting API exists after the Imagen capability model deprecation; nothing in Agent Platform docs replaced it.

## Editing and iteration (inpainting, outpainting, masks, multi-turn)

### Takeaway
Editing is instruction-based: send the image plus text ("change only X, keep everything else the same"). Google calls this "inpainting (semantic masking)"; there is no binary mask parameter in the Gemini API, and the mask-capable Imagen editing models are deprecated. Multi-turn works via `previous_interaction_id`. Whether edits preserve pixel grids is not documented and developer reports say grids are not preserved even in single generations.

### Cited Findings
- "2. Inpainting (semantic masking): Conversationally define a 'mask' to edit a specific part of an image while leaving the rest untouched." Template: "Using the provided image, change only the [specific element] to [new element/description]. Keep everything else in the image exactly the same, preserving the original style, lighting, and composition." — [Gemini API: Image generation](https://ai.google.dev/gemini-api/docs/image-generation)
- Agent Platform 2.1 capabilities: "Edit images, Multi-turn image editing: Supported" — [Agent Platform: Nano Banana 2.1](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/nano-banana-2-1)
- Third-party claims of "mask-based editing" for 2.1 (kie.ai, a ComfyUI workflow) exist, but the ComfyUI page is a community node and the APIYI docs describe only image+instruction edits with no mask parameter; no Google doc describes a mask input for Nano Banana — [comfy.org workflow](https://comfy.org/workflows/87fbc75b952a-87fbc75b952a/); [apiyi docs](https://docs.apiyi.com/en/api-capabilities/gemini-nano-banana-2.1/skills)
- Outpainting: not covered in the Gemini image doc; it was an Imagen capability-model feature ("expanding image content beyond original borders") now deprecated — [Firebase AI Logic](https://firebase.google.com/docs/ai-logic/edit-images-imagen-overview)
- Thinking: "Gemini 3 image models always think and this cannot be turned off"; they may produce up to two interim "thought images" (not charged); `thinking_level` is `minimal`/`medium`/`high` (2.1 default `medium`, 3.1 Flash default `minimal`, Pro always on) — [Gemini API: Image generation](https://ai.google.dev/gemini-api/docs/image-generation)
- Output images are always regenerated at the model's resolution table sizes (1024x1024 for 1:1 at 1K etc.); the 2.1 page notes "tiling artifacts on wide and panoramic aspect ratios (1:4, 4:1, 1:8, 8:1) were fixed at 2K and 4K" — [Gemini API: gemini-nano-banana-2.1](https://ai.google.dev/gemini-api/docs/models/gemini-nano-banana-2.1)

### Inferences
- Because every edit re-renders the whole image at a fixed output size, an "edit" of a 32x32 sprite is really a re-synthesis at 1024x1024 (or 512x512 on 3.1 Flash Image) and must be re-quantized/re-snapped afterward. Pixel-exact preservation of unchanged regions should not be assumed; diff the result against the original.

### Gaps
- No Google documentation on whether unchanged regions are bit-identical after a semantic-mask edit; no developer measurement found.

## Pixel art, small sizes, resolutions, tileability

### Takeaway
Minimum native output is 512px (0.5K, `gemini-3.1-flash-image` only, a deprecated model) and otherwise 1K/2K/4K; every model paints "pixel art" at high resolution with an inconsistent logical-pixel grid and soft edges, so true 32x32/64x64 tiles require grid detection and nearest-neighbor downsampling in post. Seamless tiling is not a feature and is reported as unreliable.

### Cited Findings
- Resolutions: "Gemini 3 image models generate 1K images by default but can also output 2K, 4K, and 512px (0.5K) (Gemini 3.1 Flash Image only)"; "Gemini 3.1 Flash Lite image model only supports 1K"; uppercase `"1K"/"2K"/"4K"/"512px"` required ("Lowercase parameters (e.g., 1k) will be rejected"); 512px "not supported on Gemini Nano Banana 2.1" — [Gemini API: Image generation](https://ai.google.dev/gemini-api/docs/image-generation)
- Pixel dimensions (Nano Banana 2.1, 1K): 1:1 1024x1024; 3:2 1264x848; 2:3 848x1264; 4:3 1200x896; 3:4 896x1200; 4:5 928x1152; 5:4 1152x928; 16:9 1376x768; 9:16 768x1376; 21:9 1584x672; 1:4 512x2048; 4:1 2048x512; 1:8 384x3072; 8:1 3072x384. 2K doubles, 4K quadruples. 3.1 Flash Image 512px: 1:1 512x512, 4:1 1024x256, 3:2 632x424, etc. — [Gemini API: Image generation](https://ai.google.dev/gemini-api/docs/image-generation)
- Supported aspect ratios on 2.1 (Agent Platform): `1:1, 3:2, 2:3, 3:4, 1:4, 4:1, 4:3, 4:5, 5:4, 1:8, 8:1, 9:16, 16:9, 21:9` — [Agent Platform: Nano Banana 2.1](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/nano-banana-2-1)
- SpriteCook (March 19, 2026, vendor blog) on Nano Banana 2: output "usually 1024x1024"; "some pixels at 6px and others at 7px, with sub-pixel noise everywhere"; colors bleed across edges so engine downscaling produces "mush"; the model "ignores or inconsistently follows canvas sizes such as 32x32 or 64x64"; recommends generating at highest resolution, detecting the intended grid (e.g. 1024 -> ~64x64 at 16x), resampling one logical pixel per output pixel, optional palette reduction to 8/16/32/64 colors, importing with nearest-neighbor filtering; prompt tips: say "side view"/"front view" (default is 3/4), include "2d game sprite", "limited color palette" — [spritecook.ai](https://www.spritecook.ai/blog/nanobanana-pixel-art-for-games)
- Ben Hoyle's pipeline resized every sprite to a max dimension of 128 px (23 MB -> 7 MB) and auto-trimmed with PIL `getbbox()`; "Expect to trim and resize every sprite, since exact per-sprite pixel dimensions are not achievable" — [roboticape.com](https://roboticape.com/2026/03/07/generating-game-sprites-with-gemini-image-generation-nano-banana-pro-lessons-learned/)
- Tiling: a creator found detailed prompts with Gemini "still resulted in visible seams"; a tile-generator vendor recommends adding "seamlessly tileable, no visible seams" and checking with an offset filter; a Gemini CLI extension (`gemini-cli-extensions/nanobanana`) has a `/pattern` command for seamless patterns with a tile-size option — [sorceress.games](https://sorceress.games/blog/ai-tileset-generator-game-ready-tilesets-from-a-prompt); [GitHub gemini-cli-extensions/nanobanana](https://github.com/gemini-cli-extensions/nanobanana); a Medium post titled "Nano Banana can't make repeat patterns, but the mockups are pretty good" (403 on fetch; title only) — [medium.com](https://medium.com/@emma.p.mantel/nano-banana-cant-make-repeat-patterns-but-the-mockups-are-pretty-good-036d24f68b6b)
- A community project, `seezatnap/nano-banana-infinimap`, generates tiled maps with Nano Banana (not inspected in detail) — [GitHub](https://github.com/seezatnap/nano-banana-infinimap)
- Google's own doc has no pixel-art, sprite, tile or seamless-texture section; the closest is the "Stylized illustrations & stickers" template ("bold, clean outlines, simple cel-shading ... The background must be white") — [Gemini API: Image generation](https://ai.google.dev/gemini-api/docs/image-generation)

### Inferences
- A 1K 1:1 render is a natural 16x upscale of a 64x64 tile or 32x of a 32x32 tile; for a Stardew-like 16x16 tile grid, generating a 4x4-tile block (64x64 logical) at 1024x1024 and snapping is the obvious unit. The grid detection must be done in your own code (autocorrelation of edge positions, or a fixed assumed scale plus median downsampling) since Google provides nothing.
- Generating at 2K/4K adds tokens (2.1: 1,680 / 3,780 output tokens) without a clear benefit for pixel art, since the logical grid is still fuzzy; 1K is the cost-efficient default.

### Gaps
- No measured success rate for grid snapping or tiling from any source; all reports are qualitative.
- No evidence whether 512px output on 3.1 Flash Image produces a cleaner grid than 1K downsampled.

## Access: Gemini API vs Vertex/Agent Platform, Node SDK, rate limits, batch, SynthID, safety

### Takeaway
Both the Gemini API (API key, `generativelanguage.googleapis.com`) and the Agent Platform (Google Cloud project, `enterprise: true` in the SDK) serve the same model IDs through `@google/genai`; the Gemini docs now lead with the Interactions API (`ai.interactions.create`) while the Batch API docs still use `generateContent`-style requests with `responseModalities`. Rate limits per model are only shown in AI Studio; batch is half price with up to 24 h turnaround; every image carries a SynthID watermark (and C2PA on Agent Platform); safety blocks surface as finish reasons/400 errors and violence is a filtered category, with no documented game-art carve-out.

### Cited Findings
- SDK: `npm install @google/genai`, Node 20+; pin `< 3.0.0` (3.0 will require Node 22); Gemini API init `new GoogleGenAI({apiKey})` or env `GOOGLE_API_KEY`; Agent Platform init `new GoogleGenAI({enterprise: true, project, location})` or env `GOOGLE_GENAI_USE_ENTERPRISE`, `GOOGLE_CLOUD_PROJECT`, `GOOGLE_CLOUD_LOCATION`; default API version is beta, `apiVersion: 'v1'` for stable — [js-genai README](https://github.com/googleapis/js-genai/blob/main/README.md)
- Interactions API (current docs): `POST https://generativelanguage.googleapis.com/v1beta/interactions` with header `x-goog-api-key`; JS: `ai.interactions.create({ model, input, response_format: { type: "image", mime_type: "image/png", aspect_ratio: "1:1", image_size: "1K" }, generation_config: { thinking_level } })`; read results by iterating `interaction.steps` -> `step.type === "model_output"` -> `content_block.type === "image"` -> base64 `data` (docs warn convenience properties miss some parts, so iterate `steps`); tools: `[{type: "google_search", search_types: ["web_search","image_search"]}]`; continue edits with `previous_interaction_id` — [Gemini API: Image generation](https://ai.google.dev/gemini-api/docs/image-generation)
- Batch: "asynchronously at 50% of the standard cost. The target turnaround time is 24 hours"; "Generating images in batch ... higher rate limits in exchange for a turnaround of up to 24 hours"; JSONL input recommended for large batches; the JS example uses `config: { responseModalities: ['TEXT','IMAGE'] }` with `ai.batches.create({ model: 'gemini-3-pro-image-preview', ... })` and reads `part.inlineData.mimeType` (older generateContent-style shape still used there) — [Gemini API: Batch API](https://ai.google.dev/gemini-api/docs/batch-api)
- Rate limits page gives no RPM/IPM per image model; it points to AI Studio for per-model values. Batch enqueued-token caps: 3.1 Flash Image Tier1 1M / Tier2 250M / Tier3 750M; 3.1 Flash Lite Image 2M / 270M / 1B; 3 Pro Image 2M / 270M / 1B. Spend caps per 10 minutes: Tier1 $10, Tier2 $50, Tier3 $200 (429 `RESOURCE_EXHAUSTED`). Tier 1 = linked billing; Tier 2 = $100 cumulative spend + 3 days; Tier 3 = $1,000 + 30 days — [Gemini API: Rate limits](https://ai.google.dev/gemini-api/docs/rate-limits)
- Agent Platform 2.1: Provisioned Throughput, batch inference, Standard and Priority PayGo supported; "Fixed quota: Not supported"; input size limit 500 MB — [Agent Platform: Nano Banana 2.1](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/nano-banana-2-1)
- SynthID: "All generated images include a SynthID watermark" — [Gemini API: Image generation](https://ai.google.dev/gemini-api/docs/image-generation); Agent Platform adds "Content Credentials (C2PA): Supported" — [Agent Platform: Nano Banana 2.1](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/nano-banana-2-1)
- SynthID robustness: a hands-on test reported the watermark survived 300 rounds of compression/resizing and broke only after a 20% crop on top — [aichatdaily](https://www.aichatdaily.com/ai-security/google-s-synthid-watermark-survives-300-edits-fragmentation); Google's help page lists "Not enough details to watermark" (very simple content) as a reason detection can fail — [Google support: SynthID](https://support.google.com/gemini/answer/16722517). No source tested pixel art or 16x downscaling.
- Safety: configurable categories `harassment, hate_speech, sexually_explicit, dangerous_content, jailbreak`; thresholds `off, block_only_high, block_medium_and_above, block_low_and_above`; default is Off for Gemini 2.5+; blocked requests return HTTP 400 with codes `safety, jailbreak, prohibited_content, blocklist`; child-safety protections cannot be adjusted; the doc's only game reference is that for "video game dialogue, you may decide to allow more content rated as Dangerous"; the page does not say whether these settings apply to image models — [Gemini API: Safety settings](https://ai.google.dev/gemini-api/docs/safety-settings)
- Vertex image responsible-AI doc: image safety filters aim to prevent "sexually explicit, dangerous, violent, hateful, or toxic material"; blocked outputs come back with a `FinishReason` such as `IMAGE_SAFETY` or `IMAGE_PROHIBITED_CONTENT`, so an image can be blocked after generation, not only at the prompt — [Vertex: Gemini image responsible AI](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/multimodal/gemini-image-responsible-ai)
- Developer forum threads report inconsistent filter behavior on `gemini-2.5-flash-image` ("Safety Filters not working") and complaints about over-blocking on other models — [discuss.ai.google.dev thread](https://discuss.ai.google.dev/t/safety-filters-not-working-for-gemini-2-5-flash-image/108622)
- Person generation: 2.1 lists "Person generation: Supported" on Agent Platform — [Agent Platform: Nano Banana 2.1](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/nano-banana-2-1)

### Inferences
- For a headless pipeline: use the Gemini API with an API key for simplicity, or the Agent Platform if you want indemnification (see licensing) and C2PA; the model IDs and `@google/genai` calls are the same. Use Batch for bulk asset runs (half price); use the online API for iterative edits.
- A cartoon "thug" with a knife or club is plausibly filterable under violent/dangerous content, with probability-based blocking; the practical mitigation is stylized wording ("cartoon", "chibi", "wooden club") and checking finish reasons. No source confirms a specific outcome for that prompt.

### Gaps
- Exact RPM/IPM per tier for image models (only visible in AI Studio after login).
- Whether `safety_settings` are honored by the Nano Banana models in the Interactions API is not documented.
- Whether SynthID survives nearest-neighbor downscale to 32x32 is untested anywhere I found; it almost certainly does not matter for shipping assets, but it also means the watermark provides no protection after your pipeline.

## Licensing, ownership, indemnification, copyright

### Takeaway
Gemini API terms: Google "won't claim ownership" of generated output, you bear all responsibility, paid-tier prompts are not used for training, and there is no IP indemnity. The Google Cloud/Agent Platform API carries Google's generated-output indemnity for GA Gemini and Imagen models. Under the US Copyright Office's January 2025 Part 2 report (reaffirmed by Thaler cert denial March 2026, Allen still pending), purely prompt-generated sprites are not copyrightable; human-modified assets and the game as a whole can be.

### Cited Findings
- Gemini API Additional Terms (effective March 23, 2026; page updated 2026-04-28): "Google won't claim ownership over that content"; Google "may generate the same or similar content for others and that we reserve all rights to do so"; you are responsible "for your use of generated content, and for the use of that content by anyone you share it with"; services are for "professional or business purposes, not for consumer use"; no indemnification clause; Unpaid Services content is used to "provide, improve, and develop" Google products with human review; Paid Services: "Google doesn't use your prompts ... or responses to improve our products", logs kept "for a limited period" for abuse detection — [Gemini API Additional Terms](https://ai.google.dev/gemini-api/terms)
- Google Cloud "Generative AI Indemnified Services" (last modified July 20, 2026): "Gemini Enterprise Agent Platform API (formerly Vertex AI API) used with generally available versions of these foundation models: Codey, Gemini, Imagen, PaLM, Veo" are "covered by the Additional Google Indemnification Obligations in the Service Specific Terms"; the page lists only Cloud and Workspace products, not the Gemini API / AI Studio — [Google Cloud indemnified services](https://cloud.google.com/terms/generative-ai-indemnified-services)
- A secondary comparison table lists IP indemnification as "No" for the Gemini API and "Yes" for Vertex AI (Enterprise) — [terms.law](https://www.terms.law/ai-output-rights/gemini/) (secondary; consistent with the primary pages above)
- Uploaded reference images: the image doc says uploaded images require rights clearance and points to the Prohibited Use Policy — [Gemini API: Image generation](https://ai.google.dev/gemini-api/docs/image-generation)
- US Copyright Office, Part 2 (January 29, 2025): copyright "protects the original expression in a work created by a human author, but does not extend to works or portions of works where a human had insufficient control over the expressive elements"; prompts alone are not sufficient to make a human the author; the Office is "more open to cases where a human-created work was inputted into the AI system to be modified, as well as situations where AI-generated works were subsequently modified by human beings" — [Akin Gump summary](https://www.akingump.com/en/insights/ai-law-and-regulation-tracker/us-copyright-office-releases-part-2-of-ai-report); [Ballard Spahr alert](https://www.ballardspahr.com/insights/alerts-and-articles/2025/01/copyright-office-issues-report-on-copyrightability-of-ai-content)
- Thaler v. Perlmutter: the Supreme Court denied certiorari on March 2, 2026, leaving the D.C. Circuit's human-authorship requirement in place — [Baker Donelson](https://www.bakerdonelson.com/supreme-court-denies-certiorari-in-thaler-v-perlmutter-ai-cannot-be-an-author-under-the-copyright-act)
- Allen v. Perlmutter (D. Colo., 1:24-cv-2665, Midjourney image with 600+ prompts): summary-judgment briefing completed January 2026; the Copyright Office argues the prompts "amounted to ideas, not creative control"; no ruling found as of this search — [artificialinventor.com](https://artificialinventor.com/?p=1661); [Law360](https://www.law360.com/technology/articles/2432068)
- No 2026 update to Part 2 was found; the one result dated August 2026 restates the 2025 report — [getcoai.com](https://getcoai.com/?p=50057) (unreliable date)

### Inferences
- Practical reading for a game: raw Nano Banana sprites are unprotectable in the US; the selection/arrangement (tileset layout, the game) and any hand-edited pixels are. If protection of individual assets matters, keep records of human cleanup (grid snapping alone is probably mechanical; hand repainting is not). This is an inference, not legal advice.
- If indemnity matters, call the same models through the Agent Platform with a Cloud project rather than an AI Studio API key; only GA model versions qualify, so avoid any `-preview` ID.

### Gaps
- The Service Specific Terms text with the indemnity conditions (e.g., whether disabling safety filters or using SynthID-stripped output voids it) was not fetched; only the covered-services list was verified.
- Whether the indemnity covers "preview"-era outputs generated before a model went GA: not determined.

## Developer reports on game assets with Gemini/Imagen

### Takeaway
The only detailed primary write-up found is Ben Hoyle's March 2026 Nano Banana Pro sprite pipeline (chroma key, white outline, content-aware slicing, trim and resize, half a day for ~74 sprites); vendor blogs (SpriteCook, sorceress.games, Promptyze, Medium tutorials) agree on the themes: style holds, grids and transparency do not, and every asset needs post-processing.

### Cited Findings
- Ben Hoyle (roboticape, 2026-03-07): time budget for ~48 clothing + 26 character sprites: prompt writing 30-60 min, 5-10 min per sheet generation with 1-2 regenerations typical, pipeline under 1 minute, manual QA 30-60 min, "roughly half a day"; key prompt lines: "EXACT hex #00FF00 (RGB 0, 255, 0)" with no gradients/noise/shadows, "Add a clean white outline/border 2-3 pixels wide around every sprite in every frame", "Keep identical scale across all frames. Add 4px padding between frames", no green in sprites, no text; "the white outline instruction [was] the most important single line"; clothing generated in neutral grey `#CCCCCC` and tinted in Python because runtime `mix-blend-mode: multiply` looked washed out — [roboticape.com](https://roboticape.com/2026/03/07/generating-game-sprites-with-gemini-image-generation-nano-banana-pro-lessons-learned/)
- Medium tutorial: a full match-3 asset set with Nano Banana Pro plus a sprite-sheet splitter (ImageSplitter.ai) — [medium.com/@moflash](https://medium.com/@moflash/tutorial-zero-to-pro-create-a-full-set-of-match-3-game-assets-with-nano-banana-pro-57ddc1b0d989) (not fetched in detail)
- Prompt guide for top-down: use "top-down orthographic" rather than "isometric", specify tile boundaries, sample prompt with "64x64 tile scale and a limited palette" — [nanoprompts.org](https://nanoprompts.org/lab/2025/game-asset-design-guide); Promptyze pixel-art guide for Nano Banana 2 — [promptyze.com](https://promptyze.com/how-to-create-pixel-art-with-nano-banana-2-gemini-flash-image/)

### Inferences
- A Node pipeline that reproduces Hoyle's steps with `sharp` (chroma key via raw pixel access, bbox trim, connected-component slicing, nearest-neighbor downscale, optional palette quantization) covers everything these reports needed; none of it requires a GPU.

### Gaps
- No Reddit or X threads with before/after sets for 8-direction walk cycles or four-season building variants were found; evidence on multi-direction consistency is thin and anecdotal.
- No independent benchmark comparing 2.1 vs Pro vs Lite on sprite consistency; only vendor assertions.
