# Living-world NPCs in shipped games: schedules, needs, relationships, simulation

Researched October 2026. Scope: what shipped games actually built for NPC daily life, how it works technically, and what developers and modders say worked or failed. Engines/frameworks and LLM-driven NPCs are out of scope (covered by other researchers). Source dates are given inline where known. Several primary pages (UESP Creation Kit wiki, Game Developer archives of some AI and Games articles, fandom wikis, GDC Vault recordings) were behind 403/paywalls during this research; where only a search snippet or secondary summary was available, that is stated.

## Stardew Valley: how NPC schedules, dialogue and events are authored

### Takeaway
Stardew's "living world" is almost entirely authored data: per-NPC schedule files keyed by a fixed priority list of conditions (festival > date > rain > season+weekday+hearts > weekday > season > `spring` fallback), dialogue files keyed by an analogous priority ladder, and events gated by slash-delimited preconditions. There is no needs model or utility AI; the "soap opera" is the authored key space plus friendship points and flags.

### Cited Findings
- Schedules live in `Content/Characters/schedules/*.xnb`, one file per NPC. Each schedule value is a slash-delimited script of points: `<time> [location] <tileX> <tileY> [facingDirection] [animation] [dialogue]`. Time is 24h military with no colon; an `a` prefix means "arrive by this time" and the game back-computes departure (used in vanilla only by Emily's and Sandy's Fall 15 schedules). Facing: 0 up, 1 right, 2 down, 3 left. Animation must match a key in `Data/animationDescriptions`. Dialogue is `"assetName:key"`; putting `marriage` in the key restricts the line to the spouse. — [Stardew Valley Wiki, Modding:Schedule data](https://stardewvalleywiki.com/Modding:Schedule_data)
- Schedule key priority (first match wins). Special: `GreenRain`. Married NPCs ignore normal keys and use only `marriage_<festival>_<day>`, `marriage_<festival>`, `marriage_<season>_<day>`, `marriageJob` (base game: Harvey, Maru, Penny only), `marriage_<dayOfWeek>` (not on rain). Normal order: `<festival>_<day>`, `<festival>`, `<season>_<dayOfMonth>`, `<dayOfMonth>_<hearts>`, `<dayOfMonth>`, `bus` (Pam, after bus repaired), `rain2` (50% chance on rainy days), `rain`, `<season>_<dayOfWeek>_<hearts>`, `<season>_<dayOfWeek>`, `<dayOfWeek>_<hearts>`, `<dayOfWeek>`, `<season>`, `spring_<dayOfWeek>`, `spring` (required; "DO NOT REMOVE THIS ENTRY. THAT WILL BREAK THE GAME."), `default` (optional). Heart keys use the highest matching threshold and are satisfied if *any* player has that friendship level. — [Modding:Schedule data](https://stardewvalleywiki.com/Modding:Schedule_data)
- Conditional commands inside a schedule: initial `GOTO <key>` (with `season` substituted); `NOT friendship <npc> <hearts>` ends the script and falls back to spring if any player has that many hearts; `MAIL <letterID>` runs the next command only if the player has *not* received the mail/world-state flag (example: `MAIL ccVault/GOTO spring/GOTO summer`); `GOTO NO_SCHEDULE` means no schedule today. A missing non-initial GOTO target crashes the game (or errors under SMAPI). — [Modding:Schedule data](https://stardewvalleywiki.com/Modding:Schedule_data)
- Exceptions for unreachable places are hard-coded: JojaMart/Railroad when locked use `<location>_Replacement`; CommunityCenter when locked falls to default/spring; `bed` as a location sends the NPC home (married NPCs go to the Farm via the Bus Stop). The wiki does not document the pathfinding algorithm. Quirks: NPCs added to an existing save usually do not follow their schedule until the player sleeps once; a `600` start time may leave an NPC stationary (use `610`). — [Modding:Schedule data](https://stardewvalleywiki.com/Modding:Schedule_data)
- Dialogue lookup order: event dialogue > location-specific strings > the NPC's `Characters\Dialogue` file > hardcoded fallback "Hi." (`NPC.cs.4061`). Within the NPC file: special keys, gift keys, festival keys, location keys, then generic keys. Generic precedence: `<season>_<key>_inlaw_<spouse>` > `<season>_<key>` > `<key>_inlaw_<spouse>` > `<key>`. Key formats include `<dayOfMonth>` (year 1 only; a documented trap), `<dayOfMonth>_1`/`_2`/`_*`, `<dayOfWeek><hearts>` (hearts checked 10, 8, 6, 4, 2), `<location>_<x>_<y>`, `<location><hearts>`. Rain dialogue has ~50% chance when nothing more specific matches. — [Stardew Valley Wiki, Modding:Dialogue](https://stardewvalleywiki.com/Modding:Dialogue)
- Dialogue commands that encode state: `$c <prob>#a#b` random branch; `$d <state>#a|b` for world states `bus`, `joja`, `cc`, `kent`; `$p <responseID>#match|nomatch` branches on earlier answers; `$q <responseIDs> <fallback>#text` asks a question, skipped if any listed ID already answered; `$r <responseID> <friendship> <reaction>#answer` records an answer and applies friendship delta; `$t <topicID> [days]` adds a conversation topic (default 4 days) and the game auto-creates `<key>_memory_<time>` topics at 1, 7, 14, 28, 56 and 104 days later, each lasting 4 days; `$v <eventID>` starts an event; `%revealtaste:<NPC>:<item>`. Response IDs are shared across questions. — [Modding:Dialogue](https://stardewvalleywiki.com/Modding:Dialogue)
- Marriage dialogue is a separate file (`MarriageDialogue.xnb` or `MarriageDialogue<Name>.xnb`) keyed by situation (`patio_<spouse>`, `Rainy_Night_<random>`, `funLeave_`, `jobLeave_`, `OneKid_<random>`, `NoBed_<random>`) and by affection tier: `<affection>_<random>` where Good lines have 50% chance at 10 hearts, 87.5% at 11, 99.4% at 12+. — [Modding:Dialogue](https://stardewvalleywiki.com/Modding:Dialogue)
- Events are in `Data/Events/<Location>` keyed `<eventID>/<preconditions>`; preconditions are slash-delimited and negatable with `!`: `Time 1900 2300` (clock runs 600–2600), `DayOfWeek`, `Season`, `Friendship Clint 750 Abigail 500` (250 points per heart), `Dating`, `Spouse`, `Weather`, `Year`, `HasMoney`, `HasItem`, `Skill`, `LocalMail`/`HostMail`, `SawEvent`, `ChoseDialogueAnswers`, `WorldState`, `Random 0.2`, `GameStateQuery`. The script's first three commands are mandatory (music, camera, actor placements), then commands like `speak`, `move`, `question fork<N>`/`fork <eventID>`, `friendship <NPC> <amount>`, `mailReceived`, `eventSeen <id> false` (to make an event repeatable). — [Stardew Valley Wiki, Modding:Event data](https://stardewvalleywiki.com/Modding:Event_data)
- Friendship numbers: 250 points per heart; 10 hearts for most villagers, 14 for spouse/roommate. Talking +20/day once per villager. Daily decay when not talked to: married −20/day (never stops), bouquet-given −10/day (stops at 10 hearts), non-romanceable −2/day (stops at 10 hearts), pre-bouquet candidate −2/day (stops at 8 hearts). Gifts: Love +80, Like +45, Neutral +20, Dislike −20, Hate −40; birthday ×8; Winter Star secret gift ×5; quality bonus only on liked/loved gifts (silver ×1.1, gold ×1.25, iridium ×1.5). Two gifts per week; one per day. Slingshot hit −30; rummaging a garbage can within 7 tiles of a villager −25 (Linus +5). Candidates cap at 8 hearts until given a bouquet; proposal with Mermaid's Pendant at 10 hearts. Largest event-driven swings: Linus 8-heart +250, Penny 8/10-heart events −1,500. — [Stardew Valley Wiki, Friendship](https://stardewvalleywiki.com/Friendship)
- A 2025 design essay uses Stardew as the exemplar: Sebastian's weekday/rain/Friday-saloon routine, pre-existing NPC webs (Sam/Sebastian/Abigail band, Penny/Pam tension, Pierre/Caroline marriage) that the player joins rather than creates, routines discovered by observation rather than explained, and roughly 10–15 rotating lines per context. The author notes these are his descriptions, not verified internals. — [Rafiul Alam, "NPCs with Lives Beyond You", 2025-03-04](https://alamrafiul.com/blogs/npcs-lives-beyond-you/)
- The modding community has built an in-game schedule editor ("NPC Scheduler") that adjusts routines by season, date and friendship conditions, confirming those three are the practical axes of variation. — [Nexus Mods, NPC Scheduler](https://nexusmods.com/stardewvalley/mods/31494)
- ConcernedApe said there are no plans to add "home-wrecking" of married NPCs; the game's core sentiment is peaceful daily routines. — [Inven Global reporting a Game Informer interview](https://www.invenglobal.com/articles/21887/stardew-valley-no-plans-to-introduce-home-wrecking-for-married-npcs)

### Inferences
- Stardew's exceptions model is "most-specific key wins, then explicit fallbacks," not interruption handling. An NPC cannot be diverted mid-day by a world event; the authoring unit is "a whole day for a whole condition." The soap-opera feel comes from heart-gated keys and `$t`/`_memory_` topics that let dialogue reference something that happened days ago.
- The cost center is combinatorial authoring: season × weekday × hearts × rain × marriage × festival, each a hand-written path. The `spring` fallback and the "year-1-only `<dayOfMonth>` key" trap show how fragile key-ladder designs are without tooling.

### Gaps
- The wiki does not document the pathfinding or what happens when a route is blocked mid-walk (e.g., player standing in a doorway); I found no developer statement on this.
- No developer talk or interview from ConcernedApe describing the schedule system's design rationale surfaced in search.

## Ultima VI and VII: hour-based schedules and the Exult reconstruction

### Takeaway
Ultima VII's schedules are a 4-byte record per entry: a 5-bit activity type (32 types: Sleep, Eat, Tend Shop, Blacksmith, Patrol, Preach, Thief, Waiter, etc.), a 3-bit time slot (eight 3-hour blocks), and a world location; each NPC has 1–8 entries, and scripted exceptions live in usecode and "eggs," not in the schedule file. The era's lesson, per Ultima fans and Exult developers, is that class-based routine templates plus a work/home cycle deliver most of the believability, and that multi-floor pathing (no Z in schedules) was a persistent flaw.

### Cited Findings
- `STATIC\SCHEDULE.DAT` format: header with NPC count (256 in both Black Gate and Serpent Isle) and per-NPC schedule counts; each schedule is 4 bytes: schedule-number+match-time byte, X and Y within a SuperChunk, SuperChunk number (SuperChunk = (RealY/256)×12 + RealX/256). The schedule/time byte packs 5 bits of schedule type (bits 7–3) and 3 bits of time (bits 2–0) mapping to 0 AM, 3 AM, 6 AM, 9 AM, 0 PM, 3 PM, 6 PM, 9 PM. "Eight is the max amount for one NPC"; each NPC needs at least one; the Avatar has none. — [Ultima Codex, Ultima VII internal formats – SCHEDULE.DAT](https://www.wiki.ultimacodex.com/wiki/Ultima_VII_internal_formats_%E2%80%93_SCHEDULE.DAT)
- The 32 schedule types (0–31): Combat, Horizontal Pace, Vertical Pace, Talk, Dance, Eat, Farm, Tend Shop, Miner, Hound, Stand, Loiter, Wander, Blacksmith, Sleep, Wait, Major Sit, Graze, Bake, Sew, Shy, Lab, Thief, Waiter, Special, Kid Games, Eat at Inn, Duel, Preach, Patrol, Desk Work, Follow Avatar. — [SCHEDULE.DAT page](https://www.wiki.ultimacodex.com/wiki/Ultima_VII_internal_formats_%E2%80%93_SCHEDULE.DAT)
- An Exult developer states NPCs update their schedule hourly, and the `run_schedule` intrinsic can force a change sooner. — [Exult forum](https://exult.sourceforge.io/forum/viewtopic.php?p=313646)
- The schedules editable in Exult Studio are defined in the engine; changing how an NPC stands or animates during a schedule means editing usecode with a proximity check. Usecode does not run on a timer; it runs on events (double-click, scripted calls, some schedules' proximity triggers), with "eggs" handling other conditions. — [Exult forum: Schedule Locations](https://exult.sourceforge.io/forum/viewtopic.php?p=19179); [Exult forum: Usecode events](https://exult.sourceforge.io/forum/viewtopic.php?p=331616)
- Known limits reported on the Exult forum: the Z coordinate cannot be set through schedules, making stairs and multi-floor routines hard; scripted openings override schedules (Trinsic's mayor leaves his scheduled spot during the Black Gate intro) and the user could not find where such exceptions are stored; the Forge of Virtue and Silver Seed add-on NPCs are not regular NPCs and have no schedules. — [Exult forum: Schedule Locations](https://exult.sourceforge.io/forum/viewtopic.php?p=19195)
- Nuvie (the Ultima VI engine reimplementation, now in ScummVM) models a U6 schedule entry with fields x, y, z, hour, day_of_week, worktype. — [ScummVM API docs, Nuvie Schedule struct](https://doxygen.scummvm.org/d7/deb/struct_ultima_1_1_nuvie_1_1_schedule.html). A 2003 Nuvie progress report says the team had listed most worktype codes in the U6 schedule file, with some temporary worktypes still unknown. — [RPG Codex, Nuvie progress report](https://rpgcodex.net/article.php?id=1431). The Ultima Codex U6 internal-formats page lists `schedule` among the game files but marks it unknown. — [Ultima VI Internal Formats](https://wiki.ultimacodex.com/wiki/Ultima_VI_Internal_Formats)
- A design essay on the Ultima Codex Lycaeum (Browncoat Jayson, 2011, updated 2014) says schedules began in Ultima V and peaked in VII/Serpent Isle (a blacksmith who sleeps, eats, works, lunches at a tavern, goes home; a farmer who tends animals and crops on a route). Ultima IV had no schedules and is still rated among the best CRPGs; Ultima IX dropped them and was received worse. Recommendations: at minimum move each NPC between work and home on a day/night cycle; build routines for classes of NPCs (all shopkeepers) and layer a few unique traits; keep NPCs findable about 14 of 24 hours; let idle routines still accept interaction. His "Game C" tavern owner (cleans, serves, closes up, banks on Saturdays, visits his wife's grave Sundays) is called too specific to scale: it "would lead to very crowded cemeteries." — [The Digital Lycaeum, "Ultima Game Developer: NPC Schedules"](https://lycaeum.ultimacodex.com/npc-schedules/)

### Inferences
- The U7 model is "activity type + location + 3-hour slot," with the engine owning what each activity *means* (where to path within the location, which animations). This is the opposite of Stardew's tile-by-tile authoring: cheap to author, but every new activity needs engine code.
- Exceptions (quest states, intro scripts) living outside the schedule file is the pattern every later game repeats: a base routine plus an override layer, with the override layer being the hard part to find and debug.

### Gaps
- I could not retrieve the actual Ultima VI schedule byte layout (the Ultima Codex page is unmarked; Nuvie's loader source would be the primary reference).
- No Origin-era developer postmortem on U7 schedules surfaced; the "what people loved" evidence is community commentary.

## The Sims (1–4): motives, advertising objects, utility selection, traits, memories

### Takeaway
The Sims' architecture is "smart objects advertise satisfaction of motives; the Sim scores advertisements against its current motive levels (and, later, traits) and picks the best." Maxis designers have repeatedly said the AI is deliberately shallow ("Big A, little i"), that randomness beat a detailed urinal-choice model, and that players supply the story; Sims 3 moved toward explicit traits and story progression, and Sims 4 toward emotions as the central state.

### Cited Findings
- Will Wright's own account (as summarized in a video-essay transcript surfaced by search; the full transcript was 403 for me): every object broadcasts an "advertisement" in a motive "flavor," and the Sim picks the object that best fits its state; the stated benefit was adding new objects later "without the Sims having any foreknowledge of what the objects were." Scores are weighted by current motive level: a rested Sim discounts a bed's energy advertisement, an exhausted one boosts it. SimAnt's pheromone model is cited as the direct precursor; the AI drew on Christopher Alexander's *A Pattern Language*, Maslow's hierarchy of needs and Hampden-Turner's *Maps of the Mind*. — [AI and Games, "The Genius AI Behind The Sims" transcript (search snippet)](https://amara.org/subtitles/cVoJS4OdmVql/en/1/download/The%20Genius%20AI%20Behind%20The%20Sims.en.txt); Alexander influence also in [Wikipedia, The Sims](https://en.wikipedia.org/wiki/The_Sims_(video_game))
- Wright's 2002 guest-lecture outline (Northwestern CS 395, Forbus's course): interaction types are Normal (~90%), Advertised (autonomous), Manual (player-selected), Pushed (high priority, immediate: Carpool, Fire), Functional (goal-oriented, driven by outside needs: Clean, Repair, Cook). Invisible objects include Social Interactions, Job, Phone Line, Visitor Generator, Burglar Portal, Sickness. Objects are programmed in EDITH, a visual language. Room score is a baseline from size, lighting, windows, doors, minus trash/broken/dirty objects, plus art/fireplace/wallpaper/flooring. Routing is A* in two modes: room-to-room over a Room Map, then within-room over variable-resolution quadtrees. Design requirements listed: graceful failure, user-definable environments, understandable to players, expandable through code, drop-in components, eventually end-user programmable. — [Forbus course outline, "Under the hood of The Sims"](https://users.cs.northwestern.edu/~forbus/c95-gd/lectures/The_Sims_Under_the_Hood_files/outline.htm)
- Sims 1 object categories: seating, surfaces, decorations, electronics, appliances, plumbing, lighting, miscellaneous. Sims cannot autonomously pay bills, find a job, exercise or conceive. The design began as an architecture simulator in which Sims existed to evaluate houses. After the 1999 E3 demo, relationship mechanics were changed so a character's orientation depends on player actions. — [Wikipedia, The Sims](https://en.wikipedia.org/wiki/The_Sims_(video_game))
- The academic "smart object" concept (Kallmann and Thalmann) predates The Sims; a 2015 paper by Warhorse/Charles University authors says The Sims implemented a version close to Kallmann's. — [Černý et al., arXiv 1508.00377](https://arxiv.org/pdf/1508.00377)
- Sims 2 (per Matt Brown of EA/Maxis, AIIDE 2006, notes by Mark J. Nelson): the design is "Big A, little i" (seem intelligent rather than be intelligent); local coherence is enough and players supply long-term story. Story trees are short hand-authored fragments; events are matched against all tree prefixes, and the next event is scored against a model of player interest and NPC personality. Authoring tools mattered more than the AI. Lessons: a detailed model of which urinal a Sim would pick did not reliably produce the behavior, and a random number generator made players equally willing to invent stories; randomness reduces brittleness and exploitability; players forget quickly, so long memory is unnecessary; hidden complex computation often reads as randomness, so it may not be worth building. Nelson adds that Sims 3 under Richard Evans moved away from this minimalism toward longer-term planning. — [kmjn.org notes on Matt Brown's AIIDE 2006 talk](https://kmjn.org/notes/sims2_ai.html)
- Sims 2 systems: eight lifetime aspirations (Grow Up, Romance, Family, Knowledge, Popularity, Fortune, Pleasure, Grilled Cheese) that "strongly influence their Wants and Fears"; personality is 25 points across five paired axes (sloppy/neat, shy/outgoing, lazy/active, serious/playful, grouchy/nice) with twelve zodiac presets; social interactions can create memories; *Nightlife* chemistry (up to three lightning bolts) from turn-ons/offs, aspiration and personality raises acceptance of social interactions; "Sims with certain personalities may not want to complete certain social interactions." — [Wikipedia, The Sims 2](https://en.wikipedia.org/wiki/The_Sims_2)
- Sims 3: up to five traits per adult Sim (mental/physical/social/lifestyle/job categories) shaping actions and wishes; wishes replace Wants and Fears and feed Lifetime Happiness; Story Progression lets every Sim in the neighborhood keep living autonomously when not controlled; seamless open world. — [Wikipedia, The Sims 3](https://en.wikipedia.org/wiki/The_Sims_3)
- Richard Evans's GDC 2010 talk "Modeling Individual Personalities in The Sims 3" (abstract only; Vault login-walled): goal was for each Sim to have an individual personality "clearly manifest in autonomous behavior," with a fine-grained socializing model and a data-driven social system letting designers specify hundreds of interactions and thousands of production rules. — [GDC Vault listing](https://gdcvault.com/play/1012294/Modeling-Individual-Personalities-in-The). Evans's 2011 paper describes the Sims 3 trait system and proposes representing traits as conditionals from world state to emotional state instead. — [Evans, "Representing Personality Traits as Conditionals"](https://philarchive.org/rec/EVARPT). A pre-release preview says Sims 3 traits "just add more motives to the pile rather than weighting scores against personality." — [Neoteo preview](https://www.neoteo.com/en/the-sims-3-preview-smarter-sims-ai-leap)
- Sims 4: Maxis put emotions and personality "front and center"; each Sim's trait and emotion combination drives specific actions and animations; sadness is designed as an option that opens possibilities rather than a penalty (Grant Rodiek); emotional state affects performance and changes gradually (Rachel Franklin). — [Game Developer, "The art of injecting emotion into The Sims 4"](https://www.gamedeveloper.com/design/the-art-of-injecting-emotion-into-i-the-sims-4-i-); [Shacknews](https://shacknews.com/article/80862/how-the-sims-4-is-aiming-for-more-subtle-sim); [Softpedia](https://games.softpedia.com/blog/Maxis-The-Sims-4-Does-Not-Treat-Sadness-as-a-Negative-Emotion-382467.shtml). A fan-forum thread criticizes the shipped system as volatile, weak in consequence and prone to overriding personality, and proposes linking emotions to decaying memories (a user suggestion, not official). — [EA forums thread](https://forums.thesims.com/En_US/discussion/1013694/dear-sims-team-for-better-emotion-system-link-them-to-memories)

### Inferences
- The advertising model is the clearest reusable pattern for a Stardew-like: it decouples "what can be done here" (data on places/objects) from "who wants it" (per-NPC state), and it is what Warhorse later generalized as smart objects/areas (see KCD).
- Maxis's own lessons cut against deep simulation for the sake of it: perceived personality (names, a few legible traits, a little randomness) carried more than hidden models. Sims 3/4 then re-added depth (traits, story progression, emotions) and attracted criticism for emotion volatility overriding personality, which suggests the hard problem is persistence and legibility of state, not quantity of state.

### Gaps
- I could not retrieve a primary table of Sims 1 motives or the exact scoring formula (fandom wiki and transcript blocked). The Forbus outline is slides only.
- No Sims 2 primary documentation on the memory/gossip propagation mechanics was reachable.

## Oblivion's Radiant AI and Skyrim: what was promised, what shipped, the package system

### Takeaway
Radiant AI shipped as a cascading list of AI *packages* (sleep, eat, travel, sandbox, etc.) with hour-block schedules and conditions, evaluated top-down each time an actor needs a new package. The emergent chaos of pre-release (addicts killing a skooma dealer; NPCs abandoning quests) was deliberately damped, Emil Pagliarulo said, because it "breaks stuff"; Bruce Nesmith later said realistic reactions are not automatically good design, that Skyrim's deeper version is *less* noticeable because it is smoother, and that the investment is "enormous."

### Cited Findings
- Pre-release pitch (E3 2005 coverage): NPCs have no fixed scripts; each gets a goal and chooses its own way to reach it; a villager heading to work might take their own route, chat with other villagers or the player, or stay in bed. — [RPGFan E3 2005](https://classic.rpgfan.com/news/2005/1502.html). Wikipedia's summary of 2005 interviews: NPCs receive broad goals such as "Eat in this location at 2pm" and decide how; Howard called the result an "organic feel" and said lack of individual scripting enabled a larger world. — [Wikipedia, Radiant AI](https://en.wikipedia.org/wiki/Radiant_AI)
- Most E3 demo content was later deleted; an early Chorrol demo opened with an NPC-to-NPC conversation cut from the final game. — [UESP, Oblivion:E3 demo quest](https://uesp.net/wiki/Oblivion:E3_demo_quest)
- Emil Pagliarulo (quoted in a 2010 GamesBeat essay): the AI sometimes "screws up our quests" and some behavior "breaks stuff"; during testing a Dark Brotherhood quest's skooma merchant was found dead because addicts from a local den killed him for his supply; NPCs behaved like Sims with a taste for murder and theft; the developers consciously reduced the most disruptive behaviors, mostly destruction and theft, which had caused mass killings and blocked gameplay. Each NPC had a simple personality of scaled values that could change, plus dispositions toward the player and each other. The essay author's claim that Bethesda could have shipped the earlier settings is opinion. — [GamesBeat, "Dimming the Radiant AI in Oblivion", 2010-12-17](https://gamesbeat.com/dimming-the-radiant-ai-in-oblivion/)
- Forum recollections (not primary): NPCs became too violent when daily tasks conflicted and there was no time to fix it before the Xbox 360 port problems; much dynamic behavior was replaced by scripts. — [gamesas forum](https://www.gamesas.com/the-radiant-oblivion-t32905.html)
- Skyrim package mechanics (Creation Kit wiki and UESP file-format docs, via search snippets; the CK wiki itself returned 403): a package's schedule "acts like another Condition in determining when and for how long a package will run" and "cannot be in less than one hour blocks"; duration is stored in minutes but shown in decimal hours; conditions attach at package level or to individual branches of the procedure tree; packages on an actor are a cascading list examined from the top, and "the first package that is found valid based on its time schedule and logical conditions is selected and activated." — [UESP CK wiki, Package (Form)](https://ck.uesp.net/wiki/Package_(Form)); [UESP, Tes5Mod PACK record format](https://en.uesp.net/wiki/Tes5Mod:Mod_File_Format/PACK)
- Modder notes: packages control where an NPC works, eats and sleeps, how it fights and how it reacts to a corpse; the "Once Per Day" flag only works if the package has neither start time nor duration, so it often looks broken; debugging packages is tedious enough that dedicated mods (More Informative Console, Package Debug Helper) exist. — [Beyond Skyrim Arcane University, NPC Packages](https://wiki.beyondskyrim.org/wiki/Arcane_University:NPC_Packages)
- Bruce Nesmith on Radiant Story (Vancouver Film School lecture, Jan 2012): the team defined ~30 player actions and world reactions (bystanders gawk at a slain dragon, people fight over a dropped item, an NPC asks for a potion after seeing alchemy); creating the new data types and attaching them to objects was "a pretty Herculean task." Cut: a vendor claiming a sold item as stolen ("you ended up always killing the guy"); using Radiant Story for the main quest ("would play horribly"); and reactions were overused at first (dropping items brought "half the town"), so conditioning limits were expanded; players did not want many generic "job quests," so job quests were restricted to NPCs where they fit (innkeepers) and custom dialogue was written per voice type. Lessons: "just because a response was reasonable in the real world, it doesn't mean it's good in a game"; "if we pass the buck to a system, it's not the same." — [GamesBeat, "Bethesda's Nesmith reflects on the difficult birth of Skyrim's Radiant Story system", 2012-01-27](https://gamesbeat.com/bethesdas-nesmith-reflects-on-the-difficult-birth-of-skyrims-radiant-story-system/). RPGamer's interview adds that early implementations were "disastrous," quests "ridiculous and tedious," and a fully procedural Companions questline was considered and dropped. — [RPGamer, Bruce Nesmith interview](https://rpgamer.com/?p=110108)
- Nesmith in October 2025: the investment in Radiant AI "is enormous," it took multiple games to get right, no other studio has built a similar system partly because of cost; Skyrim's version was more widespread and deeper (NPCs replacing killed relatives, fighting over dropped items) but smoother, so players noticed it less: "The quirkiness of Radiant AI in Oblivion is what makes it noticeable." — [FRVR blog, 2025-10-16](https://frvr.com/blog/news/elder-scrolls-designer-explains-that-radiant-ai-is-an-enormous-investment-for-bethesda-but-every-improvement-actually-makes-it-less-noticeable-to-players/)
- Skyrim's Radiant Story picks NPCs for roles by player history (for enemy roles, "the closest NPC who hates the player"; captured characters are chosen from NPCs the player previously interacted with). — [Wikipedia, Radiant AI, citing IGN 2011 and GameSpy 2012](https://en.wikipedia.org/wiki/Radiant_AI)
- GamesRadar (via inkl mirror; original 403) reports Nesmith saying Skyrim's NPC system came from a napkin drawing Todd Howard gave the team. — [inkl mirror of GamesRadar](https://www.inkl.com/news/skyrim-npcs-are-only-as-complex-as-they-are-thanks-to-a-literal-napkin-drawing-that-todd-howard-doodled-reveals-ex-bethesda-dev-it-s-actually-a-napkin-story)

### Inferences
- The shipped Radiant AI is a priority-ordered schedule/condition stack, structurally close to Stardew's key ladder but with runtime conditions and behaviours (packages) rather than tile scripts. The needs/goals layer that made the E3 demo interesting was constrained rather than removed.
- The reusable lesson is about *bounding* emergence: conflicts between goals (two NPCs want the same scarce item) are where chaos comes from; the fixes were conditioning limits and removing destructive/theft goals, not smarter planning.

### Gaps
- Primary CK documentation of procedure trees (sequence/random/simultaneous nodes) and template lists was not retrievable (403); only file-format snippets were.
- The "skooma" and "dog/sleep spell" demo anecdotes beyond Pagliarulo's quote are forum lore; I found no primary Howard interview on cut behaviors.

## Kingdom Come: Deliverance, Hitman, Watch Dogs: Legion, Shadows of Doubt, Shenmue, Majora's Mask, Gothic/Risen

### Takeaway
Large-scale living worlds converge on the same architecture: a base day-cycle per NPC, intelligence pushed into the environment (smart objects/areas or Census-style databases), a priority or subsumption layer so combat/quests override ambient life, and aggressive LOD so hundreds to thousands of NPCs persist off-screen. The recurring failure reported is bottlenecks and conflicts over shared resources (Shenmue's convenience store, KCD's beds, Hitman's crowds never calming down).

### Cited Findings
**Kingdom Come: Deliverance (Warhorse)**
- The 2015 paper by Warhorse and Charles University (Černý, Plch, Marko, Gemrot, Ondráček, Brom; arXiv Aug 2015) states the problem: non-combat NPC behavior is limited because script codebases become unmanageable, and CPU budget is tight (~5 ms per frame for all NPCs), ruling out planning for ambient behavior. Their "behavior objects" bundle behavior code, environment links/state and a "brain." Types: smart objects (chairs, doors, beds; passive, short behaviors), navigation s-objects (doors linking areas), smart areas (pubs, fields, cities) in parent-child hierarchies so a pub can defer to the city for "relax" or "pray," quest s-objects that change NPC daily routines, and "situations" (short, low-priority multi-NPC eye candy such as small talk or a pub brawl, role-based, cleaned up if any participant aborts). Behaviors are injected as behavior-tree subtrees via request nodes; subbrains are prioritized subsumption-style (ambient, combat, situations). NPCs follow daycycles; sleeping at night is kept intact for quests; every behavior must clean up on interruption and issue a movement/animation at start to avoid visual artifacts. Results: under 1 ms average with 30 complex NPCs; a scripter placed ~60 s-areas and ~200 s-objects in two days; pain points were debugging deep trees, the message system and tooling. — [Černý et al., "Using Behavior Objects to Manage Complexity in Virtual Worlds"](https://ar5iv.labs.arxiv.org/html/1508.00377)
- Lead AI developer Tomáš Plch (PC Games, April 2015, pre-release): an NPC wanting to eat knows three taverns and asks each tavern's AI whether a seat is free; if none, it records a negative experience and picks another next time; preferences develop per playthrough (a farmer who fishes in one run plays backgammon in another); quests can be driven by NPC AI (persuade an alcoholic to quit and his routine changes); a shopkeeper who recognizes a stolen item may return it, making the two NPCs friendly, affecting later greetings. Balance was the main problem: too many fixed scripts are repetitive, too much freedom frustrates players. — [PC Games interview (German), 2015-04-18](https://www.pcgames.de/Kingdom-Come-Deliverance-Spiel-16151/Specials/Kingdom-Come-Deliverance-Interview-Special-Teil-5-Kuenstlich-intelligenter-Ehebruch-und-denkende-Tueren-1156484/2/)
- GDC 2026 session (Petr Smrcek, Warhorse): "all the NPCs are doing their daily routines and reacting to player actions even when the player is long gone"; KCD II "quadruples the number of NPCs on the map to nearly 2400," requiring new AI-simulation LOD techniques. — [GDC schedule listing](https://schedule.gdconf.com/session/supporting-thousands-of-npcs-in-kingdom-come-deliverance-kingdom-come-deliverance-ii/915120). A 2018 Czech university talk by Smrcek lists scheduling, smart objects and relationships between objects, with around 600 concurrently active NPCs with jobs, homes and a daily cycle (slide titles only, per search). — [Smrcek presentation PDF](https://www.karlin.mff.cuni.cz/mffseminar/prezentace_smrcek.pdf). KCD II combines GOAP with modular behavior trees; designers "mostly specify desired outcomes rather than the steps." — [GDC Vault, Combining GOAP and MBT](https://gdcvault.com/play/1035576/Game-AI-Summit-Combining-GOAP)
- KCD II: NPCs have homes and daily business; Warhorse "ran out of beds for people in the city, so some need to leave the city by night." — [80.lv summarizing IGN](https://80.lv/articles/kingdom-come-deliverance-2-brings-reactive-world-more-ethnicities/)

**Hitman (2016) / Hitman 2 (IO Interactive)**
- Tommy Thompson's 2019 breakdown: crowd NPCs (up to 1,200 in Absolution, 2,000+ in Hitman 2) run a simple FSM (idle, walking, pending walk); 300+ behaviour-tree NPCs per level; any crowd member can be "possessed" by a behaviour-tree AI when needed. Civilians are passive but can confront or alert; guards fight; bodyguards follow VIPs. Knowledge is split into public world state and private knowledge (last-known positions, item history; characters notice missing or tampered items). Perception is sensors (immediate, breakable by line of sight) plus services (shared periodic updates: Disguise, Dead Body, Hitman last-seen). "Situations" coordinate groups (discovered body, compromised player, fleeing target; bodyguard situations Ambient VIP Escort, Escort-Search, Evacuate VIP) without direct NPC-to-NPC communication. Scale tricks: distant BT NPCs update less often with reduced animation; a 2D reasoning grid over the navmesh for walkability, security regions and sight; precomputed panic flows to exits. Limits: services update periodically so information goes stale (intended as exploitable); per Thompson's research, crowds never calm down once agitated. — [Game Developer, "The AI of Hitman (2016)", 2019-08-07](https://www.gamedeveloper.com/design/the-ai-of-hitman-2016-)
- IO's Hitman 2 scalability deck: about 1,700 default characters per level in Season 2; AI simulation continues off-screen; a pool of invisible NPCs can be upgraded from crowd agents when players interact. — [Intel-hosted IO Interactive slides (PDF too large to fully read; search snippet)](https://www.intel.com/content/dam/develop/external/us/en/documents/06-create-a-scalable-and-destructible-world-in-hitman2-807276.pdf); earlier GDC talk on 1,200-character crowds in Absolution — [GDC Vault, Crowds in Hitman](https://gdcvault.com/play/1016518/Crowds-in-Hitman)

**Watch Dogs: Legion (Ubisoft Toronto)**
- Census has two layers: a procedural generation layer assigning demographic profiles "internally consistent" with each character's role, and a simulation layer that "makes the characters persistent, and dynamically generates schedules appropriate for that character" (Christopher Dragert). Schedules are dynamic (work, then gym). Census builds relationship networks (family ties); memories and affinity propagate across them: helping one character makes relatives like the player more; hospitalizing or rescuing someone affects recruitability of their circle. Getting tagging data into the world was a major effort largely done by the Montreal team; tuning and debugging the procedural generation were ongoing. — [Ubisoft News, "The tools that built London", 2021-03-30](https://news.ubisoft.com/en-us/article/4po3S9Pwp1YcgBmGPmQxAh/watch-dogs-legion-the-tools-that-built-london)
- Clint Hocking (Nov 2019): "At the core of everything is a relational database called Census." Profiling an NPC is lazy: clothing implies job (a bin man), time of day sets the shift (noon–8pm because it is 3pm), the job sets pay, pay constrains which neighborhoods are affordable, home is picked from those, neighborhood biases hobbies; education and interests are random; backstory "narrative personas" sit on top and re-cast missions (rescue his father; his brother is held by a crime family). Voice lines were recorded by several actors and runtime-modulated. He declined to give dialogue counts: "the meaningful differences approach the infinite." — [GamingBolt, 2019-11-25](https://gamingbolt.com/watch-dogs-legion-census-system-detailed-creates-nearly-infinite-possibilities)
- GDC 2021 session description: Census "generates characters, simulates their lives, and places them into gameplay"; profiles are the basis for dynamically generated schedules "including meetings with friends, relatives, and adversaries"; the talk also covered consistency with character models, runtime performance of the relational database and large-scale tagging across content teams. — [GDC Vault, "Census: The Systemic Backbone Behind Play As Anyone"](https://gdcvault.com/play/1027018/Census-The-Systemic-Backbone-Behind)

**Shadows of Doubt (ColePowered)**
- DevBlog #8 (per search snippet; page 403): the simulation handles "100s of little citizens, all going about their daily routines"; daily schedules are computed in a short calculation before each day starts, not in real time, and citizens can change course when events call for it. — [ColePowered DevBlog #8: Simulating a City](https://colepowered.com/?p=34142). DevBlog #23 (Oct 2020) introduces a two-part video on generating each citizen's personality, aiming for characters that "aren't just window dressing." — [DevBlog #23](https://colepowered.itch.io/shadows/devlog/189689/shadows-of-doubt-devblog-23-generating-citizens-part-1). The IGF entry says citizens have 23 randomly generated traits. — [IGF 2023 entry](https://igf.com/entry/2023/shadows-doubt). The writer said the team has "many reasons" not to use generative AI to run the world because NPCs could behave unpredictably and "data integrity is extremely important." — [3DJuegos (Spanish)](https://www.3djuegos.com/juegos/shadows-of-doubt/noticias/hubo-tiempo-que-ciudad-crimen-reinaba-paz-motivo-inusual-estaba-todo-mundo-demasiado-ocupado-haciendo-pis/amp)

**Shenmue (Yu Suzuki, GDC 2014 postmortem)**
- NPCs followed daily schedules (wake, breakfast, bus to work, lunch, work, bus home). Testing found an empty warehouse district: the whole population had gone to one convenience store for breakfast at the same time and got stuck. Fix: an automatic door and a cap on store occupancy. QA recorded gameplay around the clock to find such bugs. — [Game Developer, "Yu Suzuki recounts the making of Shenmue", 2014-03-19](https://www.gamedeveloper.com/design/yu-suzuki-recounts-the-making-of-i-shenmue-i-)

**Majora's Mask (Nintendo, 2000)**
- Per Iwata Asks as summarized by Zelda Universe: the initial plan was a full week; it was cut to three days because content for a week would take too long (about a year of development), a week "was a chore to play through repeatedly," and it was hard to track "what character would be where and on which day." — [Zelda Universe, 2019-05-07](https://zeldauniverse.net/2019/05/07/zeldas-study-majoras-mask-was-originally-planned-to-have-a-weeklong-cycle/). Every NPC follows a schedule across the loop with routines varying by day; the Anju quest can only be started on day one. — [Epilogue Gaming](https://epiloguegaming.com/playing-the-narrative-majoras-mask/). The Anju & Kafei quest takes an entire three-day cycle and effectively requires multiple cycles to see everything. — [Zelda Dungeon](https://www.zeldadungeon.net/?p=106932). Miyamoto pushed for the 3DS Bombers' Notebook revamp because many players finished without finding the hidden events (Aonuma, GamesMaster, 2015). — [Cubed3](https://cubed3.com/news/23096/1/bombers-notebook-to-be-revamped-in-zelda-majoras-mask-3d.html)

**Gothic / Risen (Piranha Bytes)**
- Gothic modding: daily routines are "TA" (Tagesablauf) functions; routine names start with `Rtn_`, end with the NPC id, and `start` is the NPC's first routine; the usual advice is to copy an existing NPC script. — [World of Gothic tutorial download (German)](https://worldofgothic.de/download.php?id=1162). For Risen 2, "every NPC has a daily routine and will react to the player based on a set of rules" mirroring social norms (no stealing, no fights); sneaking into houses while residents are awake raises attention; NPCs remember fights and arguments and "admire or hate you"; the design intent is that players observe NPCs and then play along or outsmart the AI; the studio explicitly follows the Ultima tradition. — [RPG Codex reposting a GameSpot interview with Deep Silver's Daniel Oberlerchner, 2011-07-29](https://rpgcodex.net/article.php?id=7745)

### Inferences
- The three AAA systems (KCD, Hitman, Legion) all separate *who* (profile/needs/knowledge) from *where/what* (smart objects, areas, situations, Census schedule slots), and all handle interruptions with a priority stack (subsumption subbrains in KCD; situations/services in Hitman) rather than replanning. That is the practical answer to "how are exceptions handled."
- Shadows of Doubt's "precompute the day, then allow deviation" is the indie-scale version of the same idea and matches Stardew's whole-day authoring, but computed.
- Resource contention is the canonical bug class for schedule-driven populations (Shenmue's store, KCD's beds, Hitman's possessed crowd pool). Capacity limits on locations and a fallback activity are needed from day one.

### Gaps
- GDC Vault recordings (Census, Hitman 2 scalability, Warhorse 2026) are login-walled; details come from session descriptions and secondary write-ups.
- Shadows of Doubt's actual trait list, schedule representation, and how NPC killers plan were not reachable (403 on the dev blog and the Wireframe feature).
- Gothic's TA_ function syntax and the schedule interpreter were not documented in any reachable source.

## Colony and grand-strategy simulations: Dwarf Fortress, RimWorld, Crusader Kings 3

### Takeaway
These games represent personality as many numeric axes (DF: facets 0–100 on a bell curve; RimWorld: a few traits with explicit opinion/mood numbers; CK3: at most 3 personality traits plus named opinion modifiers), relationships as per-pair numbers with named thresholds (DF love 50/75/100 = friend/close friend/kindred spirit; RimWorld opinion −100..+100; CK3 modifiers like Friend +60, Rival −60), and relationship change as the sum of timed "thoughts"/modifiers from interactions. Tarn Adams' and Tynan Sylvester's stated lessons are that legibility and recognizable narrative beats, not fidelity, decide whether a system is worth adding.

### Cited Findings
**Dwarf Fortress**
- Each personality facet is 0–100; seven bands with probabilities: 91–100 (0.4%), 76–90 (2%), 61–75 (8.5%), 40–60 neutral (78%, no description shown), 25–39 (8.5%), 10–24 (2%), 0–9 (0.4%). Species shift medians (dwarves' GREED median 55; goblins' ALTRUISM median 25, capped at 50). Facets affect which social skills are learned and whether actions produce good/bad thoughts; memories can change facets over time. Facets marked † (e.g., VIOLENT, WASTEFULNESS, DISCORD, FRIENDLINESS, POLITENESS) contribute to grudges when one creature is >60 and the other <40. Concrete effects: CHEER_PROPENSITY 25–39 "will not generate a positive thought while drunk"; ANGER_PROPENSITY 91–100 makes tantrums/berserk more likely and unmet needs trigger "frustration"; STRESS_VULNERABILITY 91–100 gives 50% chance to become catatonic; DISCORD ≥91 cannot learn Consoler or Pacifier; FRIENDLINESS ≥91 "always learns Flatterer." — [Dwarf Fortress Wiki, Personality trait (v53.16)](https://dwarffortresswiki.org/index.php/Personality_trait)
- Needs: each creature's set of needs and their levels derive from facets and values (ROMANCE/LOVE_PROPENSITY → "making romance"; GREGARIOUSNESS → "spending time with people"; IMMODERATION → alcohol and good meals; VIOLENT → fighting; HARMONY/DISCORD → causing trouble; ALTRUISM → helping; NATURE → seeing animals; ~30 needs listed). A satisfied need resets to 400; descriptors: Unfettered 400–300, Level-headed 299–200, Untroubled 199–100, Not distracted 99 to −999, Unfocused −1,000 to −9,999, Distracted −10,000 to −99,999, Badly distracted ≤ −100,000. Rule of thumb: fulfill a level-1 need every two years, level-2 yearly, level-5 every six months, level-10 every three months. Focus = ratio of weighted band counts (6, 5⅓, 4⅔, 4, 3⅓, 2⅔, 2) over 4×count; very focused ≥140% gives up to +50% effective skill, badly distracted ≤60% up to −50%. Needs were added to replace the generic "on break" feature; dwarves take low-priority (green) or high-priority (magenta, "Pray to Lorsïth!") personal jobs. Satisfying any need gives a good thought and reduces stress. — [Dwarf Fortress Wiki, Need](https://dwarffortresswiki.org/index.php/Need)
- Relationships: types ordered by importance (spouse, lover, child, parent, grandparent, sibling, aunt/uncle, niece/nephew, cousin; deity; apprentice/master; pet/bonded animal; kindred spirit, close friend, friend, grudge, friendly terms, long-term acquaintance (≥30 conversations), passing acquaintance (forgotten if no contact)). Per-pair variables: loyalty, trust, fear, love/hate, respect. Normal social interactions only modify love/hate; first interaction sets trust from the trust facet tier (−50, −25, −10, 0, 10, 25, 50). Love ≥50 = friend, 75 = close friend, 100 = kindred spirit; −50..−74 "disliked", −75..−99 "hated", −100 "pure hate". Love rises more slowly at higher levels. Relations form only when idle or socializing adjacent (busy dwarves never chat, so coworkers "may barely know each other"); compatibility uses shared likes, skills, and personality; only vastly different personalities cause grudges. Mechanics: rank 15 → friendship or grudge; ~40 (31–42 observed) → lovers if friends and romantically inclined; 50 → marriage; age-difference limit max(10, min(age1, age2)/2). Talking to a grudge can add 700+ stress/day. Social skills play no role in relationships. A dwarf with ≥50 non-kin relationships drops passing acquaintances each new year. Worldgen friendships come from childhood, scholarship, art, athletics, war; grudges from business, sport, abusive rulers, religion. — [Dwarf Fortress Wiki, Relationship](https://dwarffortresswiki.org/index.php/Relationship)
- Stress is governed by three facets: bravery, stress vulnerability, anxiety. — [DF Wiki, Stress](https://dwarffortresswiki.org/Stress). With slowly building and receding stress, "a dwarf will remain in a tantrum-capable state for months if not years." — [DF2014:Tantrum](https://dwarffortresswiki.org/index.php/DF2014:Tantrum)
- Tarn Adams (chapter in *Procedural Storytelling in Game Design*, Routledge; search summary): since the game is procedural, the team could not rely on writers, so it improved storytelling through characterization: names, skills, age, family ties, likes/dislikes, injurable bodies; some elements drive mechanics, some expose hidden systems, some (names) are purely storytelling aids. — [Routledge listing](https://www.routledge.com/Procedural-Storytelling-in-Game-Design-1st-Edition/Short-Adams/p/book/9781138595309). Adams's written account (per search snippet): needs were added after dwarves left alone still reported full happiness; needs are drawn from facets and values; unmet needs cause stress and distraction; facet descriptions found their way into player stories "often well beyond what the game was actually modeling." — [search result citing Adams's chapter PDF (link 404 when fetched)](https://wileywiggins.com//documents/dorf/Adams%20-%20Characterization%20and%20Emergent%20Narrative%20in%20Dwarf%20F.pdf). At Gamescom 2026 Adams said the test for adding a simulation layer is whether it produces a recognizable narrative beat in play. — [PC Gamer, 2026](https://www.pcgamer.com/gaming-industry/game-development/dwarf-fortress-creator-says-we-have-a-natural-lean-towards-human-made-stories-but-but-were-all-going-to-be-very-sorely-tested-in-the-coming-years-by-ai/)

**RimWorld**
- Opinion sources: beauty ±20 per level capped ±40; trait effects (annoying voice −25, misandrist/misogynist −25, teetotaler −25 toward addicts, hard worker −20 toward lazy/−30 toward slothful, joyous +20). Random interactions when nearby, weighted: chitchat +10 (weight 1), deep talk +15 for 20 days (weight 0.075, scaled by compatibility ×0 at −1.5 to ×3 at +2), slight −5 (0.02), insult −15 for 20 days (0.007; −5 mood for 2 days), kind words +15 (0.01, kind pawns only). Insult/slight chance scales with opinion (×6 at −100, ×1 at 0, ×0 at +100) and compatibility; abrasive pawns ×2.3. Social fights: 4% per insult, 0.5% per slight; multipliers (bloodlust ×4, drunk ×4, hyper-aggressive ×3, dead calm ×0); outcome 50/50 cathartic +38 or angering −22 for 20 days. Family base opinions: parent/child +30, sibling +20, cousin +10. Tiers: rival −100..−20, acquaintance −20..+20, friend +20..+100. Romance: lover +35, spouse +30, ex −15; attempts every 12 days; success scaled by beauty (ugly ×30%, pretty ×230%) and age; thoughts: rebuffed −10, rejected proposal −30, broke up −50, affair/divorce −70, honeymoon +40. Compatibility = 0.45 × (1 − min(2, age diff/10)) + per-pair random normal with mean 0.3. — [RimWorld Wiki, Social](https://rimworldwiki.com/wiki/Social)
- Mood = base (by difficulty: 42, 42, 37, 32, 27, 22) plus the sum of timed thoughts; the mood bar moves toward its target at up to +12/hour rising and −8/hour falling; mental-break thresholds minor <35%, major <20%, extreme <5%; best vs worst environments can differ by ~60 mood points; sleep pauses break risk. — [RimWorld Wiki, Mood](https://rimworldwiki.com/wiki/Mood)
- Storyteller: weighs colony wealth, colonist and animal count, recent deaths/wounds, time since last major event; threat scale by difficulty 10%–220%; adaptation score rises over time and drops on damage; PopulationIntent is a product of a population curve (0→8.0, 5→1.0, 12→0.0, 20→−1.0) and a day curve, with per-storyteller floors (0.05 default, 0.20 Randy). — [RimWorld Wiki, AI Storytellers](https://rimworldwiki.com/wiki/AI_Storytellers)
- Tynan Sylvester (Aug 2016): the storyteller is "an algorithm that generates events from a categorized database" driven by a few statistics; it eases off when population drops; family relationships are generated so mechanical interactions feel meaningful; characterization is simplified so each trait affects gameplay; the colony is kept small so players know each character; raiders steal or kidnap rather than wipe out; long overlapping events (toxic fallout, sieges) create drama; losing should be a long decline. — [Game Developer, "How RimWorld fleshes out the Dwarf Fortress formula", 2016-08-11](https://gamedeveloper.com/design/how-i-rimworld-i-fleshes-out-the-i-dwarf-fortress-i-formula)

**Crusader Kings 3**
- Every character holds an opinion of every other; categories: general, attraction (adults only; off for men >65 and women >50), vassal, child, courtier, same dynasty, faith hostility (Righteous 0, Astray −10, Hostile −20, Evil −30). Most opinions "decay to 0"; tyranny is capped at 1000 and decays −0.25/month. Relation modifiers: Friend +60, Best Friend +120, Lover +60, Soulmate +120, Rival −60, Nemesis −120, Bully-Victim −20. Example general modifiers: Diplomacy +1/point, Murderer −15, Sadistic −10, Broke Truce −50 (3 years). Attraction: Beautiful +30, Ugly −20, Seducer +40. AI personality attributes (e.g., Vengefulness → target rivals; Compassion → allow love marriages) shape behavior more explicitly than opinion. — [CK3 Wiki, Opinion](https://ck3.paradoxwikis.com/Opinion)
- A CK3 dev diary (as reported) said CK2 let characters pile up traits with little effect, so CK3 limits personality traits to at most 3, each with a bigger behavioral impact. — [GamingOnLinux](https://www.gamingonlinux.com/articles/15647/)

### Inferences
- DF demonstrates the ceiling of "many axes": 50-ish facets and 30 needs produce texture, but the wiki repeatedly notes effects "not entirely understood," and Adams's own point is that players over-read descriptions. RimWorld and CK3 chose few traits with large, legible numeric effects. For a soap-opera cast of a dozen characters, the RimWorld/CK3 scale (few traits, named timed modifiers, thresholds that change the relationship label) is the more directly reusable model.
- All three represent relationship change as a ledger of timed, named entries (thoughts/modifiers) that sum to a scalar, with decay by expiry rather than continuous drift. This makes "why does she dislike me" explainable in UI, which is a feature a Stardew-like could expose in dialogue.

### Gaps
- The Adams chapter PDF was unreachable (404); the quoted points are from search summaries and should be checked against the Routledge edition.
- DF's exact formula for need decay is "not precisely known" per the wiki.

## Smaller or cautionary cases: Animal Crossing, Dragon's Dogma 2, Fable, Project Zomboid, Kenshi, Mount & Blade, Pathologic, Yakuza

### Takeaway
Most other cited games use a single hidden affinity number per NPC with level thresholds (Animal Crossing 0–255 in six tiers; Dragon's Dogma 2 roughly 0–300) and no simulated NPC-to-NPC life; Project Zomboid is the standing example of an NPC system removed because it was "utterly broken, placeholdery, and completely unoptimized" and still not shipped years later.

### Cited Findings
- Animal Crossing: New Horizons (datamined): friendship 0–255, new villagers start at 25; tiers 0–29, 30–59 (one gift/day), 60–99 (villager sells items), 100–149 (catchphrase requests), 150–199 (greeting requests, photo, personality-specific reactions), 200–255 (villager buys items). Points: +1 first daily chat, +3 furniture gift, +2 flowers/bugs/fish/favorite song/matching clothing, bonuses for wrapping and value, +3 cheering up a sad villager; −2 trash gift, −3 for repeatedly pushing/netting (20% chance an apology restores it), −5 trash at a birthday. Photo chance 6% at 150, +0.04%/point to 10.2% at 255. The only personality-type mechanic listed is special reactions at 150–199. — [Nookipedia, Friendship](https://nookipedia.com/wiki/Friendship)
- Dragon's Dogma 2: hidden affinity roughly 0–300 raised by quests and gifts in categories (Adorable, Beautiful, Fancy, Interesting, Expensive, Rare); the NPC logbook records residence and tastes; sources conflict on cooldown (once per day vs a 10-minute cooldown) and a user-reported 1000-point scale for the main pawn is unverified. — [Fextralife, Affinity](https://dragonsdogma2.wiki.fextralife.com/Affinity); [Prima Games](https://primagames.com/gaming/dragons-dogma-2-affinity-guide-all-npc-likes-favorite-gifts)
- Fable: Molyneux described Renown as "related entirely to what the people think of you"; the 2026 reboot drops the halo/horns morality display for a region-based reputation system, which he called "a real shame." — [GameBanshee Molyneux interview](https://www.gamebanshee.com/kpy8h); [GamingBolt, 2026](https://gamingbolt.com/fable-lacking-the-classic-morality-system-is-a-real-shame-says-peter-molyneux)
- Project Zomboid: early builds had basic randomly generated survivor NPCs; a developer (Lemmy) reportedly said on Discord the system was ripped out because it was "utterly broken, placeholdery, and completely unoptimized"; Build 43 is slated as the initial NPC rollout, with the caveat features "may not come out for years." — [PCGamesN](https://www.pcgamesn.com/project-zomboid/npcs); [Destructoid](https://www.destructoid.com/?p=984246)
- Kenshi: developed primarily by one person (Chris Hunt) over twelve years; "every NPC has a name and a life," no hero stats; 870 km² map; the world does not level with the player. — [Wikipedia, Kenshi](https://en.wikipedia.org/wiki/Kenshi_(video_game)); [Steam store page](https://store.steampowered.com/app/233860)
- Mount & Blade II: Bannerlord: companions left in settlements act as emissaries using Charm to raise relations with clans and notables; settlement loyalty depends on culture mismatch, garrison and governor skills; players report that everyone in a clan shares one relation score with the player and complain NPCs are "non-entities." — [GameBanshee dev update](https://www.gamebanshee.com/3hc3h); [Steam discussions](https://steamcommunity.com/app/261550/discussions/0/5300214375033082906)
- Pathologic 2: days consist of a day and a short night; townsfolk perform daily activities as long as their district is not infected; at night few citizens are active; incomplete quests are erased from the notebook at midnight (original game). — [Pathologic wiki](https://pathologic.wiki.gg/wiki/Pathologic_2); [GamingBolt interview, 2015](https://gamingbolt.com/pathologic-interview-an-enemy-you-cant-kill/amp). An Edge review calls the game's days "a mass of clashing schedules." — [Edge via PressReader](https://www.pressreader.com/australia/edge/20200103/281522227989678)

### Inferences
- The single-affinity-with-thresholds model (Animal Crossing, Dragon's Dogma, Stardew) is cheap and legible, but it makes NPCs relate only to the player. Games that wanted NPC-to-NPC drama (DF, RimWorld, CK3, Legion) all added per-pair values and family graphs.

### Gaps
- Yakuza: I found no developer source on the street/crowd NPC system; only general studio interviews.
- Kenshi: no devlog or interview on faction/squad simulation internals was found.
- Project Zomboid: the "ripped out" quote is relayed via secondary sites, not a primary post.

## Cross-cutting: personality representation, relationship change, gossip/knowledge, player reaction, scale

### Takeaway
Shipped games use one of three personality encodings (sliders: Sims 1/2, DF facets; discrete tagged traits: Sims 3, RimWorld, CK3; or a profile record: Legion's Census), relationships as per-pair scalars plus named timed modifiers, and knowledge/gossip as explicit propagation along a relationship graph (Legion) or public/private knowledge stores (Hitman). Scale ranges from ~30 villagers (Stardew) through ~300 behaviour-tree NPCs (Hitman) and ~600 active (KCD) to ~2,400 (KCD II) and thousands of crowd agents, always with LOD.

### Cited Findings
- Personality encodings: Sims 2 uses 25 points over five paired axes with zodiac presets — [Wikipedia, The Sims 2](https://en.wikipedia.org/wiki/The_Sims_2); Sims 3 uses up to five discrete traits — [Wikipedia, The Sims 3](https://en.wikipedia.org/wiki/The_Sims_3); DF uses 0–100 facets with a 78% neutral band — [DF Wiki, Personality trait](https://dwarffortresswiki.org/index.php/Personality_trait); CK3 caps personality traits at 3 — [GamingOnLinux](https://www.gamingonlinux.com/articles/15647/); Oblivion NPCs had "a simple personality, a set of scaled values that can change over time" plus dispositions — [GamesBeat 2010](https://gamesbeat.com/dimming-the-radiant-ai-in-oblivion/); Shadows of Doubt citizens have 23 random traits — [IGF](https://igf.com/entry/2023/shadows-doubt).
- Relationship change: RimWorld and CK3 are ledgers of named, timed modifiers that expire — [RimWorld Wiki, Social](https://rimworldwiki.com/wiki/Social); [CK3 Wiki, Opinion](https://ck3.paradoxwikis.com/Opinion). Stardew is a single scalar with daily decay and gift deltas — [Stardew Wiki, Friendship](https://stardewvalleywiki.com/Friendship). DF is per-pair love/hate with trust set once from a facet — [DF Wiki, Relationship](https://dwarffortresswiki.org/index.php/Relationship).
- Gossip/knowledge spread: Legion propagates memories and affinity along family networks — [Ubisoft News 2021](https://news.ubisoft.com/en-us/article/4po3S9Pwp1YcgBmGPmQxAh/watch-dogs-legion-the-tools-that-built-london). Hitman splits public world state from private per-NPC knowledge and uses periodic shared "services" that can go stale — [Game Developer 2019](https://www.gamedeveloper.com/design/the-ai-of-hitman-2016-). KCD NPCs record per-NPC experiences (a full tavern) and inter-NPC friendliness from returned stolen goods — [PC Games 2015](https://www.pcgames.de/Kingdom-Come-Deliverance-Spiel-16151/Specials/Kingdom-Come-Deliverance-Interview-Special-Teil-5-Kuenstlich-intelligenter-Ehebruch-und-denkende-Tueren-1156484/2/). Stardew has no NPC-to-NPC propagation; conversation topics (`$t`) and auto `_memory_` topics let one NPC reference past events over 1–104 days — [Modding:Dialogue](https://stardewvalleywiki.com/Modding:Dialogue).
- Reaction to the player: Risen/Gothic rule sets (theft, trespass while awake, memory of fights) — [RPG Codex 2011](https://rpgcodex.net/article.php?id=7745); Skyrim's ~30 player actions with world reactions and the overuse lesson — [GamesBeat 2012](https://gamesbeat.com/bethesdas-nesmith-reflects-on-the-difficult-birth-of-skyrims-radiant-story-system/); Hitman's sensors + services with LOS-breaking and mirror sightings — [Game Developer 2019](https://www.gamedeveloper.com/design/the-ai-of-hitman-2016-).
- Scale: Hitman 300+ BT NPCs and 1,200–2,000+ crowd — [Game Developer 2019](https://www.gamedeveloper.com/design/the-ai-of-hitman-2016-); IO cites ~1,700 default characters per Season 2 level — [IO/Intel slides](https://www.intel.com/content/dam/develop/external/us/en/documents/06-create-a-scalable-and-destructible-world-in-hitman2-807276.pdf); KCD ~600 concurrently active (2018 slides, per search) and KCD II ~2,400 — [GDC listing](https://schedule.gdconf.com/session/supporting-thousands-of-npcs-in-kingdom-come-deliverance-kingdom-come-deliverance-ii/915120); Ultima VII 256 NPC slots — [SCHEDULE.DAT](https://www.wiki.ultimacodex.com/wiki/Ultima_VII_internal_formats_%E2%80%93_SCHEDULE.DAT); Shadows of Doubt "100s" — [DevBlog #8](https://colepowered.com/?p=34142); Warhorse's ambient budget ~5 ms/frame for all NPCs — [arXiv 1508.00377](https://ar5iv.labs.arxiv.org/html/1508.00377).

### Inferences
- For a Stardew-sized cast where the player can watch everyone, the KCD/Hitman LOD machinery is unnecessary, but the knowledge split (public world facts vs private per-NPC memories with timestamps, periodically synced) is the cheapest way to get gossip and "she heard about it from her sister" without a full belief model.
- No shipped non-LLM game surfaced in this research simulates NPC-to-NPC conversation content; "gossip" is always propagation of numeric affinity or discrete facts, with authored lines keyed to those facts (Stardew `$t` topics being the simplest instance).

### Gaps
- I found no shipped-game source giving a concrete data model for NPC-to-NPC gossip beyond Legion's description and Stardew's topic keys.

## What postmortems and developer talks say were the hard parts and dead ends

### Takeaway
Across two decades the same findings recur: emergent goal conflict produces chaos that must be bounded (Oblivion), realistic reactions are not automatically fun and get overused (Skyrim), hidden depth reads as randomness and players invent the rest (Sims 2), shared-resource bottlenecks break populations (Shenmue, KCD II), authoring and debugging tools are the real cost (Sims 2, KCD, Legion, Skyrim modders), and the more polished the system, the less players notice it (Nesmith 2025).

### Cited Findings
- Emergent chaos must be damped: skooma-addict murders and quest-breaking NPC behavior in Oblivion were consciously reduced (Pagliarulo). — [GamesBeat 2010](https://gamesbeat.com/dimming-the-radiant-ai-in-oblivion/)
- Realism is not design: "just because a response was reasonable in the real world, it doesn't mean it's good in a game"; stolen-item quests always ended in murder; reactions were initially overused; procedural quests cannot match hand-crafted ones and "if we pass the buck to a system, it's not the same" (Nesmith). — [GamesBeat 2012](https://gamesbeat.com/bethesdas-nesmith-reflects-on-the-difficult-birth-of-skyrims-radiant-story-system/)
- Polish hides the system: Skyrim's deeper Radiant AI was less noticed than Oblivion's quirky one; the investment is "enormous" (Nesmith). — [FRVR 2025](https://frvr.com/blog/news/elder-scrolls-designer-explains-that-radiant-ai-is-an-enormous-investment-for-bethesda-but-every-improvement-actually-makes-it-less-noticeable-to-players/)
- Perceived intelligence beats real intelligence; detailed models (urinal choice) did not outperform randomness; players forget quickly; authoring tools matter more than AI (Matt Brown, Maxis). — [kmjn.org AIIDE 2006 notes](https://kmjn.org/notes/sims2_ai.html)
- Legibility over fidelity: RimWorld simplified characterization so every trait matters and keeps casts small (Sylvester). — [Game Developer 2016](https://gamedeveloper.com/design/how-i-rimworld-i-fleshes-out-the-i-dwarf-fortress-i-formula). DF's test for a new layer is whether it yields a recognizable narrative beat (Adams). — [PC Gamer 2026](https://www.pcgamer.com/gaming-industry/game-development/dwarf-fortress-creator-says-we-have-a-natural-lean-towards-human-made-stories-but-but-were-all-going-to-be-very-sorely-tested-in-the-coming-years-by-ai/)
- Resource bottlenecks: Shenmue's whole district stuck in one convenience store, fixed by occupancy caps. — [Game Developer 2014](https://www.gamedeveloper.com/design/yu-suzuki-recounts-the-making-of-i-shenmue-i-). KCD II ran out of beds and sends NPCs out of the city at night. — [80.lv](https://80.lv/articles/kingdom-come-deliverance-2-brings-reactive-world-more-ethnicities/)
- Script sprawl is the scaling limit; smart objects/areas plus behavior-tree injection fixed authoring speed but debugging deep trees and messaging remained painful (Warhorse). — [arXiv 1508.00377](https://ar5iv.labs.arxiv.org/html/1508.00377)
- Data tagging and tuning dominate procedural population systems (Legion: tagging handled largely by a separate team; "tuning and debugging were ongoing challenges"). — [Ubisoft News 2021](https://news.ubisoft.com/en-us/article/4po3S9Pwp1YcgBmGPmQxAh/watch-dogs-legion-the-tools-that-built-london)
- Scheduling-UI burden on players: Majora's Mask cut from seven days to three partly because tracking who is where on which day was too hard, and Miyamoto still found players missed hidden events. — [Zelda Universe 2019](https://zeldauniverse.net/2019/05/07/zeldas-study-majoras-mask-was-originally-planned-to-have-a-weeklong-cycle/); [Cubed3 2015](https://cubed3.com/news/23096/1/bombers-notebook-to-be-revamped-in-zelda-majoras-mask-3d.html)
- Key-ladder fragility: Stardew's required `spring` key, year-1-only `<dayOfMonth>` dialogue keys, crash on a bad GOTO, and NPCs not following schedules until the player sleeps. — [Modding:Schedule data](https://stardewvalleywiki.com/Modding:Schedule_data); [Modding:Dialogue](https://stardewvalleywiki.com/Modding:Dialogue)
- Package debugging is tedious enough to need third-party tools; "Once Per Day" silently fails with a schedule set. — [Arcane University](https://wiki.beyondskyrim.org/wiki/Arcane_University:NPC_Packages)
- Unfinished NPC systems get cut: Project Zomboid's NPCs were removed as broken and unoptimized and remain unshipped. — [PCGamesN](https://www.pcgamesn.com/project-zomboid/npcs)

### Inferences
- For a soap-opera Stardew-like, the evidence favors: a base authored day per character (Stardew/U7 style) with capacity-limited locations; an override stack for events and quests (KCD subbrains, Skyrim package list); a small number of legible traits with named, timed relationship modifiers (RimWorld/CK3); a per-NPC private memory store with simple propagation along a relationship graph (Legion/Hitman); and tooling for authoring and inspecting schedules and relationship ledgers, since every team names tooling as the real bottleneck.

### Gaps
- GDC Vault recordings for the most technical talks (Legion Census 2021, Hitman 2 2019, Warhorse 2026, Evans 2010) were not accessible; findings rely on abstracts and secondary write-ups.
- No postmortem specifically about Stardew's or Animal Crossing's NPC systems from their developers was found.
