# 2D game-asset pipelines and pixel-art-specific AI tools (researched 2026-10-22)

Scope: tools and pipelines for top-down (Stardew / Ultima VI style) tilesets, seamless tiles, buildings, directional character sheets, props and portraits, for a developer with no artist, no GPU, and a headless Node/TypeScript environment. Google's models and general-purpose provider transparency/reference parameters are covered by other researchers and only mentioned where a pixel-specific tool wraps them.

Source quality note: the only recent (Sept 2026) multi-tool comparison I found is published by Cinevva, itself a vendor of a (non-pixel) generator; Ludo.ai's comparison pages are also vendor-published. Independent hands-on reviews of PixelLab or Retro Diffusion output from 2025-2026 were essentially absent from search results; the most honest quality evidence is from devlogs and forum threads, cited below.

## Key question 1: Pixel-art-specific generators (what they make, consistency, inputs, sizes, API, price, license)

### Takeaway
Two tools output on a true pixel grid and have real HTTP APIs usable from Node: Retro Diffusion (prepaid USD balance, $0.03-$0.18 per image, $0.10 per tileset, $0.07-$0.25 per animation, `X-RD-Token` header, async task polling) and PixelLab (subscription $12/$24/$50 per month, OpenAPI-documented REST plus a remote MCP server, 4/8-direction rotation, skeleton animation, palette lock via `color_image`). Scenario, Layer.ai, Ludo and Leonardo are general studio tools that can be prompted toward pixel style but need a downscale/quantize pass; Scenario additionally hosts Retro Diffusion's RD Plus / RD Tile / RD Animation models.

### Cited Findings

Retro Diffusion (Astropulse LLC)
- API v2 base URL `https://api.retrodiffusion.ai/v2`; v1 still supported. Auth header `X-RD-Token`, keys start `rdpk-`, max 5 per account. `POST /v2/inferences` then poll `GET /v2/inferences/tasks/{task_id}` until `succeeded`/`failed`. Optional `Idempotency-Key`. — [Retro-Diffusion/api-examples](https://github.com/Retro-Diffusion/api-examples)
- Request fields: `prompt`, `prompt_style` (style ID also selects the model), `width`/`height` (12-512 overall, tighter per style), `num_images` (1-16, or 1-4 for some RD Pro styles), `seed`, `input_image` (raw base64 RGB) with `strength` (0-1, default 0.75), `reference_images` (RD Pro styles only, up to 9), `input_palette` (base64 palette image), `remove_bg`, `tile_x`/`tile_y` (seamless), `frames_duration` (4/6/8/10/12/16 for animations), `return_spritesheet` (PNG sheet instead of GIF), `upscale_output_factor` (nearest-neighbor upscale, default 1 = native), `bypass_prompt_expansion`, `include_downloadable_data` (e.g. inventory atlas JSON), `check_cost` (free dry run), `upload_outputs` (hosted URLs). `negative` is accepted but unused by current models. — [Retro-Diffusion/api-examples](https://github.com/Retro-Diffusion/api-examples)
- Response: `base64_images` (PNG, or GIF for animations), `balance_cost`, `remaining_balance`, `model`, `output_urls`. — [Retro-Diffusion/api-examples](https://github.com/Retro-Diffusion/api-examples)
- Costs (flat per image at any size): `rd_fast` $0.03; `rd_plus` and `rd_mini` $0.06; `rd_pro` $0.18 (`fps_weapon` $0.25); tiles (single, variation, object, scene) $0.06; tileset (`rd_tile__tileset` / `_advanced`) $0.10; animations $0.07 (`any_animation`, `big_animation`, `8_dir_rotation` $0.25); advanced animations $0.14 (`custom_action`, `subtle_motion` $0.25; `rotate` $0.10); edit tools `image_edit`/`inpainting`/`outpainting`/`seam_tiling` $0.18, `background_remover`/`color_style_transfer` $0.01. Prepaid USD balance; failed generations refunded; credits cannot be bought via the API (auto-refill or invoicing). `GET /v2/inferences/credits` returns balance. Rate limits: only "Pixel Fixer 10 req/min per token" is stated; HTTP 429 carries `Retry-After`. — [Retro-Diffusion/api-examples](https://github.com/Retro-Diffusion/api-examples)
- Third-party MCP listing agrees on pay-per-generation with no subscription, "from ~$0.01 per image", credits do not expire, output sizes 16x16 to 384x384 depending on style, and a free cost-estimation call. — [mcpservers.org Retro Diffusion listing](https://mcpservers.org/servers/retro-diffusion/retro-diffusion-mcp) (undated, secondary)
- Model families as hosted on Replicate (post dated 2025-11-19): `rd-fast` (speed, 15 styles), `rd-plus` (higher-quality text-to-image, styles for scenes/maps/UI/icons), `rd-tile` (tiles, tilesets, variations, scene objects), `rd-animation` (sprites/spritesheets with consistent framing and low frame counts). Example style presets: `game_asset`, `topdown_map`, `tileset`, `four_angle_walking`. Most models support `tile_x`/`tile_y`, `remove_bg`, input image and palette image. Examples use 128x128, 256x256, 32x32 tiles, 48x48 animation. — [Replicate blog](https://replicate.com/blog/retro-diffusions-pixel-art-models-are-now-on-replicate)
- RD Plus: "trained at native resolutions of 256 x 256 pixels (or below)"; supports style-transfer image prompt with strength, uploaded limited palette image, background removal, seamless tiling in X and Y; no animation or tilesets. RD Tile: single tiles, variations, full tilesets, decorative objects; some styles fixed at 32x32 "classic RPG tiles"; "smart transitions"/"seamless transitions" between materials (grass to dirt); "tileset advanced" mode takes a second prompt and/or reference image to blend two textures; no palette strictness; no background removal. RD Animation: 4-direction walk cycles, idle, small VFX loops, character actions; low frame counts; walking animations may be limited to 48x48, small sprites 32x32; reference images guide pose/design but are not used as starting frames; accepts palette image; short loops only. — [Scenario help: Retro Diffusion Models](https://help.scenario.com/en/articles/retro-diffusion-models-the-essentials/)
- Aseprite extension pricing per Cinevva (Sept 2026): $20 (Lite) or $65 one-time, no credits, runs locally; web app credits $5 (250) to $50 (3,500); 50 free web credits. Local use "needs a reasonable GPU" plus Aseprite ($19.99). — [Cinevva comparison, 2026-09-04](https://app.cinevva.com/guides/ai-pixel-art-generators)
- Web credits: "Each credit generates an image up to 276x276 pixels, and cost rises with size"; two base models, 28 built-in styles; listing is tagged "AI Assisted / Graphics" on itch. — [astropulse.itch.io/retrodiffusionai](https://astropulse.itch.io/retrodiffusionai)
- Training-data claim (vendor statement, no independent audit found): "this model has been trained on licensed assets from Astropulse and other pixel artists with their consent." Output ownership per the itch FAQ: code and models owned by Astropulse LLC and not commercially usable, "but the outputs of the code and models are owned by whoever creates them (you)". — [astropulse.itch.io](https://astropulse.itch.io/retrodiffusionai); [Gumroad credits page](https://astropulse.gumroad.com/l/RetroDiffusionCredits)

PixelLab
- Access paths: web creator (PixFlux for medium-XL images, BitForge for small-medium), Characters tool (4 or 8 directional views from text; one-click walk/run/idle; exports sprite sheets or frames), Pixelorama in-browser editor, Aseprite extension (Aseprite v1.3+, trial build does not support extensions), remote HTTP MCP at `https://api.pixellab.ai/mcp` with Bearer token (stdio-only clients via `npx mcp-remote@latest`; requires active subscription), REST API with Python SDK. Tool categories: create image (pose-to-image, image-to-pixel-art), edit/remove background/resize/"unzoom", rotate incl. 8-directional (Pro), animate with skeleton / re-pose / edit animation (Pro), map (tilesets, textures, isometric tiles), inpaint, reduce colors. — [PixelLab docs: ways to use](https://www.pixellab.ai/docs/ways-to-use-pixellab)
- OpenAPI endpoints: `POST /generate-image-pixflux` (image_size 16-400 per side, area 32x32 min to 400x400 max; `text_guidance_scale` 1-20; `no_background`; `init_image` + `init_image_strength`; `color_image` forced palette; `view`, `direction`, `isometric`, `seed`). `POST /generate-image-bitforge` (16-200 per side, 200x200 max; `style_image` + `style_strength` 0-100; inpainting via `inpainting_image`+`mask_image`; `skeleton_keypoints` + `skeleton_guidance_scale`; `coverage_percentage`; `oblique_projection`). `POST /animate-with-skeleton` (image_size 16/32/64/128/256; `skeleton_keypoints` exactly 3 frames of labelled points with z_index; `reference_image` required; `view` side / low top-down / high top-down; `direction` 8 compass values). `POST /animate-with-text` (64x64 only; `action`, `description`, `reference_image`; `n_frames` 2-20 but model always generates 4). `POST /rotate` (`from_image`; `from_direction`/`to_direction` defaults south/east; `view_change` -90..90; `direction_change` -180..180; `image_guidance_scale`). `POST /inpaint`. `POST /estimate-skeleton`. `GET /balance` (USD). Responses carry a `usage` USD value (examples 0.01); 402 insufficient credits, 429 too many requests, 529 rate limit. - Python SDK exposes `generate_image_pixflux(description, image_size)`; README lists Pixflux, Bitforge (reference images to match style), skeleton animation (biped and quadruped), text animation, inpainting, rotation. — [pixellab-python](https://github.com/pixellab-code/pixellab-python)
- Pricing per Cinevva (Sept 2026): 40 free trial generations; $12/mo (2,000 generations); $24/mo (priority queue, images up to 400x400); $50/mo (10,000 generations). API plus Aseprite plugin. - Older secondary sources list $9-$50/mo and 20 free generations (likely stale). — [AlternativeTo](https://alternativeto.net/software/pixellab/about); [80.lv](https://80.lv/articles/easily-create-pixel-art-based-on-sketch-with-this-ai-tool-for-aseprite/)

### Inferences
- For a headless Node pipeline the realistic shortlist is Retro Diffusion (pay-as-you-go, no subscription, seamless and palette parameters, tileset and 4-dir walk styles) plus PixelLab (subscription, better for rotations and skeleton-driven animation, palette lock via `color_image`). Both are plain JSON-over-HTTPS with base64 images, so `fetch` from Node is sufficient; no SDK needed.
- Budget estimate from the published Retro Diffusion rates: a set of ~200 props at rd_plus ($0.06) is about $12; ~20 tilesets at $0.10 is $2; 10 characters with 4-dir walk ($0.07) plus 8-dir rotation ($0.25) is about $3.20. Iteration multiplies this by the reject rate, which from devlog evidence is high (see Q6).
- "Licensed/consenting training data" is claimed only by Retro Diffusion among the pixel tools found; it is a vendor statement without independent verification.

## Key question 2: Sprite sheets and animation (rotations and cycles from one reference; shippable quality; skeletal and paper-doll alternatives)

### Takeaway
PixelLab's approach (estimate a skeleton from a reference sprite, then generate frames from posed keypoints, or rotate a reference to a new direction) is the only API-level method found that gives frame-to-frame control; Retro Diffusion generates short 4-direction walk/idle loops at fixed small sizes from text plus optional references. Independent quality reports are thin; what exists says drift between regenerations and style drift are the recurring problems, and that the hand-fixing of AI frames tends to fail, so pipelines regenerate instead.

### Cited Findings
- PixelLab `animate-with-skeleton` needs a `reference_image` plus exactly 3 keypoint frames (labels like NOSE, NECK, LEFT KNEE with z_index) and supports views side / low top-down / high top-down and 8 directions; `estimate-skeleton` extracts keypoints from an existing sprite; `rotate` turns a south-facing sprite to another compass direction with `image_guidance_scale`; `animate-with-text` is 64x64 and always 4 frames. — [PixelLab OpenAPI](https://api.pixellab.ai/v1/openapi.json)
- Cinevva calls PixelLab "the only one that treats a sprite as a skeleton you can pose and rotate rather than a picture". — [Cinevva](https://app.cinevva.com/guides/ai-pixel-art-generators)
- Retro Diffusion RD Animation: 4-direction walking cycles, idle, VFX loops, actions; walking may be limited to 48x48; "low frame counts"; references guide design but are not starting frames; cannot produce long animations. API style IDs include `four_angle_walking`, `8_dir_rotation` ($0.25), `rotate` ($0.10), `custom_action`/`subtle_motion` ($0.25), `frames_duration` 4-16, `return_spritesheet`. — [Scenario help](https://help.scenario.com/en/articles/retro-diffusion-models-the-essentials/); [api-examples](https://github.com/Retro-Diffusion/api-examples)
- A July 2026 pipeline write-up (sprite-forge, ComfyUI on a 32 GB GPU): generate a master sheet (turnarounds, expressions, poses) in one image so parts stay consistent, then redraw each cut at higher resolution with the master as reference; checkpoints reject outputs whose four corners are not transparent and damage variants more than 1 px off the base; "each regeneration shifts by a few pixels"; pixel-art terms are injected automatically because omitting them drifts toward glossy anime; hand-fixing fabric/skin/outlines had a "zero percent success rate", so fixes are regenerations. The editing model needed >20 GB VRAM; with 16 GB it produced nothing. — [dev.to / kitepon.dev](https://dev.to/quolu/how-i-made-an-ai-that-cant-draw-the-same-character-create-anime-model-sheets-19cn)
- A 2026 workflow post describes going from one locked character reference and one structured prompt to a full sheet in one pass, and says the older approach had identity drift between frames (changed clothing, moved weapon). — [IndieHackers](https://www.indiehackers.com/post/gpt-image-2-5-a-full-sprite-sheet-from-one-reference-110562d19f) (fetch blocked; summary from search snippet only)
- Visual-novel devlogs: one needed "several hours of Photoshop cleanup to match outfits" across AI sprites; another removed its AI sprites because they "took too long to edit for consistency". — [itch devlog](https://itch.io/devlog/507457/a-productive-week-another-ending-complete-and-some-sprite-work.amp); [itch devlog: removed AI CGs](https://rizvn.itch.io/deliidol/devlog/635116/removed-ai-cgs-and-sprites-images-that-were-removed-from-game)
- Hand-animation guidance still applies to review: walk cycle keys are contact, passing, contact, passing; check at game scale; verify timing in-engine; sprite origin mismatches (feet 2 px off the ground) are easy to miss. — [Relish Games, 2026-06-20](https://relishgames.com/journal/pixel-art-pipelines-best-tools-for-2026/)
- Skeletal alternative: Spine 4.3 Essential $99 ($69 sale), Professional $449 ($379 sale), Enterprise $2,499 + $379/user for businesses over $500k revenue; licence covers the Spine Runtimes in games. — [Esoteric Software purchase page](https://esotericsoftware.com/spine-purchase)
- Paper-doll alternative: the Universal LPC generator composes layered 64x64 sheets; original LPC animations are spellcast, slash, thrust, walk, shoot, hurt; LPC Expanded adds bow, climb, run, jump plus child and elderly bases (many items not yet drawn for these). Runs on Node 22.19+ (`npm ci`, `npm run dev`); layer data lives in `sheet_definitions/` and `palette_definitions/`; selections can be exported to JSON next to the PNG. — [Universal-LPC-Spritesheet-Character-Generator](https://github.com/LiberatedPixelCup/Universal-LPC-Spritesheet-Character-Generator)
- A Rust CLI (`lpcg`) composites LPC sheets headlessly; its import rule only accepts 832x1344 PNGs. — [lpcg crate](https://docs.rs/crate/lpcg/0.3.0)

### Inferences
- "Good enough to ship" is not demonstrated by any independent source found. The practical pattern in 2026 devlogs is: generate many, auto-reject by deterministic checks (alpha corners, bounding-box drift, palette), keep the survivors, and never hand-fix frames.
- A hybrid that avoids per-frame generation entirely (LPC paper-doll bodies for walk cycles, AI only for portraits, props and tiles) is the only route with guaranteed frame consistency and known licensing; the cost is that characters look like LPC characters.
- The LPC generator has no official CLI; because the layer definitions are JSON and the compositing is just PNG layer stacking, a Node script with `sharp.composite()` over `spritesheets/` can reproduce it, provided the credits export is reproduced too.

### Gaps
- No reddit or forum thread with side-by-side PixelLab/Retro Diffusion walk-cycle results was found; searches returned vendor pages and unrelated hand-animation critique threads.
- DragonBones status in 2026 not researched (no results sought after Spine pricing was confirmed).

## Key question 3: Tilesets and seamless tiles (tileable textures, Wang/blob/autotile formats, transitions, post-processing)

### Takeaway
Retro Diffusion is the only API found with first-class seamless (`tile_x`/`tile_y`) and tileset generation including two-material transitions; PixelLab has a "map" toolset in the UI but no tileset fields in its public OpenAPI. The target formats are well defined (16-tile corner/edge sets, 47-tile blob, Godot "Match Corners and Sides"), but no tool was found that emits a labelled blob set directly; the practical path is to generate base and transition tiles and assemble the 47 variants programmatically.

### Cited Findings
- Retro Diffusion: `tile_x`/`tile_y` booleans on most models; `seam_tiling` edit tool ($0.18); tiles $0.06, tileset $0.10; RD Tile "tileset advanced" mode blends two prompts/references (stone and moss) into one tileset with "seamless transitions" between materials; some styles fixed at 32x32 classic RPG tiles; RD Tile has no palette strictness. — [api-examples](https://github.com/Retro-Diffusion/api-examples); [Scenario help](https://help.scenario.com/en/articles/retro-diffusion-models-the-essentials/)
- Replicate's rd-tile example uses `prompt_style: "tileset"` at 32x32; rd-plus example uses `topdown_map` at 256x256 with `tile_x`/`tile_y`. — [Replicate blog](https://replicate.com/blog/retro-diffusions-pixel-art-models-are-now-on-replicate)
- PixelLab UI lists "Map: tilesets, textures, isometric tiles" but the OpenAPI spec has no tileset or seamless fields. — [PixelLab docs](https://www.pixellab.ai/docs/ways-to-use-pixellab); [OpenAPI](https://api.pixellab.ai/v1/openapi.json)
- Tiled terrain sets: Corner set (16 tiles for 2 terrains), Edge set (16; roads, fences), Mixed set (256 for 2 terrains; the 47-tile Blob is a reduced mixed set; rotation can reduce Blob to 15). If two terrains have no direct transition, the Terrain Brush routes through an intermediate terrain (dirt on cobblestone via sand). Up to 254 terrains per set; each tile corner holds one terrain. — [Tiled manual: Terrain](https://doc.mapeditor.org/en/stable/manual/terrain/)
- Godot 4 terrain sets: modes Match Corners and Sides, Match Corners, Match Sides, corresponding to Godot 3's 3x3 minimal, 2x2 and 3x3 bitmasks; each tile has peering bits that are a terrain ID or -1 for empty; a tile with all bits set appears only when all 8 neighbours share the terrain; transitions work because one tile can define several terrains. — [Godot docs: Using TileSets](https://docs.godotengine.org/en/stable/tutorials/2d/using_tilesets.html)
- Godot 3.5 docs: 3x3 minimal has nine bits (4 corners, 4 edges, centre); centre must be on; corners count only when both adjacent edges are on; this yields 47 valid combinations. — [Godot 3.5 docs](https://godot-ja.readthedocs.io/ja/3.5/tutorials/2d/using_tilemaps.html)
- Converters exist: Blobsmith exports Godot 4 `.tres` terrain sets and Tiled `.tsx` Wang sets; TerrainForge offers blob-47, Wang-16 and 3x3-minimal templates with Godot/Tiled export; a Godot 3.3 generator builds the 47 tiles from five source tiles. — [Blobsmith](https://blobsmith.itch.io/blobsmith); [TerrainForge](https://deforestpeg.itch.io/terrainforge); [Godot asset 4303](https://godotengine.org/asset-library/asset/edit/4303)
- Prompt guidance from a tileset-generator vendor: the word "seamless" pushes tiling-aware models to match opposite edges; pair with "top-down view", a consistent light direction ("from top-left") and an explicit grid size. — [Sorceress blog](https://sorceress.games/blog/ai-tileset-generator-game-ready-tilesets-from-a-prompt) (vendor)
- One tileset "generator" (LlamaGen/PixelBox Labs) returns "one concept image for visual exploration, not separated production assets or engine metadata". — [llamagen.ai RPG tileset generator](https://llamagen.ai/pixel-game-tools/rpg-tileset-generator)
- RPG Maker community: one developer "could not get the consistency needed for game work" and likened AI to hitting a random button; another scripted an asset pipeline around the output. — [RPG Maker guild thread](https://guild.rpgmakerofficial.com/t/topic/1898)

### Inferences
- The cr31 blob reference (http://www.cr31.co.uk/stagecast/wang/blob.html) returned 503 during this session; the Tiled and Godot docs above cover the same facts (47 of 256 mixed combinations, corners only count when both adjacent edges are set).
- A Node assembly step for blob sets: generate (a) a seamless interior texture per terrain with `tile_x`/`tile_y`, (b) one transition tile pair per terrain pair via RD Tile advanced mode, then cut quadrant-level pieces and compose the 47 (or 16) variants with `sharp.composite`, writing both a Godot peering-bit `.tres` and a Tiled wangset `.tsx`. No source demonstrates this end to end; it is an inference from the format definitions.
- RPG Maker A2 autotiles (2x3 cells of 48x48 with four 24x24 sub-quadrants) were not documented in the fetched sources; the quadrant-composition approach above is the same mechanism.

### Gaps
- No tool found that outputs a labelled 47-tile blob set directly from a prompt; Retro Diffusion's tileset style output layout was not documented in sources reachable here.
- The exact `.tsx` wangset XML fields and Godot `.tres` peering-bit serialization were not in the fetched doc pages (Tiled's page describes the editor only).

## Key question 4: Buildings and large objects (one image vs assembled tiles; 3/4 perspective; same building across states)

### Takeaway
Evidence is thin. The pixel tools expose `view` (side / low top-down / high top-down) and `direction` parameters (PixelLab) or a `topdown_map` style and up to 9 reference images (Retro Diffusion RD Pro) as the levers for perspective and identity; RD Tile also covers "larger scene objects". No source documented a validated workflow for season or damage variants of one building, and forum evidence says perspective consistency across a set is the main unmet requirement.

### Cited Findings
- PixelLab PixFlux/BitForge accept `view`, `direction`, `isometric`, `oblique_projection`; BitForge takes a `style_image` with `style_strength` 0-100 and inpainting with mask; `init_image` + `init_image_strength` for img2img. — [PixelLab OpenAPI](https://api.pixellab.ai/v1/openapi.json)
- Retro Diffusion: `reference_images` up to 9 (RD Pro styles only, $0.18/image); `input_image` with `strength` for img2img on other styles; RD Plus handles "full scenes, top-down maps"; RD Tile covers "decorative objects (statues, flowers), and larger scene objects"; `topdown_map` style preset at 256x256 shown on Replicate. — [api-examples](https://github.com/Retro-Diffusion/api-examples); [Scenario help](https://help.scenario.com/en/articles/retro-diffusion-models-the-essentials/); [Replicate blog](https://replicate.com/blog/retro-diffusions-pixel-art-models-are-now-on-replicate)
- Vendor workflow claim: uploading reference images "locks the color palette, detail level, and proportions" before further generation (untested marketing). — [PC Tech Magazine, July 2026](https://pctechmag.com/2026/07/cutting-sprite-production-time-from-weeks-to-minutes-without-losing-consistency/)
- A freelance posting for an AI-generated top-down tileset states "the single most important requirement is consistency: every tile and prop must read as one cohesive set". — [Upwork posting](https://www.upwork.com/freelance-jobs/apply/Top-Down-Tileset-Prop-Artist-Generated-Virtual-Tabletop-Map-Builder_~022063807835432765116/)
- Relish Games recommends standardising palette index order (index 0 outline, index 1 skin) so palette swaps produce variants and damage states without regeneration. — [Relish Games](https://relishgames.com/journal/pixel-art-pipelines-best-tools-for-2026/)

### Inferences
- For a building whose footprint must snap to the tile grid, generating it as one image at a multiple of the tile size (e.g. 96x128 for a 3x4-tile cottage at 32 px) with `remove_bg` and then slicing is simpler than assembling it from tiles, and keeps the 3/4 perspective internally consistent. Walls-as-tiles only pays off when the building must be resizable.
- Seasonal variants are most reliably done as palette remaps (snow, autumn) of one base building rather than regeneration, since every regeneration risks drift (see Q6). Damage states need inpainting (`inpaint` on PixelLab, `inpainting` at $0.18 on Retro Diffusion) with the undamaged building as `init_image`.

### Gaps
- No devlog or comparison found showing the same AI-generated building reproduced across seasons or damage states; the "seasons/damage" part of the question is unanswered by sources.

## Key question 5: Post-processing from Node without a GPU (downscale, quantize, alpha cleanup, grid alignment, atlases, normal maps)

### Takeaway
Everything needed runs in pure Node: `sharp` for nearest-neighbour or Lanczos resizing, `trim`, `extract` and compositing; `image-q` (MIT, pure JS) for palette quantization with several distance metrics and dithers; `pngquant` as a CLI for 8-bit PNGs; `free-tex-packer-core` (MIT) for atlases with Phaser/Pixi/Godot/Spine exporters. The best-regarded pixelization downscaler, Astropulse's K-Centroid (k-means dominant colour per output cell), is MIT and small enough to port.

### Cited Findings
- `sharp` resize kernels: `nearest`, `linear`, `cubic`, `mitchell`, `lanczos2`, `lanczos3` (default), `mks2013`, `mks2021`; only one `resize` per pipeline; `extract` crops by integer left/top/width/height before or after resize; `trim` removes edges similar to the top-left pixel with `threshold` (default 10), `lineArt` option and `margin`, and reports `trimOffsetLeft`/`trimOffsetTop` in `info`. — [sharp resize docs](https://sharp.pixelplumbing.com/api-resize)
- `image-q`: palette quantizers NeuQuant, NeuQuantFloat, RGBQuant, WuQuant; colour distances Euclidean, EuclideanBT709, Manhattan, CIEDE2000, CIE94, CMetric, PNGQuant and more; image quantizers NearestColor, error diffusion (FloydSteinberg, Atkinson, Stucki, Jarvis, Burkes, Sierra variants) and Riemersma (Hilbert curve); ordered dithering is a TODO; Node 6+; MIT; changelog top entry 4.0.0. — [ibezkrovnyi/image-quantization](https://github.com/ibezkrovnyi/image-quantization)
- `pngquant` quantizes PNGs to 8-bit palettes; quantization can change colours and transparency details. — [pngquant package description](https://linux-meta.duckdns.org/en/p/pngquant)
- `free-tex-packer-core`: packers MaxRectsBin (BestShortSideFit default, BestLongSideFit, BestAreaFit, BottomLeftRule, ContactPointRule), MaxRectsPacker (Smart, Square, SmartSquare, SmartArea), OptimalPacker (recommended); exporters JsonHash (default), JsonArray, Css, Pixi, GodotAtlas, GodotTileset, PhaserHash, PhaserArray, Phaser3, XML, Starling, Cocos2d, Spine, Unreal, UIKit, Unity3D, Egret2D, plus custom Mustache templates; options `padding`, `extrude`, `allowTrim` (default true), `trimMode` trim/crop, `allowRotation` (default true), `powerOfTwo`, `detectIdentical` (default true), `scale`, `textureFormat` png/jpg/webp; `packAsync`; MIT. — [odrick/free-tex-packer-core](https://github.com/odrick/free-tex-packer-core)
- K-Centroid (Astropulse): "uses K-Means to find the most common color for every tile of the downscaled image", written in Lua for Aseprite and "may take several seconds"; a forum commenter says it is MIT licensed and "not quite as good at turning things into pixel art as Pixelization". PixelOE includes a k-centroid mode crediting Astropulse's `k-centroid.py`. Astropulse's separate `pixeldetector` repo downscales and restores pixel art that has been resized or corrupted (estimates the scale factor from horizontal/vertical pixel differences). — [K-Centroid on itch](https://astropulse.itch.io/k-centroid); [itch forum post](https://itch.io/post/8442461); [PixelOE mirror](https://gitee.com/dkori/PixelOE); [Astropulse GitHub](https://github.com/Astropulse/); [runcomfy AstropulsePixelDetector](https://runcomfy.com/comfyui-nodes/pfaeff-comfyui/astropulse-pixel-detector)
- Relish Games: use nearest-neighbour for 2x/3x scaling; define 16-24 colours before drawing; palette validation scripts should check sprites against the approved palette; export packed atlases with JSON metadata; `aseprite --batch` for headless export; author flat sprites, generate normal maps, light in-engine. — [Relish Games](https://relishgames.com/journal/pixel-art-pipelines-best-tools-for-2026/)
- Cinevva: pixel art uses roughly 8-32 colours; "over 200 colours suggests a painting". — [Cinevva](https://app.cinevva.com/guides/ai-pixel-art-generators)
- Pipeline checkpoints from the sprite-forge write-up: reject if the four corners are not fully transparent; one accepted image still had over 200,000 black pixels of residue after background removal; alignment tolerance 1 px against the base sprite. — [dev.to](https://dev.to/quolu/how-i-made-an-ai-that-cant-draw-the-same-character-create-anime-model-sheets-19cn)
- Engine gotcha: when a collision box defaults to the full sprite canvas, transparent padding becomes solid collision. — [Makko blog](https://blog.makko.ai/pixel-art-hitboxes-ai-game-art-week-march-30/)
- Retro Diffusion returns native-resolution pixels (`upscale_output_factor` default 1), and PixelLab `estimate-skeleton`/`rotate` accept 16-256 px inputs, so when using these tools the downscale step is unnecessary; `input_palette` / `color_image` give palette lock at generation time. — [api-examples](https://github.com/Retro-Diffusion/api-examples); [PixelLab OpenAPI](https://api.pixellab.ai/v1/openapi.json)

### Inferences
- Recommended Node order for non-grid generators (Leonardo, Scenario, general models): (1) `sharp().trim()` then pad to the tile multiple, (2) downscale with K-Centroid-style k-means per cell (port the algorithm; or `kernel: 'nearest'` as a cheap baseline and `lanczos3` plus quantize as a smoother baseline), (3) `image-q` NearestColor against the project's fixed palette (no dither for pixel art), (4) alpha hard-threshold (e.g. a < 128 to 0, else 255) and reject if any corner alpha is non-zero, (5) `free-tex-packer-core` with `padding`/`extrude` 1-2 px, `allowRotation: false`, `allowTrim: false` for fixed-grid sheets.
- `image-q` can quantize to a user-supplied palette by constructing a `PointContainer`-based palette and running `applyPalette`; the fetched README did not state this explicitly, so verify against the API before relying on it.
- `pixelmatch` (not researched in this session) is the obvious tool for the "within 1 px of the base" drift check; a bounding-box comparison after `trim` is cheaper.

### Gaps
- No published Node/TypeScript port of K-Centroid or of the PixelArt-Detector was found; existing implementations are Lua (Aseprite) and Python (ComfyUI, PixelOE).
- No source on generating normal maps for pixel sprites in Node (Relish only says "generate normal maps").
- `jimp` and `pixelmatch` were not evaluated.

## Key question 6: Hybrid with open assets (CC0/CC-BY packs plus AI extension; licensing of mixes; LPC generator programmatically)

### Takeaway
Kenney packs are CC0 and can be mixed freely; LPC art is per-file CC0/CC-BY/CC-BY-SA/OGA-BY/GPL with a CREDITS.csv and a required credits screen, and CC-BY-SA or GPL items pull derivatives under the same licence. Using an open pack as a style reference for AI generation (PixelLab `style_image`, Retro Diffusion `reference_images`/`input_image`) is technically supported but no source addresses the licensing of such derivatives.

### Cited Findings
- Kenney Pixel Shmup: CC0 1.0, "use these game assets in any project including commercial ones", attribution not required; listing states "No generative AI was used". — [Kenney Pixel Shmup on itch](https://kenney-assets.itch.io/pixel-shmup)
- Universal LPC generator: code GPL-3.0; each art piece under one or more of CC0, CC-BY-SA, CC-BY, OGA-BY, GPL; CC-BY-SA requires derivatives under CC-BY-SA 4.0+, GPL requires GPL 3.0+; "credit all authors of any art used, except CC0"; ship the full `CREDITS.csv` or a list for the assets used, discoverable in-game (credits screen or visible link); the generator can download a licence sheet as CSV or text for the selected assets. — [LPC generator README](https://github.com/LiberatedPixelCup/Universal-LPC-Spritesheet-Character-Generator)
- Older LPC mirror and `lpcg` state the spritesheet art as GPL 3.0 and/or CC-BY-SA 3.0. — [lpcg crate](https://docs.rs/crate/lpcg/0.3.0)
- PixelLab BitForge uses `style_image` to "match an art style"; Retro Diffusion `input_image`/`strength` and RD Pro `reference_images` (up to 9). — [pixellab-python](https://github.com/pixellab-code/pixellab-python); [api-examples](https://github.com/Retro-Diffusion/api-examples)
- itch.io requires tagging "assets comprised of generative AI (even if modified afterward)"; untagged assets lose browse indexing. — [80.lv on itch policy](https://80.lv/articles/asset-creators-on-itch-io-now-have-to-disclose-the-use-of-generative-ai/)

### Inferences
- A CC0-only base (Kenney, CC0 subsets of LPC filtered via CREDITS.csv) keeps the mixed set free of share-alike obligations; AI extensions then carry only the generator's terms plus the US copyrightability issue (Q8). Using CC-BY-SA LPC items as `style_image` input arguably creates derivatives under CC-BY-SA; no authority found either way, so treat it as share-alike to be safe.
- Programmatic LPC use: the generator's `sheet_definitions/` JSON plus layered PNGs can be composited in Node (`sharp.composite`) without the browser; the `lpcg` Rust CLI already does this. The credits export must be reproduced from CREDITS.csv.

### Gaps
- Tuxemon, Pixel Crawler, Sprout Lands, Cup Nooble and LimeZu Modern Interiors licences were not fetched in this session (LimeZu packs are known to be paid, non-CC licences; verify on itch before mixing).
- No legal source on the licence status of AI output conditioned on a CC-BY-SA reference image.

## Key question 7: Quality evidence and failure modes (2025-2026)

### Takeaway
There is no independent side-by-side benchmark of the pixel tools; the honest signal comes from devlogs and forums, which converge on the same failure list: pixel-level drift between regenerations, style drift without constant prompt anchoring, residue after background removal, outfits and props changing between frames, and perspective inconsistency across a set. Developers who ship AI sprites do so by over-generating and filtering with deterministic checks, not by hand-fixing.

### Cited Findings
- Drift and residue: "each regeneration shifts by a few pixels"; 200,000+ black residue pixels in an accepted image; style drift to glossy anime without injected pixel-art terms; hand-fixing had "zero percent success rate". — [dev.to sprite-forge write-up, July 2026](https://dev.to/quolu/how-i-made-an-ai-that-cant-draw-the-same-character-create-anime-model-sheets-19cn)
- Identity drift between frames in older single-frame workflows: changed clothing, moved weapon. — [IndieHackers](https://www.indiehackers.com/post/gpt-image-2-5-a-full-sprite-sheet-from-one-reference-110562d19f) (snippet)
- Consistency cost: "several hours of Photoshop cleanup to match outfits"; AI sprites removed because editing for consistency took too long. — [itch devlog](https://itch.io/devlog/507457/a-productive-week-another-ending-complete-and-some-sprite-work.amp); [itch devlog](https://rizvn.itch.io/deliidol/devlog/635116/removed-ai-cgs-and-sprites-images-that-were-removed-from-game)
- RPG Maker users: could not reach the consistency needed; AI "like hitting a random button"; one scripted a pipeline around the output instead. — [RPG Maker guild](https://guild.rpgmakerofficial.com/t/topic/1898)
- Vendor claims to test rather than trust: Retro Diffusion output "grid-aligned, palette-limited, and usable in a game engine without post-processing cleanup"; PixelLab "10x faster with AI". — [Replicate blog](https://replicate.com/blog/retro-diffusions-pixel-art-models-are-now-on-replicate); [pixellab.ai](https://pixellab.ai/)
- Cinevva (Sept 2026): most generators "produce none of that [grid, palette, outlines] until you downscale, quantise and clean up by hand"; Leonardo-type output needs "downscale, palette reduction, and outline cleanup"; the comparison does not publish hands-on sample images for PixelLab/Retro Diffusion walk cycles. — [Cinevva](https://app.cinevva.com/guides/ai-pixel-art-generators)
- Makko blog (AI game-art vendor) titles its own post "why consistency is the hard part". — [Makko](https://blog.makko.ai/ai-game-art-generator/)
- General pixel-art quality checklist usable as acceptance tests: too many colours, mixed pixel densities, over-detailing, origin mismatch, timing wrong at play speed. — [Relish Games](https://relishgames.com/journal/pixel-art-pipelines-best-tools-for-2026/)

### Inferences
- What AI still cannot do well for sprites in 2026, from the evidence: hold one character's identity across a full directional sheet without a skeleton or master-sheet constraint; keep perspective and pixel density uniform across dozens of independently generated tiles and props; produce clean alpha edges without a thresholding pass; produce a labelled autotile set. Short loops (4-8 frames, 32-48 px) and single props/portraits are where the tools are credible.
- The PerfectPixel Studio project (AI generation plus deterministic post-processing) appeared in search, but its page returned 404, so its approach could not be verified.

### Gaps
- No 2025-2026 article with before/after images of PixelLab or Retro Diffusion sprites after cleanup; no numeric acceptance rates from any pipeline.

## Key question 8: Licensing and policy (copyrightability, Steam, itch.io, which tools claim licensed data)

### Takeaway
The US Copyright Office's Part 2 report (Jan 29, 2025) holds that prompts alone do not confer authorship, that human expressive inputs, creative selection/arrangement and creative modifications are protectable, and that no new legislation is needed; no 2026 update was listed on the Office's page as of this search. Steam rewrote but kept its AI disclosure (Jan 16, 2026), exempting development tools and covering shipped content; itch.io requires an AI Disclosure tag, strictly enforced for asset pages. Only Retro Diffusion among the pixel tools claims consent-licensed training data.

### Cited Findings
- Copyright Office AI reports: Part 1 Digital Replicas (July 31, 2024); Part 2 Copyrightability (Jan 29, 2025); Part 3 Generative AI Training pre-publication (May 9, 2025), final version pending; no 2026 updates listed. — [copyright.gov/ai](https://www.copyright.gov/ai/)
- Part 2 conclusions, quoted: "prompts do not alone provide sufficient control"; "Human authors are entitled to copyright in their works of authorship that are perceptible in AI-generated outputs, as well as the creative selection, coordination, or arrangement of material in the outputs, or creative modifications of the outputs"; "The case has not been made for additional copyright or sui generis protection"; "Neither the use of AI as an assistive tool nor the incorporation of AI-generated content into a larger copyrightable work affects the availability of copyright protection for the work as a whole"; selection and arrangement of "only two or three elements is not generally sufficient"; tools that let the user "control the selection and placement of individual creative elements" may yield copyrightable output case by case. — [Part 2 report PDF](https://www.copyright.gov/ai/Copyright-and-Artificial-Intelligence-Part-2-Copyrightability-Report.pdf) (text extracted locally)
- Case law summary (law-firm post, 2026-07-22): D.C. Circuit in Thaler v. Perlmutter held human authorship is required; Zarya of the Dawn kept text and arrangement, revoked individual Midjourney images; Théâtre D'opéra Spatial denied despite 600+ prompts and Photoshop edits; the post reports no 2026 court or Office updates. — [Promise Legal](https://blog.promise.legal/ai-game-assets-copyright-steam-disclosure-2026/)
- Steam: disclosure requirement dates from 2024; revised Jan 16, 2026; development tools (e.g. coding assistants) exempt; two categories remain, pre-generated content shipped with the game and live-generated content (with guardrails); covers marketing assets per some summaries; voluntary, not enforced by moderation; players can report via overlay; already-released games may be asked to complete the survey on next update; nearly 8,000 games disclosed in H1 2025; a July 2026 estimate says roughly one in five surveyed games carries the label. — [Gigazine, 2026-01-20](https://gigazine.net/gsc_news/en/20260120-steam-updates-ai-disclosure-guidelines); [Promise Legal](https://blog.promise.legal/ai-game-assets-copyright-steam-disclosure-2026/); [Legal Moves](https://legalmoveslawfirm.com/steam-ai-policy/); [GosuGamers](https://www.gosugamers.net/entertainment/news/77861-steam-revises-ai-policy-while-keeping-generative-content-disclosure-intact)
- itch.io: "accurately tag your project if it contains materials produced by generative AI" via the AI Disclosure section of the project edit page; "strictly enforcing disclosure for all game asset pages"; "Failure to tag your asset page may result in delisting"; tagged projects appear on the AI Assisted browse page; procedural/algorithmic systems without external datasets (pathfinding, procedural levels) do not count. — [itch.io quality guidelines](https://itch.io/docs/creators/quality-guidelines). Launch coverage (Nov 2024): sub-tags for graphics, sound, text/dialogue, code; "No AI" tag for a no answer; "assets comprised of generative AI (even if modified afterward) that are not tagged will no longer be eligible for indexing". — [80.lv](https://80.lv/articles/asset-creators-on-itch-io-now-have-to-disclose-the-use-of-generative-ai/); [Mobile Marketing Magazine](https://mobilemarketingmagazine.com/itch-io-mandates-genai-disclosure-for-creators/)
- Other platforms: Google Play AI labelling enforceable April 15, 2026, extended July 15, 2026 to third-party AI integrations; Apple 5.1.2(i) consent before sending personal data to a third-party AI service. — [Promise Legal](https://blog.promise.legal/ai-game-assets-copyright-steam-disclosure-2026/)
- Indie practice recommendations: audit each asset as AI-generated / AI-assisted / human; complete Steam's survey; document human modifications; disclose on store page or credits; review each tool's terms for commercial rights. — [Promise Legal](https://blog.promise.legal/ai-game-assets-copyright-steam-disclosure-2026/)
- Licensed-data claims: Retro Diffusion "trained on licensed assets from Astropulse and other pixel artists with their consent". — [astropulse.itch.io](https://astropulse.itch.io/retrodiffusionai). PixelLab's site makes no training-data statement. — [pixellab.ai](https://pixellab.ai/). Layer offers a commercial licence on every plan; Scenario and Leonardo free tiers cannot ship in released games. — [Cinevva](https://app.cinevva.com/guides/ai-pixel-art-generators)

### Inferences
- A practical consequence of Part 2 for an asset pipeline: raw single generations are likely unprotectable in the US; a curated set with a human-designed palette, deliberate selection from many candidates, tile composition and hand-authored arrangement has a plausible claim to the compilation and modifications, not the individual images. Keeping a log of prompts, selections and edits per asset (as the sprite-forge checkpoint approach does by construction) supports both the Steam survey and any registration.
- Retro Diffusion's provenance claim is the only one among pixel tools and is unverified; it does not change the US copyrightability of outputs.

### Gaps
- Steam's own Steamworks page with the current disclosure text was not reachable (the onboarding doc fetched did not contain the section); wording is from press coverage.
- No source on how specific indie studios label AI-assisted pixel art on Steam beyond aggregate counts.
